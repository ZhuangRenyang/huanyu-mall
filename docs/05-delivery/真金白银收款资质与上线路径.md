# 真金白银收款：资质门槛与生产切换手册

> 这份文档回答两个问题：
> 1. **要收到真金白银，需要什么资质、办多久、花多少钱？**
> 2. **资质到手后，怎么在本系统把它切成生产模式？**
>
> 写给：项目负责人（决定要不要办资质）+ 运维（拿到资质后执行切换）。
>
> 政策依据：各平台官方文档，核对于 2026-11。**沙箱环境不产生任何真实资金流动**——这是平台设计，不是本项目的缺陷。

---

## 一、先说结论：四条通道的真实门槛

| 通道 | 主体要求 | 能不能收真钱 | 周期 | 成本 |
|---|---|---|---|---|
| **支付宝**（推荐首选） | 个人账号 / 个体工商户 / 企业 | ✅ 能 | 线上产品当天可开 | 0 元起 |
| **PayPal** | **企业账号**（个人卖家账号**不能**跑 API） | ✅ 能 | 3–10 个工作日 | 0 元起（费率另计） |
| **微信支付** | 个体工商户及以上（**不支持纯个人**） | ✅ 能 | 1–3 个工作日 | 0 元起 |
| **Stripe** | 境外主体 / 跨境资质 | ✅ 能（门槛最高） | 1–4 周 | 视主体而定 |

**最低成本路径：办一张个体工商户营业执照。** 它一次性解锁支付宝、微信支付、PayPal 三条通道：

- 支付宝：**不限额度**（个人账号无照是单笔 ≤2000 元、单日 ≤20000 元）
- 微信支付：**满足最低准入门槛**（纯个人申请会被拒）
- PayPal：凭营业执照注册**企业卖家账号**，这是 Orders API 上线的硬性要求

个体工商户执照可线上办理，通常 1–5 个工作日出照，登记本身免费（刻章另计）。

## 二、支付宝：门槛最低，但**必须分清两个产品**

这是最容易踩的坑：支付宝「当面付」和「电脑网站支付」是**两个独立产品，准入材料完全不同**。

### 2.1 电脑网站支付 / 手机网站支付（线上产品）——本项目该用这个

本项目是线上商城，顾客在浏览器里下单付款，对应的正是「电脑网站支付」。

**准入材料**：

| 情况 | 材料 | 额度 | 有效期 |
|---|---|---|---|
| 网站已上线 | 网站链接（**需完成 ICP 备案**）+ 授权函 | 视营业执照情况 | 长期 |
| **网站未上线（开发中）** | **demo 截图**（首页、商品/服务页、支付页） | 同上 | **30 天试用期** |
| 营业执照 | **选填**：个人账号建议补充（提升额度），企业账号无需再提供 | 补充后不限额 | — |

关键结论：

- **个人支付宝账号（身份证实名）就能签约**，营业执照是选填项，不是门槛。
- 网站没上线也能先接入：提交 3 张 demo 截图即可获得 **30 天开发试用期**。这对「先跑通真实收款、后补备案」的场景非常关键。
- 没有营业执照时：**单笔 ≤2000 元、单日 ≤20000 元**；补上营业执照后**不限额度**。
- 费率：**单笔 0.6%**（按订单金额收取，四舍五入保留 2 位小数）。
- 结算：默认进商家支付宝余额，实时到账；**新签约未满 90 日或连续交易未满 30 日的商家，资金次日结算**。
- 退款：交易后 12 个月内可退，原路退回，**服务费一并退回**。

### 2.2 当面付（线下产品）——本项目不需要，别选错

当面付是给**线下门店收银**用的，准入要**经营场所照片（门头照 + 内景照）、店铺名称、实际经营地址**。个人账号还需提供营业执照。

本项目做的是线上商城，选当面付会平白多出「拍门店照片」这类无法满足的材料要求。

### 2.3 本项目当前状态与生产切换

**沙箱已验证**：当面付（precreate）能生成真实可扫的二维码，沙箱网关返回 `code=10000`。

**生产切换步骤**（三步，全部通过后台 API 完成，无需改代码、无需重新部署）：

```bash
# 1) 取正式环境的 APPID 与密钥（沙箱的不能用）
#    开放平台 → 控制台 → 我的应用 → 网页应用 → 应用信息
#    APPID（正式）：2 开头的 16 位数字（沙箱是 9 开头，两者不通用）
#    应用公钥：本地生成一对 RSA2 密钥对，把公钥填到开放平台，下载「支付宝公钥」
# 2) 后台改配置（mode: live 会切到 https://openapi.alipay.com/gateway.do）
curl -X PUT "$API/api/v1/admin/settings/payment-providers/pp_alipay" \
  -H "authorization: Bearer $ADMIN_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "options": {
      "appId": "<正式APPID>",
      "privateKey": "<正式应用私钥 PEM>",
      "alipayPublicKey": "<正式支付宝公钥 PEM>",
      "mode": "live",
      "flow": "redirect",
      "notifyUrl": "https://<你的域名>/api/v1/store/webhooks/payment/pp_alipay",
      "returnUrl": "https://<你的域名>/<locale>/<channel>/checkout/result"
    },
    "enabled_channels": ["<channel_id>"]
  }'

# 3) 验证：后台「支付方式」页面回显应为掩码，且 GET 返回 options_masked
curl "$API/api/v1/admin/settings/payment-providers/pp_alipay" \
  -H "authorization: Bearer $ADMIN_TOKEN"
```

**`flow` 字段怎么选**：

| flow | 走的接口 | 适用 |
|---|---|---|
| `redirect` | `alipay.trade.page.pay` | **生产用这个**（电脑网站支付，跳收银台） |
| `qr` | `alipay.trade.precreate` | 当面付，扫码支付；**沙箱只支持这一条** |

沙箱不支持 `page.pay`（网关直接返回 404），所以沙箱联调用 `qr`，生产切 `redirect`。

> ⚠️ **`notifyUrl` 必须是公网可达的稳定地址**。之前联调用的是 cloudflared 临时隧道（`*.trycloudflare.com`），隧道一挂回调就断——生产环境必须换成固定域名 + HTTPS。

## 三、PayPal：个人账号收不了 API 的钱

### 3.1 硬门槛

PayPal 官方 REST API 文档明确写着：

> You need a PayPal Business account to do the following:
> - Go live with integrations.
> - Test integrations outside the US.

也就是说，**Orders API 上线必须是 Business account**。

### 3.2 关于「PayPal 个人卖家账户」的澄清（2026 新政策，容易误解）

2026 年 PayPal 中国向大陆个人开放了「个人卖家账户」：

- 只需身份证实名认证，无需营业执照
- 提供**快闪收单**（付款链接 / 二维码）和**全球账单**（B2B 账单）工具
- **但**：这些是 PayPal 托管的工具，**不是 REST API 集成**

所以：

| 用途 | 个人卖家账户能否用 |
|---|---|
| 发付款链接收款 | ✅ 能 |
| 开账单收款 | ✅ 能 |
| **本项目的 API 集成（Orders v2）** | ❌ **不能**，必须 Business account |

而且 PayPal 中国官方帮助页明确：**个人卖家账户暂不支持升级为企业卖家账户**。如果以后想用 API，得重新注册企业账号。

### 3.3 路径

1. 准备营业执照（个体工商户即可）→ 注册 **PayPal 企业卖家账户**
2. 绑定对公账户或经营者个人银行账户
3. 在 [developer.paypal.com](https://developer.paypal.com) 的 Apps & Credentials 取 **Live** 模式的 Client ID / Secret
4. 绑 webhook（`verify-webhook-signature` 是官方验签入口，证书会轮换，不要本地验签）

**生产切换**：

```bash
curl -X PUT "$API/api/v1/admin/settings/payment-providers/pp_paypal" \
  -H "authorization: Bearer $ADMIN_TOKEN" \
  -H "content-type: application/json" \
  -d '{
    "options": {
      "clientId": "<Live Client ID>",
      "clientSecret": "<Live Secret>",
      "webhookId": "<Live Webhook ID>",
      "mode": "live",
      "captureMethod": "automatic"
    },
    "enabled_channels": ["<channel_id>"]
  }'
```

⚠️ **币种限制**：PayPal 在多数地区**不把 CNY 作为交易币种**。人民币收款必须走支付宝或微信。PayPal 用于 USD/EUR/GBP 等外币渠道。

## 四、微信支付：必须有个体工商户

微信支付 V3 沙箱已停止服务，联调即真实商户号。

**申请条件**：微信支付**不支持纯个人主体申请**，最低门槛是：

- 个体工商户（或企业）营业执照
- 已备案的网站（PC 支付）或小程序/公众号
- 结算账户：经营者个人银行卡（个体户可绑）或对公账户

**本项目当前状态**：`pp_wechat` 仍是沙箱桩（继承 `SandboxPaymentProvider`），只实现了回调验签（SHA256-RSA2048 + resource AES-256-GCM 解密）。**下单接口尚未真实对接**，需要先申请到商户号再补实现。

按蓝图约定「无商户不阻塞上线」，该项可延后。

## 五、Stripe：门槛最高，放最后

Stripe 需要**境外主体**或跨境支付资质，大陆个人无法直接开通。适合项目后期面向海外市场时再做。

**当前状态**：`pp_stripe` 仍是沙箱桩。测试密钥在 [dashboard.stripe.com/test/apikeys](https://dashboard.stripe.com/test/apikeys) 自助获取，**不需要**任何资质即可先联调。

## 七、生产切换前的检查清单

- [ ] provider 配置 `mode` 已切 `live`，且 `GET` 回显的 `options_masked` 各项非空
- [ ] `notifyUrl` 用固定域名，**从外网实测 POST 能收到 200**（不是本机 curl）
- [ ] `returnUrl` 指向真实可访问的店面结果页
- [ ] 金额单位正确：**Stripe 传整数分，PayPal/支付宝传主单位字符串**（本项目已由 `@mall/core/money` 统一处理，provider 边界转换）
- [ ] 微信支付渠道在**外币**下已停用（PayPal 不支持 CNY）
- [ ] 用**小额真单**跑通完整链路：下单 → 支付 → webhook → 订单转 `paid` → `payment_status=captured`
- [ ] 回调幂等验证：重复投递同一 webhook 不产生重复扣款/重复转单
- [ ] 退款验证：能原路退回，服务费一并退回

## 八、常见问题

**Q：沙箱能收真钱吗？**
不能。所有平台的沙箱环境都不产生真实资金流动。沙箱的作用是验证代码链路（签名、验签、金额换算、状态机、幂等），验证通过后换生产凭据即可。

**Q：切了 `mode=live` 就不用改代码了？**
是的。`mode` / `flow` 是后台 provider 配置项，密钥 AES-256-GCM 加密落库，通过 `PUT /api/v1/admin/settings/payment-providers/:id` 即可更新，**不需要重新部署、不需要改代码**。

**Q：为什么支付宝沙箱的 `page.pay` 报 404？**
沙箱环境没有开通「电脑网站支付」接口。沙箱联调请用 `flow=qr`（当面付 precreate）；生产用 `flow=redirect`（page.pay）。

**Q：顾客付了钱但订单还是 unpaid？**
99% 是 webhook 没到。检查：`notifyUrl` 公网可达性、provider 标识是否写对（必须是 `pp_alipay`/`pp_paypal` 这类 identifier，不是 `alipay`）、签名验签是否通过。API 日志搜 `webhook 处理失败`。

**Q：为什么用支付商交易号找不到订单？**
支付商的交易号（支付宝 trade_no / PayPal capture id）与我们内部的 `payment.id`（`pay_xxx`）**不在同一 ID 空间**。唯一可靠的锚点是**商户单号**（`out_trade_no` / `custom_id` = `payment_collection.id`），支付商会原样回传。本项目已按此实现。
