# 支付联调手册

> 本文档给出各支付渠道**从拿沙箱凭据到端到端跑通**的完整步骤。
> 一期要求：四家 Provider 全部「沙箱/测试模式联调通过」，部署方有商户号后在后台填密钥即可切生产。
>
> **凭据不要提交进仓库**。本文件只写占位符；真实值填在部署机的 `${MALL_DIR}/config/.env` 或管理后台「支付方式」里（后台存加密后的密文）。

## 一、PayPal（已实现真实对接）

### 1. 拿沙箱凭据

| 用途 | 地址 |
|---|---|
| 开发者后台 | https://developer.paypal.com/dashboard/ |
| 沙箱 App（Client ID / Secret） | https://developer.paypal.com/dashboard/applications/sandbox |
| 沙箱买家账号（模拟付款） | https://developer.paypal.com/dashboard/accounts |
| API 状态 | https://api-m.sandbox.paypal.com（沙箱）/ https://api-m.paypal.com（生产） |

步骤：登录 → **Apps & Credentials** → 切到 **Sandbox** → **Create App** → 复制 `Client ID` 与 `Secret`（Secret 需点 Show）。

### 2. 配置 Webhook（验签必需）

在同一个 App 页面 → **Webhooks** → **Add Webhook**：

- **Webhook URL**：`https://你的域名/api/v1/store/webhooks/payment/pp_paypal`
  - ⚠️ **路径里两段都不能省也不能改**：
    - `payment/` 是路由的一部分（`/api/v1/store/webhooks/payment/:provider`）
    - `pp_paypal` 必须是 `ProviderRegistry` 的 **identifier**（`pp_paypal`），**不是** `paypal`
    - 写成 `.../webhooks/paypal` 或 `.../payment/paypal` 都会失败，且返回的是 **402**（与"验签失败"同一个状态码，因为错误码首位 4 统一映射到 402），看不出真正原因
  - PayPal **强制要求 HTTPS**（填 `http://` 会报 `Not a valid webhook URL`）
  - 没有公网入口时可用 cloudflared 隧道：`docker run -d --name pp-tunnel --network host cloudflare/cloudflared:latest tunnel --url http://localhost:80 --no-autoupdate`，然后从 `docker logs pp-tunnel` 里取 `https://xxx.trycloudflare.com`
  - 保存后可用 `POST /v1/notifications/simulate-event`（传 `webhook_id` + `event_type`）**不发真实订单**直接验证回调链路是否打通
- **Event types**（勾这四个即可）：
  - `PAYMENT.CAPTURE.COMPLETED` → 支付成功（`captured`）
  - `PAYMENT.CAPTURE.DENIED` → 支付被拒（`failed`）
  - `PAYMENT.CAPTURE.REFUNDED` → 退款（当前映射为 `not_supported`，退款状态由我们主动发起时同步更新）
  - `CHECKOUT.ORDER.APPROVED` → 用户已批准，等待捕获

保存后列表里显示 **Webhook ID，以 `WH-` 开头**，填进 `PAYPAL_WEBHOOK_ID`。

### 3. 配置项

```
PAYPAL_CLIENT_ID       = 沙箱 App 的 Client ID
PAYPAL_CLIENT_SECRET   = 沙箱 App 的 Secret
PAYPAL_WEBHOOK_ID      = WH-xxxxxxxx（验签必需，缺了会拒绝所有回调）
PAYPAL_MODE            = sandbox | live
PAYPAL_CAPTURE_METHOD  = automatic | manual   （manual 走 AUTHORIZE→CAPTURE，默认 automatic）
```

### 4. 端到端验证

```bash
BASE=http://localhost/api/v1

# 1) 下单（沿用 e2e-regression.sh 的前 6 步，或直接建车→加购→结账）
# 2) 建支付会话（provider 选 pp_paypal）
curl -s -X POST "$BASE/store/payment-sessions" -H 'Content-Type: application/json' \
  -d '{"payment_collection_id":"<paycol_id>","provider_id":"pp_paypal"}'
#    → data.context 里应有 redirectUrl（PayPal 结账页）
#    → 用沙箱买家账号登录该 URL 完成付款
# 3) 授权/捕获
curl -s -X POST "$BASE/store/payment-sessions/<id>/authorize"
curl -s -X POST "$BASE/store/payment-sessions/<id>/capture"
# 4) 确认订单状态
curl -s "$BASE/store/orders/<order_id>" | jq '.data.status, .data.payment_status'
#    期望：paid / captured
# 5) 确认 webhook 到达（看 api 日志 + audit_log）
docker compose logs --tail=50 api | grep -i paypal
```

### 5. 已知限制（实现层面的真实约束）

| 项 | 说明 |
|---|---|
| **取消订单** | PayPal Orders v2 **没有**"取消订单"端点。实现策略：已授权未捕获 → `void authorization` 释放额度；未授权 → 本地标记 `canceled`（PayPal 侧订单约 3 小时后自然过期）；**已捕获不能取消，必须退款**（此时返回 `failed`，由上层引导退款） |
| **退款对象是 capture 不是 order** | `refundPayment` 的 `providerReference` 必须是 captureId（捕获后我们存的就是它） |
| **金额是主单位字符串** | 见下节，这是最容易出错的地方 |

## 二、⚠️ 金额单位：PayPal 与 Stripe 相反

| | 金额格式 | 内部 `amountMinor = 20600`（¥206.00）应传 |
|---|---|---|
| **Stripe** | 整数，**币种最小单位** | `20600`（原样，**绝不 /100**） |
| **PayPal** | **字符串，主单位** | `"206.00"`（必须 `fromMinor()` 换算） |
| **支付宝** | 字符串，主单位（元） | `"206.00"` |
| **微信** | 整数，**分** | `20600` |

统一口径：**一律走 `@mall/core/money` 的 `fromMinor()` / `toMinor()`**，不要在任何 Provider 里手写 `* 100` 或 `/ 100`。原因：`JPY` / `KRW` 是 zero-decimal 币种（小数位 0），硬除 100 会让 ¥20600 变成 ¥206.00 —— 100 倍差错。

已在 `paypal.provider.spec.ts` 用两条单测锁死（CNY → `"206.00"`、JPY → `"20600"`），改动这段逻辑时那两条必须先过。

## 三、Stripe（待接入）

### 拿测试密钥

| 用途 | 地址 |
|---|---|
| 注册 | https://dashboard.stripe.com/register |
| **测试 API 密钥** | https://dashboard.stripe.com/test/apikeys |
| **测试 Webhook** | https://dashboard.stripe.com/test/webhooks |
| 测试卡号 | https://docs.stripe.com/testing |

**中国大陆主体不能直接开 Stripe 商户**（官方明确「not available in mainland China」）。但**测试模式不需要企业资料与 KYC**：注册时地区选「中国香港」或「新加坡」，停留在 **test mode**、不激活收款，即可拿到 `sk_test_`。

```bash
STRIPE_SECRET_KEY       = sk_test_...
STRIPE_PUBLISHABLE_KEY  = pk_test_...
STRIPE_WEBHOOK_SECRET   = whsec_...     # 见下
STRIPE_MODE             = test | live
STRIPE_CAPTURE_METHOD   = automatic | manual
STRIPE_PAYMENT_METHOD_TYPES = card,apple_pay,google_pay,klarna
```

`whsec_` 两种拿法：
1. **本地联调**：装 Stripe CLI，`stripe listen --forward-to localhost/api/v1/store/webhooks/stripe`，它会打印一个专供转发的 `whsec_`，不用公网域名。
2. **Dashboard**：在 `/test/webhooks` 添加端点，事件勾 `payment_intent.succeeded`、`payment_intent.payment_failed`、`payment_intent.amount_capturable_updated`、`charge.refunded`。

测试卡：`4242 4242 4242 4242`（成功）、`4000 0025 0000 3155`（触发 3DS）、`4000 0000 0000 0002`（拒付）。

## 四、支付宝（待接入）

沙箱可自助开通（无需真实商户号）：https://open.alipay.com/develop/sandbox/app

```
ALIPAY_APP_ID          = 沙箱应用 APPID
ALIPAY_PRIVATE_KEY     = 应用私钥（RSA2）
ALIPAY_PUBLIC_KEY      = 支付宝公钥
ALIPAY_GATEWAY         = https://openapi-sandbox.dl.alipaydev.com/gateway.do
ALIPAY_NOTIFY_URL      = https://你的域名/api/v1/store/webhooks/alipay
```

沙箱有自带的买家账号（在沙箱应用页面可查）。验签用 RSA2（`signature.ts` 的 `rsaSha256Verify` 已具备）。
