## 二、用户点名的四块，拆开是什么

**装修**（散在「设置」里，共 14 项）
主题风格、微页面、店铺装修、页面设计、首页设计、页面链接、我的主题、商城主题、链接管理、
首页导航按钮、首页幻灯片、首页活动区域图片、首页滚动新闻、热门搜索、首页配置、首页超值爆款。
本质是**页面 DIY + 首页模块配置**，不是「换个颜色」。

**应用**（3 项 + 散落的接入配置）
APP 版本管理、隐私协议、插件管理；支付/短信/存储等接入散在「设置」。
本质是**外部能力的接入清单**。

**设置**（52 项）
身份与权限、系统设置、电子发票、打印机、电子面单、通知四件套、物流三件套、门店、核销员、
协议、多语言、AI 模型、一号通。

**维护**（20 项）
刷新缓存、系统日志、清除数据、数据备份、系统信息、在线升级/跨版本升级、定时任务、系统事件、
附件管理、代码生成、数据字典、接口管理。

## 四、重建顺序（原地替换，不删仓库）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **A 后台 IA**（本轮之后第一件） | 导航重排为：首页 / 商品 / 订单 / 客户 / 营销 / 装修 / 应用 / 设置 / 维护；设置页支持 `?tab=` 深链并被拆到三组 | 八个入口都能进，无 404，`typecheck` 过 |
| **B 装修 v1** | 主题（已有）+ 首页模块编排：公告、轮播、分类、商品列表、券条的**开关与顺序**，店面按配置渲染 | 后台改顺序，店面刷新即变；非法配置有兜底 |
| **C 应用** | 接入清单：支付通道、SMTP、文件存储、渠道/市场，显示「已配置/未配置」并可跳转 | 四项状态与真实配置一致 |
| **D AI（LangChain.js）** | `packages/ai`：商品文案生成、客服问答；不接入交易与金额链路 | 有开关、有超时、失败不影响下单 |
| **E 店面** | 移动端优先重排（顾客在微信里） | 手机下单/退货全流程 |

## 五、明确不抄

分销、拼团、砍价、秒杀、积分、直播、多商户、线下收银、电子发票、余额充值、
代码生成、插件市场、在线升级。

理由：ADR-014（简单优先）、无商户资质、以及这些功能的资损与运营复杂度
（分销佣金、拼团库存、秒杀超卖）远超当前团队的维护能力。

## 六、技术栈结论（LangChain）

现状（`package.json` 实测）：TypeScript 5.9、Node ≥26、Fastify 5.12.8、
Next.js 16.4.5、React 19.3.1、Drizzle、PostgreSQL、Redis；180 个路由、315 个接口测试。

LangChain.js 是**库**不是 web 框架，与 Fastify/Next 无冲突：
接入方式是新增 `packages/ai`（`@langchain/core` + provider 适配），由 API 注入，
交易链路不依赖它。

**不换框架**：换等于重写 180 个路由与 315 个测试，收益为零；
「TS 最新版」我们已经在新版本上（TS 5.9 / Node 26）。
