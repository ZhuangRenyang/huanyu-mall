# ADR-046：店铺 Logo 与外观设置的读回

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-045（店铺资料）、ADR-010（换肤）

## 背景

`theme_settings.logo_file_id` 这个字段从一期就存在，后台 `PATCH /admin/settings` 也接受它。但实际上：

1. **店面从不渲染 logo**：店头永远是一行店名文字
2. **后台没有上传入口**：外观设置页只有配色、字体、圆角、商品图比例、公告
3. **没有任何接口能读回外观设置**：只有 `PUT /admin/settings/theme`，没有 `GET`
4. 后端 SDK 里有 `getTheme()`，对应 `GET /api/v1/admin/settings/theme` —— 这个路由不存在

第 3、4 条合起来是一个**静默失效**：后台打开外观页 → 请求 404 → `getTheme()` 的 catch 返回 `DEFAULT_THEME` → 页面显示默认配色。商家改完点保存（PUT 成功），刷新后又看到默认值 —— 会以为保存坏了，或者以为系统在骗他。

## 决策

### 1. 补 `GET /admin/settings/theme`

返回完整设置 + 解析后的 `logo_url`（`file.getPublicUrls` 按存储 key 生成，直接拼 `file_id` 会 404，这是 ADR-033 时期踩过的坑）。

不做「读设置和读文件分两个请求」：外观页一进来就要显示 logo 预览，两次串行请求只多一个 RTT。

### 2. `bootstrap` 也带 `logo_url`

店头是首屏组件，`logo_url` 与 `theme` 平铺返回——前端不该知道「文件 id」和「URL」的区别，也避免了另一条 `/store/files/:id/url` 接口。

### 3. logo 上传复用商品图的上传通道

`uploadProductImage` 的主体抽成 `uploadImageAsset`，商品图与店铺 logo 共用（同样 20MB 上限、同样只收图片、同样 base64 通道）。不做第二套上传逻辑——第二套迟早会漏掉大小校验。

### 4. 保存外观时带上 `logo_file_id`

原本 `saveTheme()` 只发 4 个字段（配色/字体/圆角/比例）。加上 logo 之后如果仍只发这 4 个，商家上传 logo 再点保存，logo 不会落库；更糟的是后续任何一次保存都会把已存的 logo 覆盖成 null。合并语义下「不传 = 不动」，所以必须显式传。

### 5. 店头：有图用图，没图用文字

`<img>` 而不是 `next/image`：logo 是商家上传的任意宽高比，`next/image` 需要显式宽高，猜一个会把 logo 拉变形。用 `h-8 w-auto max-w-[140px] object-contain` 保比例。

`alt` 用店铺名称：读屏软件念出店名，而不是「logo」。

### 6. 恢复默认会清掉 logo

`恢复默认外观` 走的是同一个 `saveTheme(DEFAULT_THEME)`，`DEFAULT_THEME.logoFileId` 为 null → logo 一并清掉。这符合「恢复默认」的语义（外观设置整体回到出厂状态），页面上有 `window.confirm` 提示。

## 后果

- API：新增 `GET /admin/settings/theme`；`bootstrap.theme` 增加 `logo_url`
- 后台：外观设置加「店铺 Logo」上传/更换/移除与预览；`getTheme` 映射 logo；`saveTheme` 提交 `logo_file_id`
- 店面：`getStoreProfile()` 返回 `logoUrl`，页头有图显示图、无图显示店名
- SDK：`UpdateThemeRequest` 增加 `logo_file_id` 与 `announcement`
- 测试：`theme-settings.spec.ts` 5 条（读回已存配色、未登录 401、logo 两处生效、删除后回 null、只提交配色不抹 logo）

## 遗留

- 「首页通告条」输入框在页面上，但 `announcement` 既没有数据库列也没有店面渲染 —— 与 `site_name` 同一类幽灵字段。已在 `UpdateThemeRequest` 里补了类型，落库与展示另行处理
- logo 在页脚不显示：页脚目前用店名文字，尾部加图会让页脚第一列高度不稳定
