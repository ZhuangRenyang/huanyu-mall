# ADR-054：我的评价

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-042（商品评价）、ADR-048（收藏夹）

## 背景

ADR-042 让顾客能给已收货的订单评价，但**评价完就消失了**：

- 顾客想确认「我是不是评过这件商品」，只能逐个订单翻；
- 商家解释了评价、或者把评价隐藏了，顾客都不知道；
- 评价内容有没有写错、能不能补一句，没有任何入口。

淘宝把这块放在「我的淘宝 → 评价管理」：写过的评价、商家回复、当前状态一目了然。
账户页里已经有收藏、卡券、地址簿，唯独缺「我产生的内容」里最该有的一项。

## 决策

### 1. 按顾客收敛，`customerId` 只从 token 取

`GET /store/customer/reviews` 不接受 `customer_id` 查询参数。
评价里有顾客名（脱敏后）、买了什么、怎么评价的——传个参数就能翻别人的，是数据泄露。

### 2. 被隐藏的评价也要返回，并带 `is_visible`

`is_visible=false`（商家隐藏）时：

- **仍然返回给本人**，附 `is_visible`；
- 前端标「仅自己可见」。

理由：顾客写完发现商品页看不见，会以为自己的评价被吞了。告诉他「这条没展示」
比让他反复刷新诚实。商品页那条路径仍然只看 `is_visible=true` 的（不变）。

### 3. 商品名用快照，不回查商品

`product_review.product_title` 在评价时就冻结了（ADR-042）。
「我的评价」直接读快照，**不 join 商品模块**：跨模块查询会新增依赖边，
而商品改名/下架后评价仍应可读。

### 4. 一次取 50 条，不做无限滚动

顾客一辈子评价不了几百条；先给足 50 条，翻不到再加分页。
服务端本身支持 `limit/offset`（与商品评价同一套分页契约），前端只是先用大页。

### 5. 位置：账户页，紧跟「我的收藏」

淘宝放在「评价管理」独立入口；我们的账户页是纵向卡片流，
按「我产生的内容」聚类：收藏 → 评价 → 卡券 → 地址簿。
不放订单页：评价是跨订单的，挂在某一单下面找不到。

### 6. 索引

新增 `(customer_id, created_at DESC) WHERE deleted_at IS NULL`。
原有索引是 `(product_id, ...)` 与 `(created_at)`，按顾客查会全表扫。

## 后果

- review 模块：迁移 `0002_customer_index.sql`、`listByCustomer` / `listMyReviews`
- API：`GET /store/customer/reviews`（401 未登录；返回 items/count/hasMore，含 `is_visible`）
- SDK：`listMyReviews`
- 店面：`lib/reviews.ts` 的 `listMyReviews`（mock 摊平本地追加的那份）、
  `components/account/my-reviews.tsx`、账户页插入
- 测试：review 模块 +1（只按顾客收敛）、api +5（401、字段形状、query 覆盖无效、
  隐藏仍返回、空列表不是 404）

## 遗留

- **改评价 / 追评**：淘宝支持一次追评。需要新表或版本字段，且涉及「评价有效期」，另做
- **按商品/评分筛选我的评价**：条数少时意义不大，等真的多了再说
- **图片评价**：`product_review` 没有图片字段，需要 file 模块联动
