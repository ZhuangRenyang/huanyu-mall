# ADR-050：顾客订单留言（给卖家留言）

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-003（订单备注）、ADR-030（商家备注仅后台可见）

## 背景

订单上有 `merchant_note`（商家内部备注，**只在后台可见**），但没有**顾客写的那一栏**。

淘宝的下单页在商品清单下方有一块「给卖家留言」，买家写「工作日白天送，别放快递柜」、
「麻烦用礼盒包装」，卖家在订单详情能直接看到，拣货打包的人也印在发货单上。

自建商城缺这一栏的直接后果：

- 顾客有特殊要求只能去问客服，客服再手动记到**商家备注**里 —— 但只要有一次写成顾客可见，
  内部备注（「这单利润薄，别送赠品」）就泄露了；
- 发货单上没有任何顾客要求，打包的人按默认流程装箱，拆包投诉后才发现有备注。

这一栏必须和商家备注**分开存、分开发**：

| 字段 | 谁写的 | 谁看得到 | 是否下发店面 |
|---|---|---|---|
| `customer_note` | 顾客 | 顾客 + 商家 | **是** |
| `merchant_note` | 商家 | 仅商家 | 否 |

## 决策

### 1. 独立字段 `order.customer_note`，不塞 metadata

要出现在三个地方（店面订单详情、后台订单详情、发货单），还可能被客服按内容检索；
`metadata` 是自由 JSON，取一次解析一次，还会被行快照覆盖逻辑牵连。一个短文本就该是列。

### 2. 宽进严存：路由收 1000 字，服务层截断到 200 字

淘宝的输入框限 200 字。服务端两条路各管一件事：

- **路由**：`z.string().max(1000)`，只防超大请求体，不做业务校验；
- **服务层**：`normalizeCustomerNote` 去首尾空白 → 空白转 `null` → 超长截断到 200。

为什么不直接 400：顾客已经点过一次「下单」（前面填了地址、选了券），为一个备注打回去，
他要重走一遍；截掉几行字的代价明显更小。前端 `maxLength=200` + 字数计数，
正常路径根本不会触发截断。

### 3. 空白存 null，不存空串

空串和 `null` 同时存在时，前端每处渲染都要判两种空，后台也说不清「有留言还是没留言」。

### 4. 落点照淘宝：三处，缺一不可

| 位置 | 为什么 |
|---|---|
| 结账页右侧栏「商品与优惠之后、金额合计之前」 | 顾客看完要买什么、多少钱才想起特殊要求；放第一步多数人跳过 |
| 店面订单详情「给卖家留言」卡片 | 顾客要能确认「我说的话商家看得到」，也是纠纷凭据 |
| 后台订单详情「顾客留言」彩色块（在商家备注之上） | 顾客提的要求漏看会直接做错货，必须比内部备注更显眼 |
| 发货单（打印） | 拣货打包的人看不到后台；发货单是他唯一的作业依据 |

### 5. 不做的事

- **不做留言编辑**：下单后顾客改备注，商家可能已经按旧要求打包了。真要改，走客服
- **不做留言通知**：新订单本身就该触发商家通知，留言是订单的一部分，不属于独立通知域
- **不做留言模板/常用语**：营销域功能，与「简单优先」冲突

## 后果

- order 模块：迁移 `0007_customer_note.sql`、`OrderDTO.customer_note`、
  `CreateOrderInput.customerNote`、`normalizeCustomerNote`（导出以便复用与单测）
- workflow：`CartCompleteInput.customerNote` 透传（归一化不放在 workflow：它是业务规则，不是编排）
- API：`POST /store/carts/:id/complete` 收 `customer_note`；`mapOrder` 带 `customer_note`（店面可见）
- SDK：`Order.customer_note`、`completeCart` body 增字段
- 店面：结账页 `CustomerNote` 区块、订单详情卡片、草稿自动带（草稿存整个 form）
- 后台：订单详情彩色块、发货单打印、mock 种子数据带一条示例
- 测试：order 模块 +4（空白转 null、超长截断、去空白、与商家备注互不覆盖）、
  api +5（传进 workflow、缺省为 null、超长不 400、店面可见、后台可见）

## 遗留

- 后台订单**列表**不显示留言摘要：列表已经挤，淘宝列表也不显示，属于详情页信息
- 客服按留言内容搜索：需要订单搜索支持全文，与「按订单号/邮箱搜」是两件事
