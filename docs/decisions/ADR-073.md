# ADR-073：订单列表挂售后进度角标，不是笼统的「退款中」

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-051（退货退款）、ADR-065（订单列表申请售后）

## 背景

订单列表对退款的表达只有一个词：订单状态是 `refund_pending` 就打一个「退款中」。

但退货退款是四步（ADR-051）：申请 → 商家同意（等买家寄回）→ 买家寄回 → 商家收货退款。
四步的订单状态**全是 `refund_pending`**，列表上看起来一模一样。

于是商家看到的「退款中」可能有三种完全不同的含义：

| 实际进度 | 商家该做什么 |
|---|---|
| 刚申请 | 去审核（同意/拒绝） |
| 已同意、等买家寄回 | 什么都不用做，等 |
| 买家已寄回 | 去确认收货并退款 |

分不清的代价是逐单点开看，或者该退的忘了退、不该催的催了。

## 决策

### 1. 一次批量查询，不是逐单查

`listActiveRefundsByOrderIds(orderIds)`：一条 `IN` 查询取这一页订单的**在途**售后单
（`pending` / `awaiting_return` / `returned`），按订单只留最新一张。

放在 order 模块，与单据同源；不在 API 层循环调 `findRefundRequest`（那就是 N+1）。

### 2. 接口在订单行上挂 `refund`，不改订单状态

`GET /admin/orders` 的每一项多一个 `refund: { id, status, resolution } | null`。

**没有为这个功能改订单状态机**。理由：
- 状态机是资金与发货的闸门（`refund_pending` 期间禁止发货），语义要稳定；
- 售后进度是**展示层事实**，用单据状态表达更准确，也不会让状态机多四个只用于显示的状态；
- 已处理完（approved / rejected / canceled）不挂角标 —— 列表只显示「还在走」的。

### 3. 三档文案与「退款管理」页签同名

| 单据状态 | 角标 |
|---|---|
| `pending` | 待审退款 |
| `awaiting_return` | 等买家寄回 |
| `returned` | 退货待收货 |

订单状态仍是 `refund_pending` 但没有在途单据时（历史数据 / 单据被撤销），
退回显示「退款中」，不留空。

## 后果

- order：`ActiveRefundDTO`、`listActiveRefundsByOrderIds`（仓储 + 服务 + 契约）
- API：`GET /admin/orders` 每行附 `refund`
- 后台：`AdminOrder.refundStage`（review / awaiting_return / returned），列表角标按档位显示
- 测试：api +4（无售后单、申请后待审、同意→寄回→待收货、拒绝后摘角标）

## 遗留

- **售后单详情入口**：角标目前只是提示，点不进具体单据（订单详情里有退款面板）。
  淘宝点角标直接开售后单，这里要等订单详情支持深链到某张单据
- **导出 CSV**：售后进度没有进导出列。要加的话应与角标同口径，避免「界面上有、表里没有」
- **已完成的售后**：列表完全看不到。要查历史得去「退款管理」页，这是有意为之（列表不堆历史）
