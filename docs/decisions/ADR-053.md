# ADR-053：店铺退货地址

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-051（退货退款）、ADR-045（店铺资料）

## 背景

ADR-051 把退货退款做通后留了一个断链：商家点了「同意退货」，顾客的订单页出现
「请把商品寄回并填写单号」——**但没有地址**。

顾客这时候只能去问客服，客服再手打一遍地址。三件事跟着出问题：

1. 顾客等客服回复，退货单压在「待买家寄回」，商家以为顾客不想退了；
2. 客服手打的地址可能和商家实际收货点不一致（写字楼 vs 仓库 vs 代收点）；
3. 同一句话每次手打，错一个字包裹就寄丢。

淘宝的做法是固定的：卖家在「物流工具 → 地址库」维护发货/退货地址，同意退货时自动带出。

## 决策

### 1. 存在店铺资料里，不新开表

`theme_settings` 已经是「店铺是谁」的单例配置行（店名、客服电话、公告）。
退货地址与它们同级：低频修改、全店唯一、一处改多处生效。再开一张单行表只会让店铺信息继续分散。

### 2. 一个多行文本框，不拆省/市/区/详细地址

国内退货地址经常带非标准信息：`转运仓编码`、`某某驿站代收`、`放前台`。
拆成结构化字段装不下这些，反而逼商家往「详细地址」里塞。一个文本框 + 换行，
顾客寄件时**照抄**即可，这也是淘宝地址簿里展示的形态。

### 3. 不复用仓库地址

`stock_location` 有仓库地址，但退货地址经常与发货仓不同（退到代收点/客服处）。
混用会出现「发货单印 A 地址、顾客退回 B 地址」，两边对不上。

### 4. 顾客端：有就显示，没有就明说

同意退货卡片里多一块「寄回地址」：

- 配了 → 原样多行显示（`whitespace-pre-wrap`，换行照原样）；
- 没配 → 「店铺尚未填写退货地址，请联系客服获取后再寄回」。

**不留空白**：一块空白的「寄回地址」比没有更糟，顾客会以为页面没加载出来。

### 5. 空串存 null，与其他设置字段同一口径

`return_address: "   "` → `null`。前端只判一种「没配」。

### 6. 公开性判断

这个字段随 `GET /store/bootstrap` 出去（与店名、客服电话同一份 theme 载荷）。
它本来就是给顾客看的，不属于内部信息 —— 与 `merchant_note`（永不下发店面）的边界不同。

## 后果

- theme 模块：迁移 `0003_return_address.sql`、`ThemeSettingsDTO.return_address`、模型与仓储映射
- API：`PATCH /admin/settings` 收 `return_address`（≤300 字，`.strict()` 不变）；
  `GET /store/bootstrap` 的 `theme` 自动带出
- SDK：`UpdateSettingsRequest.return_address`
- 后台：设置 → 店铺资料 新增「退货地址」多行输入（含说明文案）；
  顺带给 admin 的 `Field` 补上 `hint` 支持，与店面的 `form-field` 对齐
- 店面：服务端在订单页取一次店铺资料，透传到退款面板（不在明细组件里再打一次接口）
- 测试：api +2（能存能读、空串存 null；拼错的键仍 400，确认 strict 没有因新增字段放松）

## 遗留

- **多退货地址**（按仓/按商品指定）：淘宝支持多地址库。当前一个店铺一个退货地址，
  多仓商家需要时再扩展成地址表
- **退货地址快照**：现在显示的是「当前配置」。商家中途改地址，已同意退货的顾客会看到新地址。
  要严谨需在单据上冻结一份 `return_address_snapshot`，与订单行快照同一思路
- **发货地址**：发货单只印店名与客服电话，没有发件地址。与快递面单一起做更合适
