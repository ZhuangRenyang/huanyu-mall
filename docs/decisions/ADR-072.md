# ADR-072：退款审核结果要发邮件告诉顾客

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-016（邮件通知）、ADR-023（不做自动退款）、ADR-051（退货退款）、ADR-061（退货地址快照）

## 背景

邮件通知只覆盖三个节点：下单确认、发货、到货提醒。

退款是**唯一一个「顾客发起、商家处理、结果决定钱」**的流程，却没有任何回音：

- 商家同意退货，顾客不知道货该寄到哪 —— 退货地址只存在后台那张单里；
- 商家收到货并退款，顾客不知道钱已经退了，会以为商家拖着；
- 商家拒绝，顾客不知道原因，只能反复刷新「我的订单」。

淘宝的售后每走一步都有站内信/短信。自建商城没有站内信，邮件是唯一触达渠道。

## 决策

### 1. 三个节点各发一封，去重键带档位

| 触发点 | `status` | 主题 |
|---|---|---|
| `approve` + `resolution=return_refund` | `return_agreed` | 退货申请已同意：订单 X |
| `approve`（仅退款）/ `receive-return` | `refunded` | 退款已原路退回：订单 X |
| `reject` | `rejected` | 退款申请未通过：订单 X |

去重键 `refund:{refundRequestId}:{status}`。

**不带档位就错了**：同一张退货单先「同意退货」再「已退款」，是两封内容完全不同的信；
用 `refund:{id}` 做键，第二封会被 `insertIfAbsent` 静默挡掉 —— 顾客永远收不到「钱退了」。

反过来，同档位重复触发（接口已拦，但事件重放可能发生）只发一封，这是想要的。

### 2. 退货地址取**单据快照**，不重新读店铺设置

`return_agreed` 的正文用 `refund_request.return_address`（ADR-061 同意的时刻写进去的），
不是 `theme.return_address`。

理由与 ADR-061 一致：商家在顾客寄回前改了店铺地址，顾客手上按旧地址寄出的包裹不能白寄。
邮件里印的地址必须和单据上的是同一个。

### 3. 失败不阻断，但绝不静默

同意退款时钱已经打出去了。这时候邮件入队失败若让接口 500，商家会以为没退成、再点一次 ——
比少发一封信糟得多。所以：

- enqueue 失败只写 `req.log.warn`，接口照常返回成功；
- 邮件本身进 outbox 后由派发器重试，配置错了会在通知记录里留下 `failed`，商家能看见。

**不是静默降级**：日志有、通知记录有，只是不把钱已经动过的请求回滚。

### 4. 开关并入现有那组邮件开关

`notification_settings.refund_enabled`，默认 `true`，与下单/发货/到货提醒同一处配置
（后台「设置 → 通知」）。关掉就一封都不入队 —— 不制造发不出去的待办。

## 后果

- notification：`0003_refund_update.sql`（`refund_enabled`）、`refund_update` 模板、
  `renderRefundUpdate`、`enqueueRefundUpdate`、类型与设置映射
- API：退款三条路由（同意 / 确认收货 / 拒绝）在审计记录之后入队通知；
  统一的 `notifyRefundUpdate` 辅助函数，`orderNumber` 取订单 id（本仓订单号即 id）
- 后台：通知设置多一个「退款进度邮件」开关；通知记录列表能筛到 `refund_update`
- 测试：notification +4（开关关闭不入队、两档位两封、地址转义、拒绝文案）、
  api +4（仅退款同意、拒绝、退货两封、总开关关闭）
- 迁移 55 个

## 遗留

- **站内信**：淘宝还有站内消息中心，顾客不打开邮箱也能看到。自建商城没做，
  现在只能靠邮件 + 自己回订单页
- **同意退货时的寄回期限**：淘宝会给「请在 7 天内寄回」。我们没有超时关闭逻辑
  （与「不做无人值守状态变更」一致），所以邮件里也不提期限
- **退款到账时间**：邮件写「以支付渠道为准」，因为沙箱支付没有真实到账回执可引用
