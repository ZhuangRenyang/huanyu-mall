# ADR-030 后台工作台：进门先看「今天怎么样」

- 日期：2026-11-12
- 状态：Accepted
- 范围：order 模块（状态计数、今日已付汇总）、API（`admin/dashboard`）、admin（工作台页 + 菜单首项）
- 关联：ADR-023（退款审核）、ADR-024（订单状态）

## 背景

后台登录后直接落在**商品列表**：`/` 重定向到 `/products`。商家想知道的第一个问题
——「今天卖了多少、有多少单要发、有没有退款等我审」——没有任何地方回答。

成熟系统都不是这么做的：

| | 进门第一屏 |
|---|---|
| 淘宝卖家中心 | 今日支付金额 / 支付订单数 / 待发货 / 待退款 + 待办 |
| Shopify Admin | Home：今日概览卡片 + 待办 + 最近订单 |

商品列表是「做事的地方」，不是「看状况的地方」。把「看状况」放在第二个位置，
等于每天让商家先翻一遍商品。

## 决策

### 1. 菜单最前单独成组「概览 → 工作台」

不塞进商品/订单任何一组：它是跨域的入口。`/` 与未匹配路由都重定向到 `/dashboard`。

### 2. 只回答四个问题，不做趋势图

| 指标 | 口径 |
|---|---|
| 今日支付金额 / 今日支付订单 | `payment_status = paid` 且 `created_at >= 今天 0 点` |
| 待发货 | `paid` / `partially_fulfilled`（付过款但没发完） |
| 待处理退款 | 退款单 `status = pending` |

**为什么不做趋势图**：按天聚合需要历史快照与对照区间，第一版没有数据积累也画不出东西。
等有真实数据了再单独做「经营分析」，不要在概览页塞一个只能看昨天和前天的小折线。

### 3. 「今天」用服务器本地时区的零点

商家理解的「今天」是自己店里的今天，不是 UTC。多时区店铺需按渠道时区切分 —— 那是后面的事，
先不做半个时区。

### 4. 一次请求拿完，不做四个接口

四个指标分四次请求会出现「金额和订单数对不上」的中间态（一个请求跨过零点就变了）。
一个接口内部 `Promise.all` 并发查，返回时口径一致。

## 后果

- 商家进门能看到今天做了多少生意、有多少事压着，页面上的「去发货 / 去审核」直接跳转对应列表。
- 订单模块新增两个只读聚合方法（`countByStatus`、`summarizePaidSince`），
  后续订单页签角标也能复用。

## 不做

- **不做趋势图 / 同比环比**：没有历史数据积累，画不出可信的东西。
- **不做多币种分币种汇总**：当前以单币种店铺为主；真出现多币种再按币种分组。
- **不做自定义看板**：商家不会配置，配置了也不看。
