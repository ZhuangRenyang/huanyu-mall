# ADR-095：退款退回积分——扣回发放、退回抵扣

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-093（积分发放）、ADR-094（积分抵扣）、ADR-023（不做自动退款）

## 背景

订单退款后，积分账本上留了两笔「已经失效」的记录：

- 该单**发放**的积分（earn）：交易取消了，积分不该继续算数；
- 该单**抵扣**的积分（spend）：顾客的钱退了，当初抵掉的积分也该退回。

不处理的话，顾客「下单用积分 → 退款」能凭空刷积分（发放的积分不扣回 + 抵扣的积分
又退回 = 净赚），这是积分版的「套现」。

## 决策

### 1. 退款审核通过后，回冲该订单的全部积分

新增 `refundPointsForOrder(orderId)`，挂在退款打款成功之后（`approve` 与
`receive-return` 两个打款路由）：

- `earn`（delta 正）→ 扣回（`delta = -earn`）；
- `spend`（delta 负）→ 退回（`delta = -spend`）。

### 2. 顺序：先退回抵扣、再扣回发放

不能反：一单既发又抵（先 spend 扣减、后 earn 发放），余额 = earn - spend。
先扣 earn 会把余额打成负数，触发「余额不足」。所以必须先加回 spend、再减去 earn。

### 3. 幂等：同订单只回冲一次

`refundPointsForOrder` 先按 `order_id` 查流水，若已有 `refund` 类型流水则直接返回。
退款 workflow 有幂等键，但路由层重试仍可能重复触发——靠流水去重兜底。

### 4. 失败不阻断退款

回冲失败只记日志（`refundPointsSafely`）：钱已经退了，把「已退款」报成失败
会让商家重复点，重复打款。积分回冲是可补偿的（人工查流水对账），不能为它
赌上资金主链路。

## 后果

- promotion：`refundPointsForOrder`、仓储 `listPointLedgerByOrder`
- API：退款 `approve` / `receive-return` 打款成功后回冲积分（失败只记日志）
- 测试：promotion +1（扣回发放、退回抵扣、幂等）；promotion 67、api 343；迁移 65

## 遗留

- **积分过期**：现在不过期，退款回冲后过期策略要一并考虑
- **部分退款**：一期只支持全额退款，部分退款的积分回冲需按比例，等部分退款再做
- **换货**：换货不退钱、不动积分（钱和积分都不变），无需回冲
