# ADR-057：订单导出 CSV

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-056（日期筛选）、ADR-033（物流单号）

## 背景

按日期筛完订单，商家的下一个动作一定是「导出来」：发给会计、发给仓库、
或者自己按单号核对签收。之前只能一页页截图。

淘宝「已卖出的宝贝」有导出（一次最多 1 万单，超出按批下）。我们照这个位置补。

## 决策

### 1. 一行一单，商品合并成一格

一行一商品会让「实付」「运费」在同一单里重复出现，按列求和直接错。
商品列写成 `标题 ×2；标题 ×1`，与淘宝导出同形。

### 2. 23 列，按对账顺序排

订单号 / 下单时间 / 订单状态 / 支付状态 / 顾客邮箱 / 收件人 / 电话 /
国家 / 省 / 市 / 详细地址 / 邮编 / 商品 / 件数 / 商品小计 / 运费 / 税费 / 优惠 / 实付 /
币种 / 物流公司 / 运单号 / 顾客留言。

状态导出**中文标签**（「已付款/待发货」），不是 `paid` —— 这张表是给人看的。
金额导出成 `107.00 CNY`：财务要元，不要分；币种跟着金额走，避免多币种店铺混算。

### 3. BOM + 转义 + 注入防护，三件都必须做

- **BOM**：不加，Excel 打开中文全是乱码（这是最常见的「导出坏了」投诉）；
- **转义**：含 `,` `"` 换行 或首尾空白的字段整体包引号、内部引号翻倍。
  漏一条，一行裂成几列，整张表对账错位；
- **注入**：以 `=` `+` `-` `@` 开头的单元格前面加单引号。内容来自顾客（留言、地址），
  不能让它在 Excel 里变成公式。

首尾空白也包引号：Excel 会吃掉前导空格，而「有空格/没空格」对账号是两回事。

### 4. 上限 5000 单，超了报错而不是截断

截断的表格最容易被当成全量对账 —— 少了几百行没人发现，账就永远差一点。
超限返回 400 并说清「请缩小时间范围或按状态分批」。

### 5. 运单批量取，不逐单查

新增 `fulfillment.listFirstTrackingByOrderIds(ids)`：一条 join 取回所有订单的运单。
5000 单逐单查就是 5000 次往返。

拆包分批发时只取**最早一条**：导出是给对账看的，一个订单一个主要单号就够。

### 6. 前端走 fetch + Blob，不用 `<a href>`

接口要 `Authorization: Bearer`，浏览器直接打开链接不会带 token，只会拿到 401。
401 时先尝试 refresh 再重试一次：后台挂在 tab 上几小时，access 过期是常态，
为了导一张表让人重新登录是最没必要的打断。

### 7. mock 模式不导出

演示数据是假单，导出去当真实对账材料反而有害。
与「演示模式无法提交退款申请」同一条口径，报错文案说清楚。

## 后果

- API：`GET /admin/orders/export`（与列表同一套筛选；`text/csv` + BOM；超限 400；
  写审计 `order.export`）
- 新增 `apps/api/src/lib/csv.ts`（`csvCell` / `toCsv` / `moneyCell` / `timeCell`）
- fulfillment 模块：`listFirstTrackingByOrderIds`（仓储 + 服务）
- 后台：订单页「导出 CSV」按钮（带当前筛选），文件名带时间戳
- 测试：api +6（401、BOM/表头/金额/运单、逗号引号转义后仍是 23 列、
  `=` 开头加单引号、日期筛选、超限 400）

## 遗留

- **导出任务化**：5 万单需要异步任务 + 下载中心（对象存储 + 过期链接），
  当前同步返回在 5000 单量级够用
- **按列选择导出**：仓库只要地址与单号、财务只要金额。现在一股脑全给，
  列多了反而难核对，等有明确诉求再加
- **xlsx**：CSV 的日期/金额在 Excel 里是文本，财务做透视表要手动转格式。
  真要做需要 xlsx 库（体积换体验），暂不引入
