# ADR-011：组件库采用 shadcn/ui 实现体系

- 状态：已采纳（2026-11-09）
- 决策者：项目负责人（用户）明确要求「必须迁 shadcn/ui」
- 关联：蓝图铁律 1（模块化）、铁律 13（前台与后端解耦）、简报第十节（界面规范）、ADR-010（图标库）

## 背景

项目初期的 `@mall/ui` 是自建组件库：Tailwind + 手写变体类 + 极简 `cn`（`inputs.filter(Boolean).join(' ')`），共 10 个组件，全部服务于店面的交易主链路。

三方面压力促成了本次迁移：

1. **蓝图明文要求**：项目简报第十节写「组件库：shadcn/ui + Tailwind CSS——前台与管理后台共用一套设计语言」。
2. **模板可更换受阻**：`apps/storefront/app/globals.css` 与 `apps/admin/src/index.css` 都用 `@source "../../../packages/ui/src"` 把私有组件库源码拉进 Tailwind 扫描；而 `cart-drawer.tsx` 又依赖 `@mall/ui` 自己的 `Button` / `IconButton` / `QuantityStepper`。结果是**任何新店面模板想挂"购物车抽屉"这类可嵌入组件，都必须把整套私有组件库一起引入**。这对"预置多套模板 / 按 Channel 分配不同店面"是实质障碍。
3. **无障碍是硬缺口**：后台的 `focus-modal.tsx` / `sheet.tsx` 是手写的 `role="dialog"` + Escape + 滚动锁，**没有焦点陷阱**（Tab 会跑到背后页面）；设置页的 tab 是手写 `role="tablist"`，没有方向键导航与 `aria-controls` 关联。这直接对应生产就绪记分卡里「无障碍无证据」的 Bronze 判定。

## 决策

采用 **shadcn/ui 的实现体系**，而不是引入某个组件库依赖：

- **保留**：`@mall/design-tokens` 作为配色/圆角/阴影/动效的单一事实来源（品牌蓝 `--primary`、橙 `--accent-orange`、`--radius` 派生档位）
- **引入**：Radix primitives（行为与无障碍）、`class-variance-authority`（变体声明）、`tailwind-merge` + `clsx`（类冲突消解）
- **形态**：组件源码放在 `@mall/ui`，前台与后台共用（shadcn 本身就是"把源码复制进项目"的分发方式，与我们这个共享包在产物形态上一致）
- **不采用**：shadcn CLI 生成的 Next.js 专属结构、shadcn 默认皮肤（UIUX 明确否决"会和一堆 AI 项目撞脸"）

## 实施（分 5 阶段）

| 阶段 | 内容 | 结果 |
|---|---|---|
| 1 | `cn` 换成 `twMerge(clsx(...))` + `extendTailwindMerge`（登记 44 个品牌语义色与 `aspect-product`）、`components.json`、导出收敛 | 完成 |
| 2 | `button` / `badge` / `skeleton` / `icon-button` 改 cva 实现（**API 与尺寸不变**：sm 32px / md 44px / lg 52px） | 完成 |
| 3 | 新增 8 个 Radix 原子：`dialog` / `sheet` / `tabs` / `select` / `input` / `textarea` / `label` / `toast` | 完成 |
| 4 | 消费方收编：删 admin 自写的 `focus-modal.tsx` / `sheet.tsx`，设置页改 `Tabs`，`field.tsx` 底层换 `Input`/`Select`/`Textarea` + `Label` | 完成 |
| 5 | 文档与 ADR | 完成 |

阶段 3/4 之外还补了三项**门禁**（否则上面这些结论无法被验证）：

1. **Token 纪律测试**（`packages/ui/__tests__/token-discipline.spec.ts`）：扫 `packages/ui/src` 全量源码，禁止出现硬编码颜色（`#hex` / `rgb()` / `hsl()`）与自造 `z-index`（`z-50` 之类）。层级一律走 `--z-modal` / `--z-drawer` / `--z-toast` 令牌。
2. **视觉快照门禁**（`packages/ui/scripts/visual-snapshot.ts`）：用 Tailwind v4 官方 Node API（`compile()`）把「迁移前 / 迁移后」的类名清单编译成真实 CSS，解析出每个类的声明并把 `var(--token)` 还原成字面值，逐属性对比。仓库没有 git 历史，所以**基线是把迁移前 admin 自写组件的类名逐条抄录进脚本**（每条带出处行号）。跑法：`pnpm exec tsx packages/ui/scripts/visual-snapshot.ts`；快照落 `docs/05-delivery/visual-snapshot.json`。当前结果：**16 个表面、77 条差异、0 条未登记差异**。
3. **真实 DOM 测试栈**：`packages/ui` 增加 `jsdom` + `@testing-library/react`（devDependencies，版本进 `catalog:`）。原因：Radix 的 Portal 在服务端静态渲染下**不产出节点**，`renderToStaticMarkup` 只能测到外壳，恰好把本次迁移最该验证的东西（焦点移入、Escape、aria 关联）全部跳过。

## 保留项（有意不迁）

1. **品牌视觉**：不套 shadcn 默认皮肤。Dialog/Sheet 的默认尺寸、圆角、遮罩浓度都**校准到迁移前 admin 的实现**（`max-w-md`/`rounded-xl`/`bg-neutral-900/40`/抽屉 `max-w-xl`），目的是让视觉快照差异为 0。另外几处也按"视觉零变化"回校过：弹层宽度写成 `calc(100% - 2rem)`（等价于旧实现的 `p-4` 容器内缩）、底栏上间距 `mt-5`（不是 shadcn 默认的 `mt-6`）、`TextArea` 的 `rows=2`（等价于旧的原生 textarea）、Tab 的悬停变前景色**只作用于未选中项**（旧实现就是如此）。
2. **对外 API**：`Button` 的 `variant: primary|secondary|ghost|destructive`、`size`、`loading` 保持原样；`SelectField` 的 `onChange(e.target.value)` 签名通过内部合成事件保住，调用方零改动。
3. **`Skeleton` 的视觉实现**：仍用 `design-tokens` 的 `.skeleton` 类（带 `--skeleton-delay: 300ms` 延迟，快速加载时不闪骨架屏），**没有**换成 shadcn 的 `animate-pulse` —— 那是降级。组件形态（`data-slot`、props 透传、`aria-hidden`）已对齐 shadcn。
4. **`CartDrawer` 的容器**：保留自写抽屉（见下）。

## 遗留项（必须知道，不要以为已经解决）

1. **`CartDrawer` 仍依赖 `@mall/ui` 内部 `Button` / `IconButton` / `QuantityStepper`。**
   它已具备 Esc、滚动锁、焦点归还，本次补上了**焦点陷阱**（Tab/Shift+Tab 在抽屉内循环），但容器仍带移动端定制（`min(440px, calc(100vw-48px))` 宽度、`--safe-area-bottom` 安全区、`ease-emphasized` 滑入）。用通用 `Sheet` 硬换会压平这些产品细节，故未替换。
   **为什么不能直接换成 Radix `Sheet`**（技术结论，不是偏好）：购物车抽屉是**常驻挂载**的（关闭时也在 DOM 里，靠 `translate-x-full` 移出视口）。Radix 的 `Dialog`/`Sheet` 只有「打开时才挂载」或「`forceMount` 常驻」两种模式：
   - 常规模式 → 关闭时抽屉节点消失，DOM 结构变化（视觉快照门禁会记差异）；
   - `forceMount` → Radix 的 `DialogContentModal` 在挂载时无条件调用 `hideOthers(content)`，会给**整页**加 `aria-hidden`，导致抽屉关闭时全站对屏幕阅读器不可见 —— 这是不可接受的无障碍缺陷。
   代价是焦点陷阱目前是自写的（40 行，Tab/Shift+Tab 在抽屉内循环），不是 Radix 原语。这是**已知取舍**，不是「已迁移到 Radix」。
   **彻底解耦需要做 headless 化**：库只提供状态与行为，UI 由模板注入（插槽），或改成 Web Component + Shadow DOM。这是"模板可更换"从口号变成事实的关键一步，**留待模板系统阶段**。
2. **`apps/admin` 没有测试运行器**：本次无障碍验证靠 `@mall/ui` 的 vitest（jsdom + testing-library，35 个用例）与真实浏览器验收，admin 侧改动无自动化回归。已在 `OPEN-DECISIONS.md` 登记。
3. **Radix 的体积成本**：admin bundle 从 324.59 kB → 459.16 kB（gzip 101.15 → 145.32 kB）。管理后台是内网使用，可接受；**但前台 storefront 若全量引入需注意 LCP 预算**（简报要求 < 2.5s），模板阶段应确认 tree-shaking 生效。
4. **`Select` 的展开交互未纳入单测**：jsdom 对 Pointer Events 捕获、ResizeObserver、DOMRect 支持不全，补 polyfill 仍会在后续步骤静默中断。这是**测试环境空洞**，不是组件缺陷；已在测试文件里显式标注，改为浏览器验收。
5. **`Sheet` 只有进场动效，没有退场动效**：进场用 Tailwind v4 的 `starting:` 变体（生成 `@starting-style`，元素插入 DOM 时从偏移位过渡到原位）；**退场**依赖 Radix `Presence` 等待 CSS `animationend`，而我们没有 keyframes（design-tokens 里只有 `skeleton-pulse`）→ 关闭是瞬时的。要补退场滑出，得在 design-tokens 增加 `@keyframes`，属于令牌层改动，不在组件层硬塞。
6. **`Toast` 用 sonner，但主题接管是「行内 style」而非 CSS 规则**：sonner v2 在运行时把样式表 `appendChild` 到 `<head>`，落点在应用样式表**之后** —— 同优先级的 CSS 规则会被它反超（白底又回来了）。所以颜色/圆角/字栈/层级改为在 `<Toaster style={...}>` 上用**行内 style** 传 CSS 变量（`--normal-bg: var(--card)` 等），与注入顺序无关。toast 后代元素（关闭按钮尺寸）无法行内化，放在 `packages/ui/src/sonner.css`（用 `body` 前缀把特异性抬高一级来压过 sonner 的规则），两个应用各 `@import "@mall/ui/sonner.css";` 一行即可。**当前两个应用都还没有挂 `<Toaster />`**，所以这套接线暂时没有消费方（`page-specs.md` 已把 Toast 列为通用原子）。

## 后果

**正面**
- 无障碍能力从"手写近似"变成"Radix 保证"：焦点陷阱、Escape、焦点归还、背景滚动锁定、`aria-labelledby`/`describedby` 关联、Tabs 方向键导航、Select 键盘完整操作。
- 组件源码形态与行业主流一致，第三方模板作者不再需要学一套私有 API。
- `cn` 从"拼接"变成"冲突消解"，修掉了 `aspect-product` 与 `aspect-square` 同时存在这类静默样式 bug（`aspect` 不在 tailwind-merge 内置分组，已用 `extendTailwindMerge` 登记）。

**负面 / 风险**
- 体积增长（见遗留项 3）。
- 新增运行时依赖：Radix dialog / tabs / select / slot、cva、clsx、tailwind-merge、sonner，版本统一进 `pnpm-workspace.yaml` 的 `catalog:`（ADR-006）。另新增 2 个 devDependencies：`jsdom` + `@testing-library/react`（测试栈，理由见"实施"节第 3 条）。
- 组件默认值被校准到 admin 现有视觉，通用性略降（如 Dialog 默认 `max-w-md`）；未来做模板系统时应重新审视默认值。
