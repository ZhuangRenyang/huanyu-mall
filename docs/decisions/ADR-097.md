# ADR-097：后台统计报表——近 30 天交易汇总 + 状态分布 + 销量排行

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-030（工作台）、ADR-067/070（销量）

## 背景

后台只有「工作台」（看**今天**），没有「统计」（看**一段时间**）。
商家想知道「这个月卖了多少、退了多少、哪个商品卖得最好」，此前只能
导出 CSV 自己算。CRMEB/淘宝后台都有独立的「统计/数据中心」。

## 决策

### 1. 统计只看近 30 天，一期不做自定义时间窗

默认窗口 30 天（`last30Days`）。自定义起止时间需要日期选择器 + 分页的
趋势图，属独立增强；先把「近 30 天」这个最高频的口径做扎实。

### 2. 交易汇总四条口径，金额服务端算

`summarizePaidBetween(from, to)`（销售额/订单数）+ `summarizeRefundsBetween(from, to)`
（退款额/笔数）→ 客单价 = 销售额 ÷ 订单数，净收入 = 销售额 − 退款额。
退款额只数「已同意」的退款单（approved），拒绝的不算。

客单价在 API 层用 `Math.round` 除（不是 bigint 除法）：它是展示指标，
不是资金字段，minor 的整数舍入足够。

### 3. 销量排行按变体聚合，标题从 product 批量取

`topSellingVariants(limit)` 直接 SQL `GROUP BY variant_id ORDER BY sum(quantity)`
取 top 10；标题用 `listVariantsByIds` 一次批量查（禁 N+1），
变体标题为空退回 sku。

### 4. 统计是只读页，权限同工作台（orders）

只读、不导出、不落缓存。staff 持 orders 权限即可看。

## 后果

- order：`summarizePaidBetween`、`summarizeRefundsBetween`、`topSellingVariants`
- API：`GET /admin/statistics`（近 30 天交易 + 状态分布 + 销量 top 10）
- SDK：`getStatistics`；后台：`/statistics` 页 + 导航「统计」
- 测试：api +2（汇总与排行、无订单返回 0）；api 345、order 34；迁移 65

## 遗留

- **自定义时间窗与趋势图**：需要日期选择器 + 按天聚合的趋势数据
- **按渠道/地区拆分**：多渠道路径不同，属多商户后的增强
- **导出**：统计页暂不导出（CSV 在订单列表有，统计导出单独加）
