# ADR-018 税务：按收货国家解析税率 + 后台可切换可调整

- 日期：2026-11-11
- 状态：Accepted
- 范围：tax 模块、购物车合计、下单金额、店面结账、后台税务设置

## 背景

用户口径：**「没有实际地区，看用户选择，最好可以切换调整」**——不预设某个税区，
税率跟着顾客在结账时选的国家走，商家在后台随时改。

动手前核实到的事实：

1. `tax` 模块有 `tax_rate_rule` 表与 `TaxService`，但**从未接进结账链路**：
   `cart.service.ts` 的 `totals.tax_minor` 写死 `0n`，订单 `tax_minor` 恒为 0。
2. 后台**没有任何税务入口**（只有 `getRateForChannel` 这类内部方法）。
3. 更严重：`checkout.ts` 里 `shippingAddress: {}` 写死 ——
   **订单根本没存收货地址**。它既是按国家计税的前提，本身也是一个独立缺陷。

## 决策

### 1. 税率解析顺序：国家覆盖 → 默认 → 未配置（0）

```
顾客选的国家（ISO 两位码，大写）
  ├─ 命中 tax_rate_rule(country_code=该国)  → 用它
  ├─ 否则命中 tax_rate_rule(country_code IS NULL) → 默认税率
  └─ 都没有 → 0 税（rateSource = none，界面可见）
```

- 国家码在服务层归一为大写并校验 `^[A-Z]{2}$`，避免 `cn` / `CN` 存成两条。
- `resolveRate` 返回 `source`，前台/后台都能看出「这一单的税是哪来的」。

### 2. 一个总开关，默认关闭

`tax_settings.enabled` 默认 `false`：没配税率就不该收税，
和营销功能开关同一取向——**关了就是不收**，不靠「税率填 0」这种隐式表达。

### 3. 含税价 / 价外税是两种口径，不能混

```
含税价（prices_include_tax = true）：tax = amount × rate / (10000 + rate)
                                     合计不再加税（税已含在价里，只是拆出来报账）
价外税（false）：                    tax = amount × rate / 10000
                                     合计 = 商品 + 运费 - 折扣 + 税
```

- 全部 bigint 整数运算、half-up 四舍五入，不用浮点。
- `CartTotals.tax_minor` 与 `CartTotals.total_minor` 都由后端算，
  店面不再自己 `subtotal + shipping - discount`（原来那行把税当 0，接上税后会与实付不一致）。

### 4. 税按「折后行金额」算，并快照进订单

- 行税额用 `unit_price × qty - 行折扣` 计税，不是原价——否则折后仍按原价收税。
- 下单时行级 `tax_rate_bps` / `tax_amount_minor` 随订单行落库：
  **后续改税率不会改变历史订单**（订单是会计凭证，不能回溯变动）。
- 收货地址随下单提交并落 `order.shipping_address`，税率也从同一份国家解析，
  保证「购物车看到的税」与「订单收到的税」一致。

### 5. 后台：设置 → 税务（三段式）

| 段 | 内容 |
|---|---|
| 计税 | 总开关 / 税名（订单上显示）/ 价格是否含税 |
| 默认税率 | 名称 + 百分比（没单独设的地区用它） |
| 地区税率 | 两位国家码 + 名称 + 百分比，可增改删（删掉即回落默认） |

权限 `settings`（与其它店铺配置同权，staff 不可见），全部写审计
（`tax.settings.update` / `tax.default_rate.update` / `tax.country_rate.update|delete`）。

### 6. 店面「可选国家」由后端给，不再是写死的一条

发现：店面 `COUNTRIES = [{ code: 'CN', name: '中国' }]` 写死在前端——顾客的「选择」
其实只有一个选项，后台配了别国税率也**选不到**，「按用户选择计税」无从发生。

改为 `GET /store/checkout/countries`：

```
可选项 = 内置常用国家/地区（26 个） ∪ 商家配过税率的国家（去重）
每项带：code / name / tax_rate_bps / rate_source（country | default | none）
```

- **税率关着时统一报 0**：否则界面会写「收 13%」却并不收，属于欺骗。
- 商家在后台加一个国家税率，店面立刻多一个可选项——**不用改代码、不用发版**。
- 前端拿不到清单时退回最小清单（中国），**不因为附加接口失败就让顾客下不了单**。
- 选择国家即触发重算：税额、合计跟着变（ADR-018 §5 的购物车链路）。

**没配运费区域的国家会选得到但下不了单**（无可用配送方式），这是正确行为：
能不能卖到某国首先由运费区域决定，税率只决定收多少税。

## 后果

**收益**：商家不必预先决定「卖到哪」，顾客选哪个国家就按哪个国家的税率算；
调税率不用发版；订单税额可审计、不随配置漂移。

**代价与风险**：

- 只做了「单一税率按国家」。**没有**税号（VAT/GST）、没有税区（EU 内多国）、
  没有按类目差异税率、没有多税种叠加。真要做跨境合规申报时需重做这一层。
- 税率改了对**已下单未支付**的购物车会立即生效（购物车是实时重算的）；
  已经生成的订单不受影响。
- 运费也按同一税率计税（`shippingTaxMinor`），部分国家运费免税，需要时再加开关。

## 不做（明确记下来，避免以后误以为漏了）

- 不做税号收集与验证、不做 OSS/IOSS 申报、不做多税种（联邦+州+市）叠加。
- 不做「按商品类目设不同税率」——等真有跨境/多品类合规诉求时再评估。
- 不做税额手工覆盖（会计调账走退款/补差，不篡改订单税额）。
