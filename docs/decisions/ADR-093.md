# ADR-093：积分第一刀——账本 + 订单完成发放

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-078（D 期营销）、ADR-029（领券）、ADR-075（取消释放库存）

## 背景

D 期营销里，积分是「会员体系」的底座：订单完成后给顾客积累积分，
后续可用积分抵扣。CRMEB/淘宝都有积分。此前我们完全没有积分概念。

积分与钱的边界必须先定清：**积分是顾客资产，但不是钱**——不可提现、
不可转让，只能在本店抵扣。这决定了它不会走「退款打款」那类资金链路。

## 决策

### 1. 积分单位：整数「点」，与金额换算用常量

- 发放：实付每 `POINT_EARN_DIVISOR_MINOR = 100` minor（1 元）发 1 点；
- 抵扣：每点抵 `POINT_DISCOUNT_MINOR_PER_POINT = 1` minor（100 点 = 1 元）；
- 上限：积分抵扣不超过订单应付的 `POINT_MAX_DISCOUNT_RATIO_BPS = 50%`。

三个常量导出自 promotion 模块，先固定、后续做成店铺设置（与 ADR-089 到货提醒
有效期同一条「常量 → 设置」的路径）。

点数用 bigint，不引入浮点——「1 元 = 1 点」等价于点数与 minor 同数值，
发放 `paidMinor / 100`、抵扣 `points × 1`，全程无精度问题。

### 2. 账本两表：balance 单行 + ledger 流水

`point_balance`（customer_id 主键，balance，CHECK >= 0）存当前余额；
`point_ledger`（kind / delta / balance_after / order_id）存流水，balance_after
快照让对账可回溯。

余额变更走 `applyPointDelta`：事务内 `INSERT ... ON CONFLICT DO NOTHING` +
`SELECT ... FOR UPDATE` + `UPDATE ... RETURNING`，与 gift_card 扣减同一套
「行锁 + 原子」纪律，杜绝并发下「先查后写」的余额竞态。

### 3. 发放触发：订单完成（确认收货）

`POST /store/orders/:id/confirm-receipt` 完成后调用 `earnPointsForOrder`，
由 feature 开关 `points` 控制（默认关）。

- **幂等**：`point_ledger` 的 `unique (order_id) WHERE kind='earn'` 保证同一订单
  只发一次；事件重放/重复调用不会重复发；
- **失败不阻断确认收货**：积分是赠予，发放失败只记日志，不能让顾客以为
  「货没确认」。

### 4. 抵扣留到下一刀

本轮只做「发放 + 账本 + 余额查询」，**抵扣不接入结账**。抵扣会改结账计算链路
（金额服务端算的铁律 13），且需要「下单成功才扣积分、取消/退款退回」的补偿，
与 gift_card 的 consume/release 同一套，属独立一刀，不能和发放混在一个提交里
做完（改动面过大，无法可靠验证）。

## 后果

- promotion：迁移 `0013_points.sql`、`point_balance` / `point_ledger` 模型、
  `POINT_*` 常量、`PointBalanceDTO` / `PointLedgerDTO`、仓储 `applyPointDelta`
  （原子）/ `getPointBalance` / `listPointLedger`、服务 `earnPointsForOrder`（幂等）/
  `getPointBalance` / `listPointLedger`、纯函数 `pointsEarnedFromPaid` / `pointDiscountMinor`
- feature：`MarketingFeature` 加 `points`
- API：`GET /store/points`（余额 + 流水）；确认收货发积分
- SDK：`getStorePoints`
- 测试：promotion +3（折算、封顶、幂等）、api +3（发放、开关关着不发、余额查询）；
  promotion 64、api 343、storefront 46；迁移 64

## 遗留

- **积分抵扣**：结账接入 + 下单扣分 + 取消/退款退回（下一刀，与 gift_card consume/release 同构）
- **积分过期**：现在不过期；淘宝/CRMEB 有有效期，需要滚动过期或按年清点
- **发放比例可配置**：现在固定 1 元 = 1 点，应做成店铺设置
- **积分商城/兑换**：用积分换商品，属另一条商品链路，暂不做
