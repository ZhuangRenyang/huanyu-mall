# ADR-047：店铺公告（首页通告条落地）

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-046（外观设置读回）、ADR-045（店铺资料）

## 背景

后台「设置 → 外观」里从一期就有「首页通告条」输入框（`maxLength=40`）。但：

- `theme_settings` 没有 `announcement` 列
- `PUT /admin/settings/theme` 的 body schema 里没有这个字段（会被剥掉）
- 店面从不渲染公告

于是商家写下「双十一全场 8 折」，点保存，页面提示「已保存」，内容直接消失。ADR-046 修 logo 时发现了同一批幽灵字段，这次把它接通。

## 决策

### 1. 落库在 `theme_settings.announcement`

与店名、客服电话同一行：它是「店铺当前在说什么」，属店铺身份/外观，不是营销活动（活动有 promotion 模块）。迁移 `0003_announcement.sql` 加一列 `text`，可空。

### 2. 40 字上限写在服务端

前端输入框有 `maxLength`，但那只是体验。schema 用 `z.string().max(40)`：公告条是一行文本，超了会把页头挤成两行，靠前端守不住。

### 3. 空串统一成 `null`

与 `support_phone` 同口径：`""` 与 `null` 混存，渲染时就得判两次，展示逻辑迟早出现「空字符串被认为有公告」的白条。在 schema 里 `transform` 成 null。

### 4. 公告条在页头之上，全站可见

参考 Shopify 的 announcement bar 与淘宝店铺公告：一条通栏、字号小、背景用 `primary-subtle`。

不做「只在首页显示」：商家写公告是为了让人看到，首页之外的落地页（商品页、列表页）同样需要这条信息；隐藏它等于让活动只在一条路径上生效。

不做可关闭（× 按钮）：需要记「已关闭」状态（cookie/localStorage），而公告本身是短期信息，加状态只会让「商家改了公告但顾客看不到」变成新问题。

### 5. 保存时一起提交

`saveTheme()` 现在提交 `logo_file_id` 与 `announcement`。合并语义下「不传 = 不动」，但**显式提交**才是对的：一旦以后改成整体替换，漏字段就是静默清空。

## 后果

- theme 模块：迁移 0003、模型一列、DTO 与默认值、仓储映射
- API：`themeBody` 接受 `announcement`（trim + 40 字上限 + 空串转 null）
- 后台：保存外观时提交公告（输入框原本就在，现在真的会存）
- 店面：`getStoreProfile()` 返回 `announcement`，布局在页头之上渲染公告条；为空不渲染任何节点
- 测试：`theme-settings.spec.ts` 新增 3 条（保存读回 + bootstrap 带出、清空为 null、超 40 字 400）

## 遗留

- 公告不支持富文本/链接：一行纯文本够用，带链接要处理 XSS 与跳转白名单
- 公告没有生效时间：需要排期字段（`starts_at` / `ends_at`），属运营排期能力
