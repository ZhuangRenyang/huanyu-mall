# ADR-021 运费模板随商品走：商品上架时选模板，配置入口在商品域

- 日期：2026-11-11
- 状态：Accepted
- 修订：ADR-020（该 ADR 把运费当成"全店一套配置"，因此放错了归属与入口）
- 范围：product 模块、fulfillment 模块、cart 运费计算、admin 菜单与商品编辑
- 关联：ADR-014（简单优先）、ADR-019（国家是唯一口径）

## 背景

ADR-020 之后用户否掉了它的落点：

> 这个功能不要在系统设置里去弄，这种是商品的功能，要在上架商品详情里去设置，
> 不要什么东西都往系统设置里去塞，跟系统没关系的不要放系统设置里，要分类对应好。

判断是被纠正的，不是口味问题。淘宝的卖家后台里，运费确实挂在商品上：

- **商品发布页 → 物流信息**：选「运费模板」，或选「卖家承担运费」（包邮）；
- **物流工具 → 运费模板**：模板里配计费方式与各地区的价格。

ADR-020 的错在于：把「发货区 + 运费方式」当成了**全店唯一的一份配置**，
于是它自然长成了"设置项"。但真实模型里那一坨是**可复数的模板**，
商品才是选择模板的主体 —— 归属一变，入口就该跟着变。

## 决策

### 1. 三层模型：商品 → 运费模板 → 发货区 → 运费方式

```
product.shipping_profile_id  ──┐
product.free_shipping          │  商品只决定「用哪套 / 是否包邮」，不填金额
                               ▼
shipping_profile（运费模板）    ← 可多套：默认模板 / 重货专线 / 冷链
  └ shipping_zone（发货区，按国家）
      └ shipping_option（固定价 / 满额包邮）
```

- `product.shipping_profile_id`：为空 = 用默认模板；
- `product.free_shipping`：卖家包邮（淘宝的「卖家承担运费」），该商品不产生运费；
- `shipping_profile.is_default`：全店唯一，商品没选模板时的兜底，**不可删除**。

### 2. 配置入口按域归位

- **商品列表 → 运费模板**：管理模板、发货区、运费方式（独立菜单，不在设置里）；
- **商品编辑 Sheet → 运费**：选模板 + 卖家包邮开关；
- **设置页不再有「运费」**：设置里只放主题、支付、通知、税务、系统、账号安全。

判断标准：这个配置决定的是「商品怎么卖」还是「系统怎么跑」。前者归商品域。

### 3. 同一国家的唯一性只在模板内成立

ADR-020 的守卫是"一个国家只能属于一个区"，全局。多模板下这条要收窄：

- **同一模板内**：一个国家只能属于一个区（否则两套价同时命中，是可绕过口子）；
- **跨模板**：允许重复（默认模板发中国 8 元、重货模板发中国 30 元），
  因为商品属于哪个模板是确定的，不会同时命中。

### 4. 结账按模板分组计价后相加

```
非包邮商品 → 按 shipping_profile_id 分组 → 每组用该组小计取最便宜方案 → 求和
包邮商品   → 不产生运费，且金额不计入任何满额门槛
任一组无可用方案 → 整单不可结（不静默免运费）
```

为什么包邮商品的金额不计入门槛：否则把包邮商品塞进车里就能"凑满额"，
让本该付运费的商品免运费——这是明确的资损口子。

## 后果

- 新增两张迁移：`shipping_profile` 表 + `shipping_zone.profile_id`（数据迁移把既有区挂到默认模板）；
  `product.shipping_profile_id` + `product.free_shipping`。
- 后台新增「商品 → 运费模板」页面（替代原「设置 → 运费」），商品编辑多一个运费区块。
- 购物车运费从"一车一套价"变成"按模板分组累加"，`shipping_method` 在多模板时名称为「运费（N 个包裹）」。
- 商品接口 `PATCH /admin/products/:id` 必须显式映射 `shipping_profile_id` / `free_shipping`：
  原来 `{ ...body }` 透传，snake_case 会被静默丢掉（有专门测试守着）。

## 验证

- fulfillment 25 条：模板守卫（默认不可删、有区不可删）、跨模板同国家允许、按模板统计可下单国家。
- cart 30 条：包邮商品运费 0、包邮商品不凑门槛、两模板运费相加（800 + 3000 = 3800）。
- api 108 条：商品更新能保存运费字段（防静默丢）、只改标题不动运费、建商品可带模板。
