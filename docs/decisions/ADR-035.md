# ADR-035 购物车：提示可用券，并停止承诺一个假的免运费门槛

- 日期：2026-11-12
- 状态：Accepted
- 范围：storefront 购物车页（`cart-view.tsx`）
- 关联：ADR-029（可领取的店铺券）、ADR-019（运费按国家算）

## 背景

两件事，都在购物车这一屏：

**1. 领了券没人提醒。** ADR-029 让顾客能在商品页领券、结账页能用券，
但购物车——顾客决定「买不买」的那一屏——对卡券只字不提。
顾客领完券回到购物车，看到的还是原价小计，等于白领。

**2. 免运费是写死的。** 购物车侧栏有一行：

```ts
const freeShipping = subtotal.amountMinor >= 19900;  // 满 199 免运费
```

这个 199 是代码里的常量，不是店铺配置。商家的免运费门槛在运费模板里
（ADR-019，按国家与金额），可能是 99、也可能是没有。购物车写「免运费」而结账时收了运费，
是对顾客的直接误导 —— 和 ADR-034 的「写死微信支付」是同一类问题。

## 决策

### 1. 购物车显示券提示，但不做「自动选券」

- 有可用券：`有 N 张优惠券可用，结算时选择`
- 只有差一点的券：`再买 ¥X 可用「减 Y」券`

**为什么不在购物车选券**：折扣金额由服务端按购物车内容算，购物车页没有折扣预览接口；
在这儿选券等于要做一遍金额预览，和结账页口径分叉的风险比收益大。
提示 + 引导到结账页选，链路最短且口径唯一。

### 2. 「差多少」只提示门槛最低的那张

罗列所有未达门槛的券会让侧栏变成一张优惠列表。挑门槛最低的一张说
`再买 ¥X`，是唯一能促成动作的信息。

### 3. 删掉写死的免运费判断

运费取决于**收货国家 + 运费模板 + 满额包邮规则**，购物车还不知道国家。
所以侧栏改成固定文案：`结算时按国家计算`。
结账页选完国家后，运费与「免运费」是后端算好直接展示的（那里才是权威）。

同时删掉空购物车里的「满 ¥199 免运费」——同一句假话的另一个出口。

## 后果

- 顾客领了券能在购物车看到「有券可用」，领券的动机闭环。
- 购物车不再承诺任何运费数字，避免「购物车说免运费、结账收了 12 元」。
- 损失了一点点「满 199 免运费」的促销暗示 —— 但那句话本来就不一定是真的。

## 不做

- **不做购物车内的券选择器**：金额预览要服务端算，购物车没有折扣预览接口。
- **不做「凑单推荐」**（再买 X 元推荐商品）：需要按门槛筛商品并排序，是独立功能。
- **不做免运费进度条**：门槛按国家不同，购物车不知道国家；结账页已有真实运费。
