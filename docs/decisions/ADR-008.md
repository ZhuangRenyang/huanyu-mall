# ADR-008: Provider 注册与配置 = 插件包声明接口 + DB 存加密配置 + 按 Channel 启用

## Status: Accepted (2026-11-08)

## Background

铁律 5：支付/履约/税务/存储/通知/搜索都定义 provider 接口，核心只依赖接口。铁律 4：扩展不改核心，定制通过 Module/Workflow Hooks/Subscriber/Plugin 完成。需要回答：provider 怎么被声明、怎么被配置（密钥）、怎么被启用、怎么按 Channel 隔离。

关键事实（对齐 Medusa，需 POC 验证其 v2.22 配置键名）：Medusa 在 `medusa-config.ts` 的 `modules[].options.providers[]` 里声明 provider，运行时经容器解析。本项目自研，采用更明确的"编译期声明 + DB 存配置"三段式。

## Decision

**编译期声明接口 + 数据库存配置（密钥加密）+ 按 Channel 启用 + 按需实例化**：

1. **声明**：每个 provider 包 `export default ModuleProvider({ identifier, label, capabilities, service, optionsSchema })`，`optionsSchema` 是 Zod（密钥字段名、必填性、格式）。启动时 `ProviderRegistry` 收集全部声明，但不实例化、不触网。
2. **配置存 DB**：`payment_provider_config` 等表存 `options_encrypted`（AES-256-GCM），主密钥来自 `config/secrets.json`（0600，不进镜像）。后台填入时加密，读取时打码（`mchid: 19****88`），永不回显明文。
3. **按 Channel 启用**：`payment_provider_channel` 关联表（§4.3）声明"该渠道启用哪些 provider + 顺序"，店面 `listEnabledProviders(channelId)` 据此渲染。
4. **按需实例化**：仅当某次操作真正要用到 provider 时 `load(identifier, decryptedOptions)`，构造函数不做网络请求。
5. **为什么不用环境变量存密钥**：铁律 9"必填配置为 0"——环境变量要求用户在安装前就填密钥，违背零配置；DB 存配置允许"先装起来，商户号后填"（PRD M06 原话：无商户不阻塞上线）。

## Consequences

正面：
- 密钥与程序分离（DB + secrets.json），程序替换不动密钥。
- 按 Channel 隔离启用，天然支持"国内 Channel 用微信/支付宝、海外 Channel 用 Stripe/PayPal"（§12 R10）。
- 新增 provider 不改核心，只加一个 `packages/providers/*` 包 + 一条后台配置。

负面：
- 密钥加密主密钥一旦丢失，所有已存密钥不可解密（需把 `secrets.json` 纳入 §9.5 的备份）。
- 比环境变量多一层"后台配置 + 加密 + 打码回显"，Admin API 多几个端点。
- DB 存配置需保证 `options_encrypted` 列不进日志（§11 日志脱敏）。

## Alternatives

1. **纯环境变量**：运维最熟，但违反"必填配置 = 0"（安装前就要填密钥），且多 provider 多 Channel 的密钥会污染 env。否决。
2. **插件包内写死默认 + env 覆盖**：不能按 Channel 动态启用，且密钥在代码/镜像里流转不安全。否决。
3. **独立配置服务（etcd/consul）**：能力最强但引入重基础设施，违背一键安装零配置。否决。
