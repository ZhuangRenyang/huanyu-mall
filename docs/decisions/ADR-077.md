# ADR-077：不删仓库，按 CRMEB 的信息架构原地重建后台

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-014（简单优先）、ADR-076（维护）、`docs/02-architecture/crmeb-alignment.md`

## 背景

要求是「把系统删掉重建，用现在的骨架和语言，直接模仿 CRMEB，
框架要 TS 最新版且能兼容 LangChain，最好把 CRMEB 下载下来对着抄」。

CRMEB 已下载到 `D:/CRMEB-reference`（v8.0 / c0be948 / 5.1 MB，只取后台路由与设置页），
菜单清点 138 项，四块（装修 14、应用 3、设置 52、维护 20）的构成已写进对照文档。

## 决策

### 1. 不删仓库

删掉重建**不会更快**，只会更慢：

- 现有的 76 份 ADR 解决的是「钱怎么算、库存怎么释放、售后怎么审核」这类**正确性问题**，
  删掉之后要重新踩一遍；这些不是 CRMEB 的 PHP 代码能抄过来的。
- 后端 180 个路由、315 个接口测试、55 个迁移是资产，不是包袱。
- 真正要换的是 `apps/admin` 的信息架构与页面，不是整个工程。
- 删除不可逆；仓库能靠 git 恢复，但环境变量、数据库数据、已部署配置不在 git 里。

重建按**原地替换**做：保留 `packages/core`、`packages/modules/*`、`apps/api`，
重写 `apps/admin` 的导航与页面，新增装修/应用两个模块。
为防万一，已打标签 `archive/pre-crmeb-rebuild`（指向删除请求前的最后一个提交）。

### 2. 只抄信息架构，不抄源码

CRMEB 是 PHP（ThinkPHP）+ Vue2 + uni-app，本仓是 TS + Fastify + React，
「对着抄代码」跨语言没有意义。抄的是：

- 菜单分组与层级（138 项的完整清单见对照文档）；
- 页面字段、状态流转、空态/错误文案；
- 「设 置 / 装修 / 应用 / 维护」四块的边界划分。

许可：根 LICENSE 是 Apache-2.0，但源文件头声明「不是自由软件、不能去掉版权」。
**不复制源码**，只参考结构，规避许可与语言双重问题。

### 3. 技术栈不换

现状：TypeScript 5.9、Node ≥26、Fastify 5.12.8、Next.js 16.4.5、React 19.3.1。

- 「TS 最新版」已经满足，不存在「换成最新 TS 框架」这件事；
- LangChain.js 是库，不是 web 框架，挂在 Fastify/Next 上都能跑；
  接入方式是新增 `packages/ai`，交易链路不依赖它；
- 为「新」而换框架（Nest/Hono）意味着重写 180 个路由与 315 个测试，收益为零。

### 4. 重建顺序

A 后台 IA（导航八组 + 设置拆页 + 应用页）→ B 装修 v1（首页模块编排）→
C 应用接入清单 → D `packages/ai`（LangChain）→ E 店面移动端。

每阶段独立提交、独立验收；不合并成一次大爆炸。

## 后果

- `docs/02-architecture/crmeb-alignment.md`：138 项菜单清点、映射表、阶段与验收
- 标签 `archive/pre-crmeb-rebuild` 作为回滚点
- 不做：分销/拼团/砍价/秒杀/积分/直播/多商户/线下收银/电子发票/余额充值/代码生成/插件市场/在线升级

## 遗留

- 装修 v1 只做「首页模块开关与顺序」，不做 CRMEB 那种自由拖拽的页面设计器
- 应用页先做只读接入清单，不做插件安装
- 若后续确需物理删除：先备份数据库、导出环境变量、确认标签可回滚，再执行
