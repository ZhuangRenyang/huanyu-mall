# ADR-074：工作台加「库存预警」，并能一键落到筛好的库存页

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-030（工作台）、ADR-039（低库存筛选与等货人数）

## 背景

工作台首页回答四个问题：今天卖了多少、有多少单要发、有多少退款要审、最近谁下了单。

缺了第五个：**有多少规格快没货了**。这件事在淘宝卖家中心首页是有独立一格的 ——
它不像退款那么急，但拖一天就是少卖一天；而库存页虽然有「只看低库存」筛选，
商家得先想到去点开它，工作台不给提示，等于这条信息不存在。

## 决策

### 1. 计数按 inventory_item 去重，不数库存行

库存页是「仓 × SKU」的行视图，同一规格在几个仓就有几行。
工作台要回答的是「几个规格要补货」，所以 `countLowStockItems(threshold)` 用
`count(distinct inventory_item_id)`：

- 2 个仓各 3 件 → 报 **1** 个预警（不是 2）
- 判定沿用库存页那一条：`available_quantity <= threshold`（已预留的货卖不了，
  按在库量算会漏掉「看起来有货、其实卖光了」的规格）

### 2. 默认阈值 5，与库存页输入框一致

`LOW_STOCK_ALERT_THRESHOLD = 5` 导出自 inventory 模块，接口把它随响应一起下发
（`pending.low_stock_threshold`），前端文案「可用量 ≤N 件」直接用返回值。

不写死在前端：卖手机和卖家具的「低库存」不是一个数（ADR-039），
将来做成店铺设置时只需要换这一个来源。

### 3. 含已售罄

对商家来说「没货」和「快没货」都是要补货。分开统计会让商家点两次、看两处，
而且淘宝的库存预警也把零库存算在里面。

### 4. 卡片直接深链到筛好的库存页

`/inventory?low=1&threshold=5`，库存页读取 query 预置「只看低库存」与阈值，
落地就是筛好的视图，不用商家再点一次。

工作台只说「有 3 个规格要补」，不列具体是哪几个 —— 列表在库存页，
工作台重复一遍列表只会让首屏变长。

## 后果

- inventory：`countLowStockItems(threshold)`（仓储 + 服务 + 契约）、
  导出 `LOW_STOCK_ALERT_THRESHOLD`
- API：`GET /admin/dashboard` 的 `pending` 加 `low_stock` / `low_stock_threshold`
- 后台：工作台第五张卡（0 件时灰、>0 时橙）、库存页支持 `?low=1&threshold=N`
- 测试：api +2（计数透传、无预警返回 0 而不是缺字段）

## 遗留

- **阈值不可配置**：现在固定 5。要按店铺/品类配置需要一张设置表，
  与「到货提醒有效期可配置」是同一件事，等设置域统一时一起做
- **不区分「售罄」与「低库存」**：卡片只给总数。真要分开，应该在库存页出两个页签
- **多仓调拨建议**：现在只提示「该补货」，不提示「B 仓还有货可以调」。
  调拨是人工决策，自动建议容易把货调到更不好卖的地方
