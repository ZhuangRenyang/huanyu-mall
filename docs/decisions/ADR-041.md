# ADR-041：售罄状态贯穿商品列表与详情

- 日期：2026-11-12
- 状态：已采纳
- 关联：ADR-028（分类）、ADR-037（列表分页）

## 背景

商品卡只显示图、标题、价格。库存只有点进详情才知道，而且详情页还有一个更隐蔽的问题：

```ts
const soldOut = variant ? variant.stock === 0 : false;
```

`variant` 只有在**选完规格后**才有值。所以一件全部规格都卖光的商品，进详情看到的是一个可点的「加入购物车」，点了才提示「请先选择规格」；选完规格才变成「暂时缺货」。

列表侧同样失真：`GET /store/products` 明明已经把变体都取出来了（要算最低价），却没顺带算可用量。顾客在列表里看到的是原价 + 正常图，点进去才发现买不到。

对照淘宝：商品图上直接盖「已售罄」标签；详情页在规格全空时按钮就是「已售罄」且不可点。

## 决策

### 1. 可用量在列表接口算，前端不猜

`GET /store/products` 追加 `available_quantity`：对本次返回的所有变体调一次 `inventory.getAvailability({ variantIds })`（批量，两查询），按商品求和。

- 与详情页同源：详情早就在用 `getAvailability`，列表复用同一函数，不存在两套库存口径
- 用**可用量**而不是在库量：在库 100、已预留 100 的 SKU 实际卖不了，按在库量会误报有货
- 与价格同一个 `Promise.all`：两者都依赖变体列表，串行只会多一个 RTT

### 2. 商品级 = 变体之和，只有 0 才叫售罄

多规格商品「黑色有货、白色没货」不是售罄，是「部分规格缺货」——那种情况本来由规格选择器置灰表达。列表只回答一个问题：**这件商品现在还能不能买**。

### 3. 前端两处表现，一处判断

- `ProductCard`：`available === 0` → 图灰度 + 半透明遮罩 + 「已售罄」标签，价格淡化，促销角标隐藏（促销角标挂在卖不掉的商品上只会误导）
- `ProductBuyBox`：`allSoldOut`（全部变体 stock 为 0）→ 按钮「已售罄」并禁用，不要求先选规格
- `available` 为 `undefined`（旧接口 / 未取到）时按有货处理：宁可少标，不可把正常商品误标售罄

### 4. 不做的事

- 不做「到货通知」：需要订阅表 + 补货时群发，属独立功能
- 不做「售罄商品自动下沉排序」：淘宝默认也不改排序，顾客会以为商品消失了
- 不在列表上显示「仅剩 N 件」：那是详情页规格级的提示，列表页每个商品都标数字会变成噪音

## 后果

- 列表接口多一次批量库存查询（两查询），与价格查询并发，不增加串行延迟
- mock 数据按同一口径（变体 stock 求和）计算 `available`，演示与线上一致
- 测试：`store-availability.spec.ts` 两条契约（有货时有数值、全部无货时为 0）

## 遗留

详情页 `product.variants[].stock` 来自详情的 `available_quantity`，与列表口径一致；但购物车的 `maxQuantity` 用的是加入时的库存快照，结账时由服务端重新校验——这部分不在本 ADR 范围。
