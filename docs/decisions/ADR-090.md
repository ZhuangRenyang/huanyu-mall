# ADR-090：换货——售后的第三种类型，全程不打款

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-051（仅退款/退货退款）、ADR-023（不做自动退款）、ADR-075（取消释放库存）

## 背景

售后此前只有两种类型：仅退款、退货退款（ADR-051）。顾客想「换一件」——
尺码不对、质量瑕疵——只能退了重买，或直接接受。这是淘宝/CRMEB 都有的第三种
售后类型，我们缺了它。

## 决策

### 1. 换货 = resolution `exchange`，与退款共用一套单据

换货仍是 `refund_request`，只是 `resolution = exchange`，状态流转：

```
pending → awaiting_return → returned → exchange_sending → completed
```

- `awaiting_return` 与 `returned` 两段和退货退款**完全共用**（同意给退货地址、
  买家填退货单号寄回）——买家面对的「寄回」动作没有第二种写法。
- 分叉点在「商家确认收到货」：退货退款在这里**打款**，换货在这里**什么都不做**，
  只推进到 `exchange_sending`（待发出换货）。

### 2. 换货全程没有资金动作（铁律）

- `agreeExchangeRequest` / `confirmExchangeReturn` / `shipExchange` 三个服务方法
  都不碰 payment；
- 服务层 `confirmReturnReceived`（打款关卡）加了 `resolution !== return_refund` 守卫，
  换货即使被误调也**打不出钱**；
- 后台 `approve` / `receive-return` 两条打款路由也在状态校验后加 `exchange` 拦截，
  双保险：路由层挡在前，服务层兜底在后。

### 3. 换出商品走同一套库存预留，租约键用申请单 id

同意换货时，若换出商品已售罄，商家同意后无货可发。所以 `approveExchange`（API 层）
先调 `inventory.allocateAndReserve({ orderId: 申请单 id, items })` 把换出商品占住，
成功后再推进单据；失败则整单报错。

发出换货时 `shipExchange` 先落单据、后 `commitReservation` 把货真正扣掉；
拒绝/撤销时 `releaseExchangeReservation` 还回预留。

租约键用申请单 id（`rfr_...`）而不是订单 id：换货的预留和原订单自己的预留互不干扰。

### 4. 第一版只支持「换同款同规格」

顾客端换货选项与退货退款同组出现（都要求已发货），目标规格取订单第一个行项的
变体，即「换一件同款同规格」。理由：

- 这是换货最常见场景（质量瑕疵换一件），不需要变体选择器；
- 跨规格换（尺码/颜色）涉及「不同规格不同价」的差价处理，差价收款是另一条资金
  链路，不能顺手加进去。

API 层已按「同一商品任一规格」校验（`listVariantsByIds` + 目标规格 product_id
必须命中订单行项），将来做跨规格换时前端加个选择器即可，协议不变。

## 后果

- order：迁移 `0010_exchange.sql`、模型/DTO/仓储/服务、`confirmReturnReceived` 打款守卫
- API：`/admin/refund-requests/:id/{agree-exchange,receive-exchange,ship-exchange}`；
  `apps/api/src/lib/exchange.ts`（预留/发货/释放）；店面申请支持 `exchange`
- SDK：`agreeExchange / receiveExchange / shipExchange`；`requestOrderRefund` 带换货字段
- 后台：退款管理新增「待发换货」页签、行内「同意换货/确认收货/发出换货」、
  换货三段式对话框
- 店面：订单详情换货选项（同款同规格），文案「换货不退钱」
- 测试：api +3（申请换货、全链路状态机、换货走打款关卡被拒）；api 335、order 34、
  storefront 46、迁移 61

## 遗留

- **跨规格换货**：需要变体选择器 + 差价处理（目标价高于原价要补收，低于要补退）。
  补收/补退都是资金动作，单独立项
- **换货也应有进度邮件**：现复用「同意退货」邮件，未区分「换货」字样；
  notification 的 `refund_update` 模板可加 `exchange_agreed / exchange_shipped` 两档
- **换出商品库存预留失败的重试**：同意换货失败已回滚预留，但 commit 失败（发货后）
  目前靠人工重发；如需自动要接入任务队列
