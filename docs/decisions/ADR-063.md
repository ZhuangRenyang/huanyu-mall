# ADR-063：浏览足迹

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-048（收藏）、ADR-054（我的评价）

## 背景

挑东西会反复回看同一件：比价、看参数、等发工资。没有足迹，顾客只能靠浏览器历史记录找，
那里面混着新闻和别的网站，等于让他自己在大海捞针。

淘宝「我的淘宝 → 我的足迹」就是干这个的。我们缺，且缺得很明显 ——
商品页看完就没了，除非当时点了收藏。

## 决策

### 1. 存在本机（localStorage），不上服务端

浏览是**最高频**的写操作：每开一个商品页一次。放服务端等于给每次点击加一次写库，
而它几乎不影响成交 —— 收益远小于代价。游客也没有身份，服务端要记就得先造匿名 id，
那是另一套需要清理与授权的东西。

代价是跨设备不同步。所以界面必须**写明「只记录在这台设备上」**，
不能让顾客以为换了手机还能看到（那比没有这个功能更糟）。

### 2. 纯函数 + 可注入存储

- `mergeRecent(list, next, limit)`：纯函数，只做「去重 → 置顶 → 截断」；
- `recordView` / `listRecent` / `clearRecent`：读写端口可注入，测试用内存实现。

分离的理由：去重与截断是**唯一会出错的地方**（同一件刷满列表、上限失效），
把它做成纯函数就能直接测，不必装一个假 localStorage。

### 3. 同一商品只留一条，重复查看顶到最前

反复回看是常态。留多条会让列表变成同一件商品的复读机，别的东西被挤出去。

上限 30 条：再多没人翻，还会把 localStorage 撑大。

### 4. 脏数据一律当「没有足迹」

localStorage 是用户可改的，不能当可信来源：

- 解析失败 → `[]`（不能让一块坏 JSON 白屏账户页）；
- 不是数组 → `[]`；
- 逐条校验关键字段（productId / handle / title / priceMinor / viewedAt），
  缺字段的旧数据丢掉，好的那条保留。

### 5. 存储失败不影响浏览

隐私模式 / 配额满时 `localStorage.setItem` 会抛 `QuotaExceededError`。
读写全部包 try/catch：**「记不住看过什么」绝不能变成「商品页打不开」**。

### 6. 展示价取最低变体价

与购买区默认选中的那档一致。取最高价会让足迹里的价格比顾客实际看到的贵，
点进去发现不一致就是不信任。（真正的成交价仍由服务端算，这里只是列表展示。）

### 7. 位置：账户页「我的收藏」之后

两者都是「我看过 / 我想要」，中间隔别的会把它们拆散。没有足迹时**整块不渲染** ——
空区块比没有区块更碍眼。

## 后果

- 新增 `apps/storefront/lib/recently-viewed.ts`（纯函数 + 存储端口 + 容错）
- 新增 `TrackView`（只写不渲染的客户端组件）挂在商品详情页根部；
  商品页是服务端组件，localStorage 只能在客户端读，所以单独抽出来
- 新增 `MyFootprints`（账户页），带「清空足迹」
- 测试：storefront +8（去重置顶、上限截断、读写回环、清空、坏 JSON、
  非数组、缺字段过滤、写入抛错不传染）

## 遗留

- **登录后同步到服务端**：需要 customer_id + 一张浏览表 + 写入频率控制（去抖/采样），
  且要考虑「游客期间本机足迹并入账号」的合并策略，工作量是现在的数倍
- **「最近看过」横条**：商品页底部可以放一条（淘宝有），先看足迹这块的接受度
- **失效商品在足迹里**：目前不判下架/售罄，点进去由商品页自己处理。
  真要标，需要在列表接口带 `available`（商品列表已带，可复用）
