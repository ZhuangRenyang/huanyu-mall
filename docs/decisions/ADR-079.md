# ADR-079：装修第一版——首页模块的顺序与开关

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-077（原地重建）、ADR-078（全功能对齐）、ADR-076（维护）

## 背景

Phase A 把「装修」从设置里拆出来，但装修页只有主题外观（颜色/字体/Logo/公告）。
CRMEB 的装修真正值钱的是**首页由商家编排**：显示哪些区块、按什么顺序。
没有这一条，「装修」就只是换皮肤。

## 决策

### 1. 先做三个真实模块，不做自由画布

首页现有可编排的模块：商品分类、优惠券条、当季主推（商品流）。
搜索固定在最前 —— 它是顾客最常用的动作，不该被排到第二屏。

不做拖拽画布：页面设计器是独立产品级能力（组件库、属性面板、预览、回滚），
三个模块用上移/下移已经能表达顺序。先跑通「后台改 → 店面变」的闭环。

### 2. 存 `theme.metadata.home_modules`，不开新表

装修是店铺级单行配置，三个布尔 + 顺序，为它建表 + 迁移 + 仓储不划算。
`metadata` 已经是 JSONB 且随主题一起读写。

**写入必须是合并而不是覆盖**：装修页只提交 `home_modules`，
若整体覆盖 metadata，会把其它键悄悄抹掉。PATCH 路由里做浅合并。

### 3. 归一化只在服务端做一次

`normalizeHomeModules(metadata)` 是纯函数（theme 模块导出）：

- 未知 id 丢弃（老版本存过已下线的模块，不能让首页崩）；
- 重复 id 只认第一个；
- 新版本新增的模块补在末尾并默认开启（老配置升级后不会少一块）。

接口在 bootstrap 里下发归一化结果，店面**不复制**一套默认顺序与容错逻辑。

### 4. 店面按配置渲染，空模块不留空档

关掉的模块整段不出现；分类为空、没有可领的券时同样整段跳过。
优惠券只显示未领取的：首页是「发现」，卡包才是「我的」。

## 后果

- theme：`home-modules.ts`（类型、默认值、归一并移动）、模块入口导出
- API：PATCH `/admin/settings` 的 metadata 改浅合并；bootstrap 下发 `theme.home_modules`
- 店面：`getStoreProfile().homeModules`；首页按顺序渲染分类/券条/商品流
- 后台：装修页新增「首页模块」编辑器（上移/下移/显示开关/保存）
- 测试：api +4（默认、顺序与开关、未知与重复、移动越界）

## 遗留（装修的后续）

- 轮播图 / 公告图：需要图片位与跳转链接，属独立的「素材 + 链接」模型
- 微页面与页面链接：CRMEB 的另一半装修能力，需要页面实体与路由
- 自由拖拽编辑器：等模块类型超过 6 个再评估，现在做会先做一套用不上的抽象
