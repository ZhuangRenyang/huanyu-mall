# ADR-042：商品评价（评价列表 + 后台管理）

- 日期：2026-11-12
- 状态：已采纳
- 关联：ADR-002（模块化）、ADR-030（工作台）、ADR-041（售罄）

## 背景

商品详情页只有图、价格、描述。顾客看不到任何「别人怎么说」——淘宝详情页的第二屏就是评价，转化几乎全靠它。后台也没有评价管理：差评骂人、广告刷屏、发货慢的抱怨，商家没有地方处理。

评价不是一个「展示组件」，它是一条有归属、有前置条件的业务数据：

- 只能评价**自己买过**的商品（否则任何人都能刷一星）
- 只能评价**已经收货**的订单（没收到货就评价，评的是物流不是商品）
- 同一订单的同一商品**只能评一次**（否则评分可以被单个人刷）

## 决策

### 1. 新建 `review` 模块，不做成 product 的附属表

评价挂商品，但它的前置条件是订单。放进 product 模块会让 product 反向依赖 order（模块图里 product 在 order 下面，违反分层）。新建模块 `M-review`：

- 表 `product_review`，一个迁移
- 模块图不新增依赖边：订单数据通过 **端口** `ReviewOrderPort` 注入，
  适配器在组合根（`apps/api/src/deps.ts`）里实现，延迟 `resolve("order")`
- 商品名与顾客名做**建单快照**：商品改名、顾客注销后，评价仍然是「当时评的哪件、谁评的」

### 2. 展示名脱敏在服务层做，不在前端做

`张**` / `t***` 由 `maskName()` 生成后落库。放前端做等于把全名发给浏览器——查看源码就能看到。后台看到的也是脱敏名；需要真实身份时从订单（收货人）查。

### 3. 「已收货」的判定用 fulfilled 起，不等 completed

`REVIEWABLE_STATUSES = fulfilled / delivered / completed`。只认 `completed` 会让绝大多数真实订单永远评不了——系统里没有「自动完成」的定时任务，没人会手动点完成。淘宝也是确认收货即可评价。

### 4. 一单一商品一条，用「服务层查重 + 部分唯一索引」双保险

`UNIQUE(order_id, product_id, customer_id) WHERE deleted_at IS NULL`。并发下两个请求同时通过查重，第二条会被索引挡住（500 而不是脏数据）；正常情况下服务层先返回可读的错误（「已经评价过了」）。

### 5. 前台入口放在「我的订单」，不放商品页

淘宝也是「已买到的宝贝 → 评价」。在商品页放「写评价」按钮，等于给没买过的人一个入口，最后还得在服务端拒一次。订单详情里每个商品行右侧显示「评价」/「已评价」，与退款入口同一位置逻辑。

### 6. 后台位置：交易 → 评价管理

评价是**交易完成后的产物**，不是商品资料。放商品域会让商家在「编辑商品」时看到评价，误以为能改。菜单紧跟「退款管理」——两者都是售后处理。

后台只做两件事：隐藏（辱骂/广告/无关）、解释（差评给个说法）。**不做改评分、不做代顾客写评价**：能改分的话，评分就不再代表顾客的真实感受。

### 7. 商品页评价区的位置与空态

排序：详情 → 评价 → 规格参数（淘宝同序）。没有评价时不隐藏整块，明确写「还没有评价。买过的顾客确认收货后可以在这里评价」——空白区块会让人以为页面坏了，也让商家不知道去哪引导。

评分摘要给四样：平均分（一位小数）、总条数、星级分布条、每条评价的星级与日期。`average` 无评价时为 `null` 而不是 `0`——`0.0` 分是「很差」，`暂无` 才是事实。

### 8. 不做的事

- **图片/视频评价**：要文件上传 + 内容审核，先把「有没有评价」补上
- **追加评价 / 追评**：需要评价树结构，V1 用不上
- **评价提醒（站内信/邮件）**：通知模块有模板机制，但「收货后几天提醒评价」是运营节奏，属营销而非交易
- **有用/无用投票**：数据量小时没有意义

## 后果

- 新增模块 `@mall/review`（1 表、1 迁移），`check:module-graph` 的 LAYERS 增加 `review: 3`
- `migration-sources.ts` 的 MODULES 增加 `review`（漏了会让迁移静默不执行——已有测试守着这条）
- 订单详情接口追加 `reviewed_product_ids`；订单行项追加 `product_id`（评价按它提交）
- 店面前台：商品页评价区、订单详情「评价」按钮与弹窗
- 后台：交易 → 评价管理（列表 / 隐藏 / 解释）
- 测试：review 模块 13 条（提交条件、去重、摘要、隐藏、解释、脱敏），api 9 条契约（匿名可读、401、201、重复 400、未收货 400、隐藏后不可见、解释可写可清）

## 遗留

- 评价影响商品列表/详情的排序与筛选（「按评分排」）未做：先有数据再谈排序
- 商家回复暂不通知顾客：需要站内信或邮件模板，属通知域独立工作
