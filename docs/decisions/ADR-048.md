# ADR-048：商品收藏（详情页收藏 + 账户页收藏夹）

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-026（地址簿）、ADR-042（评价）

## 背景

顾客看完商品想「先记着」，系统里没有任何入口。淘宝的「收藏宝贝」（商品详情页一颗星 + 账户页收藏夹）是最基础的留存动作：它不产生订单，但决定顾客第二次回来时能不能找回那件商品。

单店商城的收藏比平台简单得多：没有「店铺收藏」，只有商品收藏；不需要「收藏夹分组」，只有一条时间倒序列表。

## 决策

### 1. 收藏记在 customer 模块，不新建模块

收藏是「顾客 → 商品」的一条关系，归属者是顾客；商品只是被引用的 id。

- 表 `customer_favorite (customer_id, product_id, created_at)`，唯一索引 `(customer_id, product_id)`
- **不建跨模块外键**（商品在 product 模块的表里）——与 `promotion.voucher_collection` 同口径
- **取消收藏直接删行**，不做软删：收藏没有审计价值，软删只会让「反复收藏同一商品」堆死行，还得在每次查询里过滤

### 2. 收藏与取消都是幂等的

`insertFavorite` 用 `onConflictDoNothing`，`removeFavorite` 直接 `DELETE`：

- 顾客连点两下不该看到红字
- 网络重试不该产生 500（唯一索引冲突）

前端按钮在请求期间禁用，但幂等要由服务端保证，不能只靠前端防连点。

### 3. 收藏前校验商品存在且上架

`POST` 时先 `listProducts({ ids: [productId], status: "published" })`，不存在 → 404。

理由：收藏一个已下架/已删除的 id，会在收藏页留一行空白（商品取不到）；而且顾客点收藏时商品就在页面上，能收藏却取不到说明状态已经变了，报错比静默写入更诚实。

### 4. 三个接口，各管一件事

| 接口 | 用途 |
|---|---|
| `GET /store/customer/favorites` | 账户页列表：商品卡片 + 总数（分页） |
| `GET /store/customer/favorites/ids` | 详情页判断「已收藏」：只回 id，不分页 |
| `POST` / `DELETE /store/customer/favorites/:productId` | 收藏 / 取消，均 204 |

「ids」单独开一个接口而不是复用列表：详情页只需要知道「这件收藏过没有」，拉一页卡片数据纯属浪费。

### 5. 收藏列表的卡片与商品列表同源

把商品列表的价格/可用量/主图映射抽成 `mapStoreProductSummaries()`，收藏列表复用它。

复制一份的后果很具体：商品列表跟着改价、改库存标记，收藏页停在旧口径——「列表 99、收藏 129」这种 bug 排查起来要翻两处代码。

顺序按收藏时间（`customer_favorite.created_at`）而不是商品创建时间：顾客记得的是「我什么时候收藏的」。

### 6. 店面两个入口

- **商品详情页**：加购按钮右侧「收藏 / 已收藏」（`aria-pressed`）。未登录点击跳账户页——不做「先记本地、登录后补收藏」，那种半接状态最容易出现「收藏了却没进收藏夹」
- **账户页**：加购卡片网格，空态引导「商品详情页点收藏」

下架商品不进收藏列表（服务端只返回 `published`），但收藏记录保留：重新上架后自动回来。

### 7. 不做的事

- 收藏数（`favorited_count`）与「热度排序」：需要商品级聚合与另一个排序维度，等有真实流量再谈
- 收藏夹分组 / 备注：平台需求，单店是过度设计
- 「收藏降价提醒」：需要价格快照与定时比对，属通知域的独立工程

## 后果

- customer 模块：迁移 `0004_favorites.sql`、模型、仓储三个方法、服务四个方法
- product 模块：`ProductQuery.ids`（`inArray`，空数组返回空而不是全量）
- API：`store/favorites.ts` 四个端点；商品列表映射抽成共享函数
- 店面：`lib/favorites.ts`、`ProductFavoriteButton`、账户页 `MyFavorites`
- SDK：`listMyFavorites` / `listMyFavoriteIds` / `addFavorite` / `removeFavorite`
- 测试：customer 4 条（去重、幂等取消、顾客不存在报错、按顾客隔离）、api 5 条（401、收藏+ids+列表、取消、404、空集合）

## 遗留

- 列表页/首页的卡片上没有收藏按钮：每张卡一个「是否已收藏」查询会退化成 N+1，需要先批量取 ids（已有接口）再分发，属下一版
- 收藏总数没有上限：单顾客收藏到几千条时列表会变慢，需要按需加限流或归档
