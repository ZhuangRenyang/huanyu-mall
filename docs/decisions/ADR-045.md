# ADR-045：店铺资料（名称 / 客服电话）

- 日期：2026-11-12
- 状态：已采纳
- 关联：ADR-044（发货单缺店名）、ADR-030（工作台）

## 背景

店名写死在两个地方：`header.tsx` 与 `footer.tsx` 各一个「全球商城」。发货单（ADR-044）需要店名与客服电话，一个都取不到。

设置页里有「外观」「支付方式」「通知」「税务」「顾客账号」「系统」「账号安全」七个分组，唯独没有「这家店叫什么、怎么联系」。而 `UpdateSettingsRequest` 里有一个 `site_name` 字段——从来没有任何代码读写它（设置路由是全放开的 `z.record`，写进去也不会落库）。

三个问题叠在一起：**店名写死、字段幽灵、写入口不校验**。

## 决策

### 1. 店名与客服电话放进 `theme_settings`

不是新开一张单行表：`theme_settings` 本来就是「店铺外观与身份」的单例配置。再开一张 `store_profile` 会让「店铺信息」分散在两处，读的时候要 join 两次单行表。

迁移 `0002_store_profile.sql` 加两列：

- `store_name text NOT NULL DEFAULT '全球商城'`（有默认值，老数据不会变空名）
- `support_phone text`（可空 —— 没有客服电话的店不该被迫填一个假号码）

### 2. 设为「店铺」分组，排在外观之前

设置页新增第一个 tab「店铺」。理由：先定「我是谁」，再定「长什么样」。淘宝的店铺管理也是这个顺序（店铺信息在前、装修在后）。

### 3. 店名是一处数据，三处渲染

- 店面：`getStoreProfile()` 读 `/store/bootstrap` 的 `theme.store_name`，由布局传进页头与页脚
- 后台：发货单页眉印店名，页脚印客服电话（为空则退回「客服联系：本店铺在线客服」，不印空行）
- 读不到时退回默认名「全球商城」，不让店名读取失败把整页打成 500

### 4. 顺手收紧写入口：`z.record` → 显式 schema + `.strict()`

`PATCH /admin/settings` 原来接受任意键。这意味着：

- 拼错的键（`store_nmae`）返回 200，商家以为存上了
- `site_name` 这类从未实现的字段可以一路写到「成功」，实际在 `updateSettings` 的合并里被丢掉

现在显式声明主题变量 + 店铺资料 + metadata，并 `.strict()`：未知键直接 400。设置是低频高影响的写入口，宁可在提交时报错，也不要静默丢弃。

`support_phone` 的空串在 schema 里 `transform` 成 `null`：`""` 与 `null` 两种空值混着存，读的时候要判两次、渲染时要判两次。

### 5. 删掉幽灵字段 `site_name`

SDK 的 `UpdateSettingsRequest` / `Settings` 里各有一个 `site_name`，全仓库无任何写入方。用 `store_name` 取代并注明原因——留着它，下一个人会以为它是可用的。

## 后果

- theme 模块：迁移 0002、模型两列、DTO 与默认值、仓储映射
- API：`PATCH /admin/settings` 显式 schema + strict；`GET /store/bootstrap` 的 theme 自动带出两个新字段
- 店面：`getStoreProfile()`、布局传参、页头页脚改为可变店名（客服电话为空不显示）
- 后台：设置 → 店铺（名称 / 客服电话）；发货单页眉与页脚使用店铺资料
- SDK：`UpdateSettingsRequest` / `Settings` 用 `store_name` / `support_phone` 取代 `site_name`
- 测试：`store-profile.spec.ts` 5 条（默认值、保存读回、bootstrap 带出、空店名 400、拼错键 400）

## 遗留

- logo 上传仍在「外观」里，且店头没有渲染 logo：`logo_file_id` 有字段、有上传入口，但店面从未使用。补它需要文件 URL 解析与页头布局调整，属独立改动
- 店铺简介 / 地址未做：发货单与页脚目前用不到
