# ADR-006: Monorepo 与构建 = pnpm workspace + Turbo + 编译链（TypeScript 版本）

## Status: Accepted (2026-11-08)

## Background

铁律 11 要求依赖集中管理并锁定版本（lockfile + 统一版本目录）。候选：pnpm workspace + turbo、Nx、裸 workspace。此外编译链（TypeScript 版本）必须定案——实测 latest=7.0.2 为原生编译器世代，存在生态兼容风险。

## Decision

1. **Monorepo 工具**：`pnpm workspace` + **Turborepo 2.11.10**（仅做任务编排、缓存、并行，不接管构建）。包边界见 ARCHITECTURE.md §8。
2. **统一版本目录**：pnpm `catalog:`（`pnpm-workspace.yaml`）集中声明所有第三方单一版本，各包 `package.json` 写 `"drizzle-orm": "catalog:"`；升级只改 catalog。
3. **lockfile 入库 + `--frozen-lockfile`**：CI 与 install.sh 一律 `pnpm install --frozen-lockfile`，依赖漂移即失败。
4. **engines 钉死**：`engines.node: "26.x"`、`packageManager: pnpm@12.18.0`。
5. **TypeScript**：**首选 7.0.2，但以 POC 为前提**——若 `drizzle-kit`/`vitest`/`ts-node` 任一在 TS 7 下无法工作，**回退 5.9.x** 并在此 ADR 补记回退版本与原因（这就是 ARCHITECTURE.md §0 TS 行所引"ADR-006 补记"的含义）。

## Consequences

正面：
- 依赖单点管理，升级一处生效；lockfile 保证"任何机器装出来的依赖一致"（正面回应 PM 坑 3 的 lockfile 诉求）。
- Turbo 缓存让 CI 增量构建快，适合单人 + AI 高频迭代。
- 版本锚点（§0）有机器实现，不靠人记。

负面：
- TS 7 若回退 5.9.x，需在 catalog 里改一处并重跑门禁（成本低，但需记 ADR 补记）。
- pnpm 12 + Turbo 2 的组合相对新，冷门插件兼容性需留意（catalog 锁死可缓解）。

## Alternatives

1. **Nx**：能力最全（依赖图、affected、缓存、生成器），但对单人项目过重，配置心智高。否决。
2. **裸 pnpm workspace（无 turbo）**：够用但无缓存与并行编排，CI 与本地重复构建慢。否决（turbo 成本极低，收益明确）。
3. **npm workspaces**：无 catalog 能力、hoisting 语义与 lockfile 管理弱于 pnpm。否决。
