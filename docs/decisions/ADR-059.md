# ADR-059：到货提醒（售罄 → 登记 → 补货发邮件）

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-041（售罄展示）、ADR-016（通知 outbox + 派发器）、ADR-013（库存）

## 背景

ADR-041 把「已售罄」标得清清楚楚，但也仅此而已：按钮禁用、页面没有别的出路，
顾客唯一能做的就是关掉。这些人是**已经走到商品页的高意图访客**，丢掉最可惜。

淘宝在售罄商品上给「到货提醒」：留个邮箱，补货时发一封。这是转化链条上最便宜的一环。

## 决策

### 1. 提醒属于 product 模块，不是 customer

提醒是「变体 × 人」的关系，主体是商品（商品/变体失效，提醒跟着失效）。
放 product 侧只需存 `email` + `customer_id` 两个标量，**不新增模块依赖边**。

### 2. 游客可登记

售罄页大部分访客没有账号。要求先注册才能提醒，等于把提醒本身关掉。
登录顾客不用填（用账号邮箱），游客必须填。

### 3. 有货就拒绝登记

商品明明能直接买，却让顾客等一封「已到货」——这是耍人。
接口先查 `inventory.getAvailability`，`available > 0` 直接 400「该规格现在有货」。

### 4. 幂等：唯一键 (variant_id, email)

重复点「到货提醒」是常态，不是错误。唯一索引 + `onConflictDoNothing`，冲突时返回已有记录。
邮箱统一小写去空白：`Buyer@Example.com` 与 `buyer@example.com` 是同一个人。

### 5. 补货事件走领域事件，不新增模块依赖

- `inventory` 增加可选发射端口 `inventory-events`（与 `payment-events` 同一套），
  **只在增量 > 0 且可用量 > 0** 时发 `inventory.restocked { variantIds, availableQuantity }`；
- `workflows` 订阅它 → 查待通知 → 逐人 `enqueueStockAlert` → 最后标记已通知。

事件在库存调整**之后**发、且异常被吞：货已经进仓，邮件发不出去是通知的问题，
不该把补货回滚掉。

### 6. 先入队、再标记

反序（先标记再入队）会让邮件丢在「已标记但没发」的空档里，而且再也不会重发。

### 7. 通知去重键含「该次登记的创建时间」

`stock:${alertId}:${createdAt}`：

- 同一次登记被重复派发 → 键相同 → `insertIfAbsent` 挡住；
- 通知过一次后顾客**重新登记**（重新登记会把 `notified_at` 清空、`created_at` 刷新）
  → 键不同 → 下一次补货还能再收到，而不是被第一次的键永久挡掉。

### 8. 邮件不写价格、不做深链

补货后价格可能调过，写死旧价顾客点进去发现不一致就是不信任；
商品页要 locale/channel 才拼得对，硬拼一个错链接比不给更糟 ——
按钮指向店铺首页，与既有订单邮件同一做法。

### 9. 演示模式不假装发信

mock 模式下接口返回「已登记」并**明确写「不会真的发送邮件」**，
而不是让演示用户以为邮箱里会来信。

## 后果

- product：迁移 `0003_stock_alert.sql`、`stock_alert` 表、`DrizzleStockAlertRepository`、
  `subscribeStockAlert` / `listPendingStockAlerts` / `markStockAlertsNotified` / `countPendingStockAlerts`
- inventory：`variantIdsByItemId`（库存项 → 变体）、可选 `inventory-events` 发射端口、
  `adjustLevel*` 增量 > 0 时发 `inventory.restocked`
- notification：迁移 `0002_stock_alert.sql`（`stock_alert_enabled` 默认开）、
  `renderStockAlert` 模板、`enqueueStockAlert`
- workflows：`handleRestocked` + `inventory.restocked` 订阅（异常不外抛）
- API：`POST /store/stock-alerts`（游客必填邮箱 / 登录用账号邮箱 / 有货 400 / 幂等 201）
- 店面：`StockAlertForm`（售罄时挂在购买区下方，登录顾客预填账号邮箱）
- 测试：api +5（游客登记、缺邮箱 400、登录用账号邮箱、有货 400、幂等）、
  workflows +3（逐人入队并最后标记 / 可用量为 0 不发 / 无人登记不动作）

## 遗留

- **后台看不到需求热度**：`countPendingStockAlerts` 已实现，但库存页的行只有 `sku` 没有
  `variant_id`，要在路由层做一次 sku → 变体映射才敢展示，本轮未接
- **通知失败不重试**：`enqueue` 之后派发器负责 SMTP 重试；若 `enqueue` 本身失败，
  该条不标记，**下一次补货才会带上**（不做定时补偿，与「不做无人值守状态变更」同一原则）
- **提醒有效期**：现在登记永久有效。淘宝是 N 天失效，否则三个月后一封「到货了」会很突兀
