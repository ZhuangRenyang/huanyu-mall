# ADR-024 顾客账号真实化与「我的订单」

- 日期：2026-11-12
- 状态：Accepted
- 范围：auth 模块（令牌声明）、order 模块（按顾客查询）、customer 模块（地址簿接口）、
  storefront（account / orders）、API 店面路由
- 关联：ADR-023（退款审核）、ADR-018（结账国家）

## 背景

后台（商品、订单、退款、运费、支付）已经闭环，但**顾客侧还停在演示态**：

| 位置 | 改造前 |
|---|---|
| `apps/storefront/lib/account.ts` | 纯 `sessionStorage` mock，演示账号 `demo@example.com` / `demo1234`，关浏览器即掉 |
| 后端 `store/auth` | 注册 / 登录 / 刷新 / 登出四端点齐全，**前端从未调用** |
| `GET /store/orders` | 不存在，只有按单号查单条 |
| 下单写入的 `customer_id` | **从不写入**（`CartCompleteInput` 没有这个字段） |
| 地址簿 | 只有后台接口，店面是本地数组 |

后果：顾客登录了也看不到自己的历史订单；换个设备账号就没了。这不只是体验问题 ——
「我的订单」是售后、退款进度、复购的入口，缺了它顾客侧永远闭不上环。

## 决策

### 1. token 里带 customerId，不再拿 identity id 当顾客 id

`AuthContext.sub` 一直是 **identity id**，而 `order.customer_id` 是顾客 id，两者不同。
改造前的归属校验是：

```ts
if (order.customer_id && req.auth && req.auth.sub !== order.customer_id) throw forbidden
```

两处错：
- `sub !== customer_id` 永远成立 → 已登录顾客查自己的订单会被判越权；
- `req.auth` 在店面路由上**从未被填充**（没有挂 `customerAuth`），整段条件被跳过 →
  有归属的订单，任何人只要知道单号就能看到地址与手机号。

现在：
- 登录令牌增加 `customer_id` 声明，`AuthContext` 增加 `customerId`；
- 店面订单 / 地址 / 顾客资料 / 结账路由统一挂 `auth.customerAuth`（无 token 也放行，由 handler 决定是否 401）；
- 归属一律比 `customerId`。

### 2. 下单写入顾客归属

`CartCompleteInput` 增加 `customerId`，结账路由从 **token** 取（不是 body）：

```ts
customerId: req.auth?.customerId ?? null
```

从 body 取等于「客户端传谁就是谁」，归属形同虚设。

### 3. 我的订单：只认 token，不接受 query 传顾客 id

`GET /store/orders`：
- 未登录 401（**不是空列表** —— 空列表会让顾客以为订单丢了）；
- `OrderQuery.customerId` 由路由从 token 填；
- 列表要显示商品，`OrderDTO` 不含行项：新增 `listOrderSummaries` 一次批量取回当前页行项，
  按订单分组后套用与详情同一个 `mapOrder`（不做 N+1，也不另写一份映射）。

### 4. 游客单仍可按单号查

`customer_id` 为空的订单（未登录下单）保留匿名按单号查询：
顾客需要一个无需注册的查单入口，且订单号是 ULID 不可枚举。
一旦订单有归属，就必须登录且本人。

### 5. 前端登录态持久化

- token 存 `localStorage`（跨标签、关浏览器仍在），`sessionStorage` 只留给 mock 演示；
- `lib/api.ts` 的店面客户端注入 `accessToken` 与 `onRefresh`：401 自动换一次 token 再重试；
- 打开页面先读缓存资料渲染，再用 `restoreSession()` 向 `/store/customer/me` 校正；
- 登录 / 注册后 `syncStoreToken()`：否则会出现「登录成功但下单仍是无身份请求」。

## 后果

- 顾客注册 / 登录走真接口；演示账号只在 mock 模式生效。
- 订单列表在 live 下按登录态分叉：已登录看全部订单，未登录显示「登录后查看全部订单」+ 游客查单。
- 店面订单状态补齐：`refund_pending`（退款中）、`refunded`、`canceled`（已关闭）、
  `shipped`（待收货）、`delivered`（已完成）。改造前「只要付过款一律 paid」，
  已发货、已退款在店面全显示「待发货」。
- 退款不再显示为「支付失败」——顾客看到的是「已退款」。
- 新增接口 6 个：我的订单、当前顾客资料、地址簿 4 个。
- 迁移 0 个：`order.customer_id`、`customer_address` 表本来就有，缺的是写入与读取口径。

## 补充：后台补「客户管理」（2026-11-12）

用户指出：**注册登录是前台的事，后台应该是「客户管理」查看客户信息**。
核查确认后台当时没有任何客户入口 —— 接口 `GET /admin/customers` 与 SDK 方法都存在，
只缺页面，属于和运费、退款同类的「后端有、前端没接」。

按淘宝「客户运营 → 客户列表」/ Shopify「Customers」落地：

- 一级菜单 `客户 → 客户列表`（不与订单合并：客户资料、地址、消费是独立维度）。
- 列表：客户（姓名/邮箱）、联系方式、**订单数**、**累计消费**、最近下单、搜索（邮箱或姓名）。
- 详情（右侧抽屉）：基本信息 + 三项统计 + 地址簿 + 最近 10 条订单。
- 统计口径：只算**已付款且未退款**（paid / partially_fulfilled / fulfilled / delivered / completed）。
  把已取消、退款中、已退款算进消费额，商家会高估客户价值。
- 统计实现：`order.summarizeByCustomerIds` 一次 GROUP BY，不做 N+1；
  新增迁移 `0006_customer_index`（`order(customer_id, created_at DESC)`），
  否则客户列表和店面「我的订单」都是全表扫描。

**后台不提供代客注册、代客改密**：注册登录是顾客自己的动作，只在前台。
