# ADR-081：装修的链接选择器（先有取值协议，再谈微页面）

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-079（首页模块）、ADR-080（轮播）

## 背景

轮播的链接此前是自由文本：商家手打 `/zh-CN/cn/products/tee`，前缀错一个字符就是 404，
而且他根本不知道前缀规则。微页面、首页模块的跳转也都会遇到同一个问题。

先定「链接从哪来」，再做微页面，才能避免三处各写一套取值逻辑。

## 决策

### 1. 服务端给路径，不给 id

`GET /admin/settings/link-targets?type=product|category&q=` 返回：

```
{ items: [{ id, label, href }] }
```

`href` 已经是**带 locale 与 channel 前缀**的站内路径（`/zh-CN/cn/products/tee`），
商家点一下即填入。前端不拼前缀 —— 前缀规则属于渠道模型，只有一个地方该知道。

取启用中的第一个渠道作为默认；多渠道上线时这里要变成「选择渠道后给路径」。

### 2. 只支持商品与分类两种目标

微页面本身还没有实体，页面类链接现在给了就是死链。等微页面上线再加 `type=page`，
同一接口扩展，不改协议。

### 3. 仍然保留手填输入框

选择器覆盖 90% 场景，外链（https）与特殊活动页仍需手填。
手填内容依然过 `normalizeLink` 白名单（ADR-080），选择器不是唯一入口，
但也不是绕过校验的入口。

## 后果

- API：`/admin/settings/link-targets`（settings 权限）
- SDK：`listLinkTargets`
- 后台：装修 → 首页轮播的添加表单里加「类型 + 搜索 + 结果点选」，点选后回填链接
- 测试：api +2（商品路径带前缀、分类路径带 category 参数）
- 无迁移

## 遗留

- 分页与更精确的搜索：现在最多 10 条，够装修用；商品过万后要改成真正的搜索接口
- 渠道选择：多渠道路径前缀不同，届时接口要带上渠道参数
- 页面类链接：等微页面实体落地后追加 `type=page`
