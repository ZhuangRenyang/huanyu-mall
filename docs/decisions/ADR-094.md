# ADR-094：积分抵扣——结账接入 + 下单扣分 + 补偿退回

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-093（积分发放）、ADR-012（促销计算）、ADR-075（取消释放库存）

## 背景

ADR-093 做完了「发放 + 账本」，但积分只能攒不能花——没有抵扣，积分对顾客
没有意义。本 ADR 把「下单时用积分抵现金」接进结账主链路。

这是**资金链路**：抵扣金额进订单应付，下单成功才扣分，取消/退款要退回。
任何一步算错都是「少收钱」或「多扣积分」。

## 决策

### 1. 购物车只存「想用多少点」，金额永远后端算

`cart.points_to_use` 存点数（意愿），`PUT /store/carts/:id/points` 设置。
抵扣金额在 `computeDiscounts` 里由服务端折算 + 封顶（铁律 13），
前端与客户端永不传金额——与券码、礼品卡同一纪律。

### 2. 抵扣规则复用 ADR-093 的常量

`pointDiscountMinor(points, payableMinor)`：1 点 = 1 minor，封顶到剩余应付的
`POINT_MAX_DISCOUNT_RATIO_BPS = 50%`。实际用掉点数 = 抵扣额（同值）。

抵扣顺序：行级折扣 → 订单促销 → voucher → gift card → **points**（最后）。
积分抵扣拿到的「剩余应付」已经是前面所有折扣扣完的余额。

### 3. 下单成功才扣分，失败退回（与 gift_card 同构）

`cart-complete` workflow 新增 `consumePointsStep`：

- invoke 调 `consumePointsForOrder`（原子减余额 + 写 `spend` 流水），
  余额不足抛错 → 引擎补偿前面已成功的步骤，整单回滚；
- compensate 调 `releasePointsForOrder`（加回余额 + 写 `refund` 流水）。

折扣留痕 `type="points"` 进 `order_discount`，`pointsUsed` 从留痕提取
（1 点 = 1 minor，`amountMinor` 即点数），下单侧不用另传。

### 4. feature 开关 `points` 同时管发放与抵扣

一个开关管整条积分链路：关着时既不发、也不抵，避免「发了不能花」或
「能花没发」的半开状态。

## 后果

- cart：迁移 `0005_points.sql`（`points_to_use`）、模型/DTO、`setPointsToUse`、
  `PromotionLookupPort` 加 points 字段、`discountMinor` 计入 points
- promotion：`ComputeDiscountsInput.pointsToUse`、`ComputeDiscountsResult.pointsAppliedMinor/pointsUsed`、
  `consumePointsForOrder` / `releasePointsForOrder`、computeDiscounts 加 points 抵扣
- workflows：`consumePointsStep`（invoke 扣分 / compensate 退回）、`pointsUsedFromDiscounts`
- order：`OrderDiscountType` 加 `points`
- API：`PUT /store/carts/:id/points`；SDK `setPointsToUse`
- 测试：promotion +2（抵扣折算封顶、扣分退回）；promotion 66、cart 30、
  workflows 24、api 343、storefront 46；迁移 65

## 遗留

- **退款/取消退回积分**：当前 workflow 补偿已覆盖「下单后步骤失败」；但用户主动
  退款（走退款审核）后积分是否退回，属售后链路，需与退款 workflow 挂钩，单独一刀
- **前端选积分 UI**：`setPointsToUse` 已就位，但店面结账页还没做「用积分」的输入框
- **积分过期**：见 ADR-093 遗留
