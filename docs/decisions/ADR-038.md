# ADR-038 我的订单分页：订单多的顾客不能只看到最近 20 单

- 日期：2026-11-12
- 状态：Accepted
- 范围：storefront（`orders-view.tsx`）
- 关联：ADR-036（同一次「我的订单」改造，页签之后漏了分页）、ADR-037（商品列表同款）

## 背景

ADR-036 给「我的订单」加了状态页签，但仍是一次拉 20 条、没有分页。

对顾客的后果：**买过 21 单以上，第 21 单起就永远看不到**。
「查看历史订单」这件事直接失效，而他不知道是系统的问题。

这已经是同一类问题的第四次（后台订单、顾客订单页签、商品列表、这里）。
根因一致：前端固定 `limit`、后端支持 offset 但前端不传。

## 决策

### 1. 一页 20 单，页码控件在列表底部

只做「上一页 / 下一页 + 当前页」，不做页码跳转条：
顾客几乎不会跳到第 7 页，翻两页找不到就直接用「按单号查询」了。

### 2. 换页签回到第一页

在第 3 页点「待发货」而待发货只有 5 单，会看到空列表。
把 `setPage(1)` 放在页签点击里（不是用 effect 监听 filter）——
用 effect 会先按「新页签 + 旧页码」发一次请求，再按第 1 页发第二次，白跑一趟。

### 3. mock 模式同样分页

演示环境的订单条数少，但分页逻辑若只写在 live 分支，
以后改 mock 数据就会暴露「演示是一回事、线上另一回事」。

## 后果

- 顾客能翻到全部历史订单；页签与分页可以组合（待收货第 2 页）。
- 每次翻页一次请求，20 条/页。

## 不做

- **不做无限滚动**：订单页需要「回到第 N 页」的稳定位置，页码比滚动位置可靠。
- **不做每页条数切换**：顾客不需要。
- **不做「加载更多」按钮**：与分页控件二选一，选了页码就不叠另一种。
