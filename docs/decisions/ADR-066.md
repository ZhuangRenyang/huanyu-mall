# ADR-066：券适用范围下发店面

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-064（券适用范围）、ADR-029（店铺券）

## 背景

ADR-064 让「指定商品券」真正只对命中范围生效，但**顾客领券前不知道范围是什么**：
券条只写「限指定商品」，顾客不知道是「限 3 件商品」还是「限整个服饰类」，
更不知道是不是自己想要的商品。

领了一张用不上的券，比不发券更糟 —— 顾客会在结算页被拒绝，然后觉得被耍了。

## 决策

### 1. 范围随券一起下发，只给「数量」不给「名称」

`listPublicVouchers` 与 `listCollectedVouchers` 返回的每张券多一个
`scopes: [{ scope_type, scope_id }]`，promotion 模块自己查范围表（不引入其他模块依赖）。

店面只把它换算成一句「限 N 件商品 / 限 N 个分类」。

**为什么不展开商品/分类名**：promotion 模块不认识商品名，展开名称要么加跨模块依赖，
要么把 storefront 拉商品目录再 join —— 两种都比「一句话提示」贵，
而「限 2 件商品」已经足够让顾客判断这券跟自己有没有关系。

### 2. 两张券列表都带，不只在公开券

顾客领完券，进「我的卡券」同样要看到范围。否则领之前不知道、领之后也不知道，
只有结算失败那一刻才知道 —— 那是最坏的时刻。

### 3. 无范围时字段省略，老客户端不受影响

`scopes?` 可选。整单券 / 运费券不带，老客户端拿不到这个字段照常渲染。
前端只在 `type === 'specific_product'` 且有值时拼文案。

## 后果

- promotion：`PublicVoucherDTO.scopes?` / `CollectedVoucherDTO.scopes?`，
  `listPublicVouchers` / `listCollectedVouchers` 批量附范围（`listScopesByVoucherIds`，禁 N+1）
- 店面：券条与「我的卡券」显示「限 N 件商品、N 个分类」
- 测试：promotion +1（公开券与我的卡券都带出范围）
- 无 API / SDK / 迁移改动（店面促销路由直接透传 DTO）

## 遗留

- **商品页「本商品可用券」**：要判断「当前商品是否命中某张券的范围」，
  需要 storefront 把商品 id 连同分类传给券列表，promotion 侧再做覆盖判断。
  这是下一步的转化优化，比「一句话提示」更直接，但要动公开接口契约
- **展开范围名称**：等需要精确展示（如「仅限：耳机、键盘」）时再引入
  商品名 join 或让 promotion 存范围时的名称快照
