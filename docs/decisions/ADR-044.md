# ADR-044：后台发货单打印

- 日期：2026-11-12
- 状态：已采纳
- 关联：ADR-031（订单列表）、ADR-033（物流单号）

## 背景

商家在后台点「发货」，填承运商与运单号。包裹里要放一张纸：订单号、收货人、商品与数量、备注——这是仓库与顾客都能核对的东西。淘宝的「打印发货单」、Shopify 的 packing slip 都是这个。

系统里没有：订单详情只能看不能打，商家要么手抄，要么截图打印（会印出侧边栏和按钮）。

## 决策

### 1. 独立路由，不套后台外壳

`/orders/:id/packing-slip` 挂在 `RequireAuth` 之下、`Shell` 之外。套着侧边栏打印会印出一列菜单，「打印」这件事就白做了。

从订单详情的「打印发货单」以 `target="_blank"` 打开：商家看完这一单可以留在详情继续处理下一单，打印窗口自己关掉。

### 2. A4 尺寸、含金额

- 内容宽度 `210mm`（A4），`@media print` 下去掉页面留白与操作条
- **含单价与小计**：淘宝的发货单模板就是带金额的，装箱单（packing slip）才隐藏价格。这张纸的用途是核对，顾客也常拿它对照实付
- 收货人 / 地址来自订单快照：改地址不会改变历史订单上印的内容

### 3. 操作条打印时隐藏

顶部「返回 / 打印」用 `print:hidden`。打印按钮直接 `window.print()`，不跳浏览器的打印预览弹窗之外的任何中间页——多一层「确认打印」只会让商家多点一次。

### 4. 不放店铺名，因为系统里还没有这个设置

发货单通常印店名与客服电话。当前设置里没有「店铺名称」字段（`settings` 只有支付/通知/税务/账号这些），硬编码一个店名会变成第二个「写死微信支付」。

所以这一版只印「发货单 + 订单号 + 收货信息 + 商品 + 金额 + 备注」。**这是已知缺口，不是设计选择**：补「店铺名称」需要设置域加字段与编辑界面，属独立改动。

## 后果

- 新增 `apps/admin/src/pages/packing-slip.tsx`，路由在 `RequireAuth` 内、`Shell` 外
- 订单详情状态行右侧加「打印发货单」入口（新窗口）
- 无后端改动：`getOrder` 已返回发货单所需全部字段

## 遗留

- 店铺名称 / 客服联系方式：设置域未提供，补上后发货单页眉应显示它们
- 批量打印（一次打多单）：需要「选中订单 → 合并为一个打印任务」的批量选择，这一版只有单张
- 快递面单（承运商模板）：属对接快递公司 API，与发货单是两件事
