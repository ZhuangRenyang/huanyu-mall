# ADR-062：购物车失效宝贝分组

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-041（售罄展示）、ADR-013（库存）、ADR-059（到货提醒）

## 背景

购物车里的行只存商品快照（标题/单价/数量）。商品被下架、变体售罄之后，
那一行**看起来和正常商品一模一样**：图、名、价、数量选择器都在，
「去结算」也是可点的。

顾客点下去才失败，而那时购物车已经关了 —— 他不知道是哪一件出了问题，
只能一件件猜。这不是「边界情况」，是每天都会发生的库存变化。

淘宝的做法是固定的：购物车底部单独一栏「失效宝贝」，标灰、不能结算、
提供「清空失效宝贝」。

## 决策

### 1. 状态由服务端判，前端只负责分组

`GET /store/carts/:id` 每行多两个字段：

| 字段 | 值 |
|---|---|
| `availability_status` | `ok` / `insufficient` / `out_of_stock` / `delisted` |
| `available_quantity` | 该变体当前可用量（不含已预留） |

判定顺序（**先下架、后库存**）：

1. 不在「仍可购买变体」里 → `delisted`
2. 可用量 `<= 0` → `out_of_stock`
3. 可用量 `< 行数量` → `insufficient`
4. 其余 → `ok`

顺序不能反：商品下架但仓库还有货时，可用量是正数，只看库存会判成正常。

### 2. 「仍可购买」要 join 商品状态，不能只看库存

新增 `product.purchasableVariantIds(ids)`：一条 `product_variant ⟕ product` 的
inner join，要求变体未删、商品未删、`product.status = 'active'`。

这是 ADR-062 的关键一步：库存表不知道商品是否下架，只看库存永远判不出「已下架」。

### 3. 两次批量查询，不做 N+1

一车 20 行只多两次查询：`inventory.getAvailability({ variantIds })` 与
`product.purchasableVariantIds(variantIds)`，各自一条 SQL。

### 4. `insufficient` 不算失效

商品还在，只是数量超过库存。归到失效组会让人以为买不了，
实际只要把数量改小 —— 所以它留在正常区，行内提示「仅剩 N 件」，
数量选择器的 `max` 收到可用量（`max` 仅在 `available > 0` 时设，
否则会出现「值 1、上限 0」的矛盾态）。

### 5. 金额一律不自己算（铁律 13）

小计仍用服务端返回的 `totals`，前端**不做「扣掉失效商品后重算」**：
那会是第二套金额逻辑，和结算时服务端算的必然对不上。
有失效商品时只加一行说明「小计含 N 件失效宝贝，移出后自动重算」，
并禁用「去结算」。

### 6. 移出走既有单行删除接口，不开批量端点

「移出失效宝贝」= 对每个失效行调用 `DELETE /carts/:id/line-items/:lineId`。
批量端点会绕过每行的归属校验（那是花钱的东西），收益不值得。

### 7. 抽屉不重复做这套逻辑

购物车抽屉的「去结算」本来就跳购物车页，所以只在购物车页拦截。
抽屉继续按普通行渲染（失效行仍可删），不引入第二处判定。

## 后果

- product：仓储 `listPurchasableVariantIds`（join 商品状态）、服务 `purchasableVariantIds`
- API：`carts.ts` 新增 `mapCartWithAvailability`，7 个返回购物车的端点统一走它
- SDK：`CartLineItem.availability_status?` / `available_quantity?`
- UI：`CartLineItemProps.availabilityStatus?` / `availableQuantity?`（M18 组件不破坏既有调用方）
- 店面：`applyLiveCart` 映射两个字段并据此设 `maxQuantity`；
  购物车页分成「有效」与「失效宝贝」两组，失效组标灰、可一键移出、禁用结算
- 测试：api +5（ok / 售罄 / 下架 / 库存不足 / 刚好够买边界）

## 遗留

- **结算页也拦一层**：目前只在购物车页拦。若顾客在购物车页停留很久再点结算，
  库存可能在这期间变化 —— 服务端预留会拒绝，但提示是结算页的通用错误。
  真要做需要结算页把每行的可用量也拉一次，成本比收益高，暂不做
- **「到货提醒」联动**：失效宝贝旁边可以直接放「到货通知我」（ADR-059 已有接口），
  这是很自然的一步，但会引出「提醒哪一件/哪几件」的选择问题，单独设计
- **降价提醒**：淘宝会在失效/收藏商品降价时提示，需要价格历史表，另议
