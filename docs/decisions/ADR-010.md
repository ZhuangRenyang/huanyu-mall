# ADR-010: 图标库锁定 lucide-react（一套 SVG 描边，覆盖管理后台与前台商城）

## Status: Accepted (2026-11-08)

## Background

团队 P0 规则：禁止 emoji 作为功能图标；Spec 必须锁定一套 SVG 图标库，全项目统一不混用。需要一套同时覆盖管理后台（商品/订单/客户/设置）与前台商城（购物车/搜索/支付/物流/账户）的图标库。

候选（均实测版本）：lucide-react 1.70.0、@heroicons/react 2.2.0（Vercel Commerce 默认）、@radix-ui/react-icons、@tabler/icons-react。

## Decision

锁定 **lucide-react 1.70.0**，全项目唯一图标来源。

理由：
1. **shadcn/ui 的默认图标库**就是 lucide（简报第十节已锁 shadcn/ui），零额外心智成本，组件示例代码开箱即用。
2. **纯 SVG 描边**（stroke），风格统一、可无限放大、可被 CSS 变量控制 `stroke-width`/`currentColor`，天然适配设计变量（M17）。
3. **图标覆盖全**：约 1600+ 图标，同时覆盖电商（`shopping-cart`/`credit-card`/`truck`/`package`/`store`/`badge-percent`/`search`/`user`/`filter`）与管理后台（`settings`/`users`/`boxes`/`clipboard-list`/`shield`）。
4. **按需 tree-shaking**：`import { ShoppingCart } from "lucide-react"`，只打包用到的图标。

## Consequences

正面：
- 一套图标两个端共用，杜绝混用与风格分裂。
- 与 shadcn/ui 零摩擦，AI 生成组件时不会"顺手"引入第二套图标。
- 描边风格可用 CSS 变量调粗细/颜色，满足换肤地基。

负面：
- lucide 是轮廓线风格，若品牌需要实心/圆角填充风格需换库（一期设计语言已定为简洁描边，无此诉求）。
- 1.x 版本的 API 与 0.x 基本一致，但团队需按锁定版本写，避免引用不存在的图标名（门禁脚本 `scan-icons.ts` 校验 import 的图标名在 lucide 清单内）。

## Alternatives

1. **@heroicons/react（Heroicons 2.2.0）**：Vercel Commerce 用它，但它是 Tailwind 官方出品、分 outline/solid 两套，图标数量远少于 lucide，且引入即与 lucide 混用（shadcn 默认 lucide）。否决。
2. **@radix-ui/react-icons**：15×15 网格、风格极简，但图标数量少（约 300），覆盖不了电商完整场景，且偏"控制类"图标。否决。
3. **@tabler/icons-react**：图标量大，但风格更"插画感"、默认 stroke-width 2 偏粗，与简洁留白的店面调性不搭。否决。
