# ADR-020 运费配置的位置：设置页的发货区，不是商品详情的包邮开关

- 日期：2026-11-11
- 状态：**已修订（被 ADR-021 取代）**
- 修订说明：本文把「发货区 + 运费方式」当成全店唯一配置，因而把入口放进系统设置、
  并断言"商品详情不放运费"。实际模型里它是**可复数的运费模板**，商品上架时选模板 ——
  归属与入口均以 ADR-021 为准。本文保留作决策过程记录。
- 范围：fulfillment 模块、admin 运费设置、结账可选国家
- 关联：ADR-019（国家是唯一口径）、ADR-014（简单优先）

## 背景

用户否掉了「在商品详情里让商家勾选包邮 / 自己填运费」：

> 后台可设置包邮或不包邮在商品详情里，让商家自主设置运费，还要这个功能干什么，
> 你应该多参考成熟方案，而不是独创功能。

这个判断是对的。商品级运费开关有三个绕不过去的问题：

1. **同一商品在不同国家没有唯一运费**。一件 T 恤发中国 8 元、发美国 80 元，
   商品详情上的一个数字必然对其中的一个国家是错的。
2. **和发货区打架**。系统已有「区（国家）→ 方式 → 规则」这条链路，
   再加商品级开关就是第二套口径；两套口径同时生效时，取哪个都能被解释成 bug。
3. **多商品订单无解**。购物车里有 3 件商品、2 件包邮 1 件不包，运费怎么加？
   成熟电商的答案是「不相加」——运费是订单级属性，不是商品级属性。

## 决策

### 1. 照抄成熟模型：发货区 → 运费方式

Shopify（Shipping zones / rates）、WooCommerce（Shipping zones / methods）、
Medusa（Shipping options / profiles）三家结构一致，我们采用同一套：

- **发货区（shipping_zone）**：一组国家。同一国家只能属于一个区。
- **运费方式（shipping_option）**：属于某个区，`flat`（固定价）或 `free_over`（满额包邮）。
- **规则（shipping_option_price_rule）**：满额包邮的门槛金额。

不做「按重量」（`weight_based`）：购物车从未把商品重量传进运费计算，
规则配了也永远按 0 克算——这是会静默算错钱的死功能，界面不提供。
字段与计算函数保留，等真要做时再补链路。

不做商品级「包邮」开关，理由见上。

### 2. 配置入口在「设置 → 运费」，不在商品详情

商家只配三件事：**哪些国家（区）、多少钱（方式）、满多少免运费（门槛）**。

界面刻意不出现两个实现细节：

- **渠道**：运费区按国家划分，创建方式时自动绑定当前所有启用渠道。
  若漏绑，方案在后台看得见、顾客那边「无可用运费」——这类错误不该让商家犯。
- **规则表**：门槛就是方式上的一个数字，不暴露「price_rule」概念。

每条记录独立生效，没有「保存」按钮——少一个「改了没保存」的坑。

### 3. 结账可选国家以**配送范围**为准，不以税率为准

改动前：`GET /store/checkout/countries` 直接取税务模块的国家清单。
后果是顾客能选一个没配运费的国家，填完地址、点支付，才在服务端拿到
「无可用运费方案」400——失败点被推到了最后一步。

现在：

```ts
items = taxCountries.filter((c) => deliverableCountries.has(c.code))
```

`deliverableCountries` 与结账查运费**用同一套过滤条件**
（区未删 + 方式启用 + 已绑渠道），口径一致才不会出现「能选不能买」。

没有任何区时返回 `items: []` + `shipping_configured: false`，
前台据此整屏提示「暂无可配送地区」，而不是渲染一个空下拉。
接口失败（网络/500）仍退回最小清单——这两种「空」不是一回事。

### 4. 唯一性守卫在服务端

「同一国家只能属于一个区」在 `FulfillmentService.assertCountriesFree` 里校验，
不在界面上拦：界面置灰只是体验，接口才是防线。

## 后果

- 商家改运费不再需要进数据库。之前三张表只有读路径，没有任何写接口。
- 结账可选国家会**变少**：只保留真正能配送的国家。这是有意的收紧。
- 已有数据（真机上 e2e 造的区）无需迁移，表结构不变，只是多了写入口。
- 新增后台接口 7 个（区 3 + 方式 3 + 总览 1），全部 `settings` 权限 + 审计。

## 验证

- 模块单测 9 条：国家大写去重、跨区冲突、非法国家码、删区保护、
  门槛必填且 > 0、门槛能被结账算出、类型切换后旧门槛失效、可下单国家随启停变化。
- 接口测试 7 条：未登录 401、总览结构、建区+建方式可读回、重复国家 409、
  缺门槛 400、非空区删除 409、国家码格式 400。
