# ADR-034 订单详情的支付渠道与配送方式：别再写死「微信支付」

- 日期：2026-11-12
- 状态：Accepted
- 范围：API（`store/orders/{id}`、订单 mapper）、storefront（`toOrderRecord`）
- 关联：ADR-033（同一次「顾客看到的信息要真实」的延续，遗留项就是这里）

## 背景

ADR-033 修物流时顺手发现两处顾客可见的错误信息，当时为了不让 diff 混杂没有一起改：

1. 店面订单详情的「支付方式」写死为**「微信支付」**（`recordToView`）；
2. live 模式下「配送方式」是**空字符串**（`toOrderRecord` 没拿到运费方式名）。

后果分别是：PayPal 付的订单也显示微信支付；顾客看不到自己选的是什么配送。

订单模块其实一直有这些数据：

- `OrderDetailDTO.shipping_method`（`order_shipping_method` 表：名称、承运商、金额）；
- `payment.findPaymentByOrderId(orderId)` → `provider_id`；
- `payment.listEnabledProviders(channelId)` → `identifier + label`。

缺的是**接口没把它们吐出来**，以及**前端把占位文案当成了真值**。

## 决策

### 1. 详情接口返回 `shipping_method` 与 `payment_provider`

- `shipping_method`：`{ name, carrier_name, amount_minor, currency_code } | null`；
- `payment_provider`：`{ id, label } | null`。

两者都只在**详情**接口返回。列表页不查：一页 20 单就是 20 次额外查询，
而列表只显示金额与状态，用不到它们。

### 2. `provider_id` 要换成 label

`provider_id` 是内部标识（`alipay`、`paypal`、`pp_fake`），直接展示给顾客没有意义。
用 `listEnabledProviders` 找到对应渠道的 `label`；找不到时退回 `provider_id`，
而不是编一个名字 —— 显示 `alipay` 至少是诚实的。

### 3. 前端的占位文案改成「在线支付」

`paymentMethod` 在 `OrderRecord` 上变成可选字段：

- 有 `payment_provider.label` → 用它；
- 没有（未付款 / 货到付款 / mock）→ 显示「在线支付」，不再假装知道渠道。

### 4. mapper 加字段，不改店面契约的其他部分

`mapOrder` 增加 `shipping_method` 与 `payment_provider` 两个可选输出，
后台的 `mapAdminOrder` 复用同一份映射，两边字段口径一致。

## 后果

- 顾客看到的是「我选的标准快递、我用支付宝付的」，而不是空白与写死的渠道名。
- 订单详情多两次查询（物流 + 支付），都用主键/订单 id 索引，可接受。

## 不做

- **不做支付渠道图标**：需要维护品牌素材与授权，纯视觉收益。
- **不做「修改支付方式」**：已付款订单换渠道等于退款重下，不做半个功能。
- **不做列表页的运费方式**：列表只回答「买了什么、多少钱、到哪一步」。
