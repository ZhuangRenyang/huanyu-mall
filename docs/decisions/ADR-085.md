# ADR-085：券的「领取后 N 天有效」——到期时间落在券码上

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-029（领券）、ADR-078（D 期首项）

## 背景

券只有固定区间（`starts_at` / `ends_at`）。淘宝与 CRMEB 都有「领取后 N 天有效」：
同一张券，不同顾客的截止时间不同。固定区间表达不了这件事。

## 决策

### 1. 到期时间写在哪：券码，不是券

`voucher.valid_days` 只是**规则**；真正的截止时间落在 `voucher_code.expires_at`，
领取那一刻按 `now + N 天` 写入。

理由：一张券发给一百个人，就有一百个截止时间；写在 `voucher` 上只能有一个。

### 2. 与固定区间取交集

券的展示与核销都取**更早**的那个截止时间：

- 结账：`code.expires_at` 过期即跳过（与 `voucher.ends_at` 同一轮筛选）
- 我的卡券：`ends_at = min(code.expires_at, voucher.ends_at)`

两条都用的同一个事实「什么时候不能用」，不能出现列表说有效、结账说无效。

### 3. 计算抽成纯函数

`voucherCodeExpiry(validDays, now)` 单独导出并单测：空/0/undefined 都返回 null，
避免旧数据缺少字段时算出 `Invalid Date`（第一版就是在这里踩到：`undefined > 0` 为 false，
`undefined !== null` 为 true，于是算出一个 NaN 日期）。

## 后果

- promotion：迁移 `0005_voucher_valid_days.sql`（`voucher.valid_days`、`voucher_code.expires_at`）、
  模型与 DTO、`setVoucherCodeExpiry`、`collectVoucher` 写到期、结账与卡券列表取较早值
- API：创建/更新券接受 `valid_days`（1–365，可空）
- 后台：券编辑里新增「领取后有效天数（选填）」
- SDK：`AdminVoucher.valid_days` / 请求体
- 测试：promotion +1（纯函数边界：空/0/1 天/30 天）；全量 58 通过；api 329；迁移 58

## 遗留

- 已发出的券不会追溯调整：改 valid_days 只影响之后领取的码
- 阶梯满减仍未做（下一项）
