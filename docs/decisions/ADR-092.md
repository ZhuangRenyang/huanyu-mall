# ADR-092：券的「排除范围」——scope_mode 区分指定可用 / 指定不可用

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-064（券范围）、ADR-071（商品页可用券）、ADR-086（阶梯满减）

## 背景

券的 `specific_product` 只有「白名单」：指定哪些商品/分类可用。商家要发
「除清仓外全场通用」的券，只能把其余每个商品都点一遍——商品一多就做不到，
或者干脆放弃。

淘宝/CRMEB 的优惠券都有「适用商品：全部 / 指定商品 / 指定商品不可用」三种。

## 决策

### 1. `voucher.scope_mode`：include（默认）/ exclude

`specific_product` 下的 `scopes` 语义由 `scope_mode` 决定：

- `include`（默认，老行为）：scopes 是白名单，命中才覆盖；
- `exclude`：scopes 是黑名单，不在列表即覆盖（空列表 = 全场）。

`scope_mode` 只对 `specific_product` 有意义；其它类型忽略。

### 2. 商品页与结账共用一个判定函数

抽纯函数 `voucherIncludesItem(type, scopeMode, scopes, productId, categoryIds)`：

- 商品页 `listPublicVouchersForProduct` 和结账 `eligibleVoucherBase` **都调它**，
  口径只有一个来源 —— 这是 ADR-071「商品页说能用、结账用不了」那类不一致的根治法；
- exclude 模式结账适用小计 = 整单小计 − 排除项小计，满减门槛按这个适用小计算。

### 3. 创建/更新仍强制 specific_product 必须有范围

exclude 也不许给空范围：空范围 = 全场，语义上等于 `entire_order`，
会让「指定商品券」这个类型名不副实。两个模式都要求至少一条 scope，
只是文案区分「可用 / 不可用」。

## 后果

- promotion：迁移 `0012_voucher_scope_mode.sql`、模型/DTO、仓储读写、
  `voucherIncludesItem` 纯函数、`eligibleVoucherBase` 与 `listPublicVouchersForProduct` 共用判定
- API：券创建/更新 schema 加 `scope_mode`；`mapVoucher` 下发
- SDK：`AdminVoucher.scope_mode`、`Create/UpdateVoucherRequest.scope_mode`
- 后台：券编辑「适用范围」加「指定商品可用 / 指定商品不可用」切换
- 测试：promotion +2（纯函数 include/exclude 边界、exclude 结账适用小计）
- **顺带修复**：`0005`/`0006` 迁移文件此前建了却漏注册进模块（ADR-085/086 的存量缺陷），
  真实数据库跑迁移时不会执行 `valid_days` / `tiers` 列；本轮一并补进 `index.ts`
- promotion 61、api 340、storefront 46；迁移 63

## 遗留

- **排除范围明细下发店面**：商品页「本商品可用券」已用统一判定，但券详情文案
  还未区分「限 N 件 / 除 N 件外」；属展示增强
- **多级范围叠加**：include 与 exclude 不能同券混用（一个 scope_mode），
  需要「指定 A 且排除 B」的复杂场景当前不支持，等有真实诉求再评估
