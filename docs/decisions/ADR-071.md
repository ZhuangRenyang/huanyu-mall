# ADR-071：商品页领券区只摆「本商品可用」的券

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-029（领券）、ADR-064（券适用范围）、ADR-066（范围下发）

## 背景

ADR-064 给券加了适用范围，ADR-066 把范围下发到了店面；但商品页的领券区还是
**全店公开券直接铺开** —— 页面拿到的是 `GET /store/vouchers`，不区分这是哪件商品。

结果是顾客在 B 商品页看到「限 A 商品，减 5 元」，点领取、进了卡券包，
结账时这件商品用不了。券没坏，展示的位置错了。

淘宝的商品页领券区只摆这个商品能用的券；用不上的券根本不该出现。

## 决策

### 1. 新接口挂在商品下，不往全店券接口加参数

`GET /api/v1/store/products/:handle/vouchers`，返回结构与 `/store/vouchers` 一致
（`items` / `count` / `currency_code`）。

挂商品下的理由：判定要用到商品的**分类**（分类券要命中它挂的分类），
而 handle → 商品 → 分类的解析本来就在商品域。放到券接口上会变成
「券路由反过来查商品」，边界反了。

匿名可读（券条要能渲染），登录后每条带 `collected`，与全店券接口同一套语义。

### 2. 判定与结账同源，复用 `listPublicVouchers`

`listPublicVouchersForProduct({ productId, categoryIds, customerId })`
= `listPublicVouchers(customerId)` 再按范围过滤：

| 券类型 | 是否算「本商品可用」 |
|---|---|
| `entire_order` | 是 |
| `shipping` | 是（这个商品下单时运费能抵） |
| `specific_product` | 范围里必须有一条命中本商品或它挂的分类 |

**空范围的指定商品券一律排除** —— 结账时 `eligibleVoucherBase` 对它返回 0，
也就是用不了。这里放出来就是「能领、不能用」。

复用而不是重写：营销开关、有效期、已领张数只有一处口径，
不会再出现「券条说有、结账说没有」。

### 3. 店面按 handle 取，不再拉全店券

`getStoreVouchers(handle?)`：传了 handle 走新接口，没传仍走全店券（保留给将来的
店铺首页券区）。商品页固定传 `product.handle`。

## 后果

- promotion：`IProxyModuleService.listPublicVouchersForProduct` + 服务实现
- API：新增 `GET /store/products/:handle/vouchers`；`productRoutes` 创建 auth 辅助
- SDK：`listProductVouchers(handle)`
- 店面：`getStoreVouchers(handle)`，商品页传 handle
- 测试：promotion +2（整单/运费/命中/未命中混合、空范围券排除）、
  api +3（命中与未命中过滤、匿名可读、商品不存在 404）
- 无迁移

## 遗留

- **商品页券条的 `collected` 恒为 false**：店面是服务端渲染，拿不到顾客 token。
  要让「已领」在券条上显示，得把券条改成客户端拉取（或把 token 透传到 SSR），
  那是另一处改动
- **店铺首页券区**：现在没有首页券位；要加时用 `getStoreVouchers()` 的全店口径
- **变体级范围**：券范围只到商品与分类，没有「限某个尺码」。
  淘宝也没有，不做
