# ADR-101：分销——佣金只记账，结算靠人工，系统不发一分钱

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-078（D 期营销）、ADR-023（不做自动退款/自动打款）、ADR-100（拼团）

## 背景

D 期最后一块营销能力是分销：商家找推广员（老客、KOL、渠道）带客，
成交后按比例给佣金。CRMEB 的分销包含「佣金提现」——系统直接把钱打给推广员。

**这一步不能照抄。** ADR-023 定的是「不存在无人值守就会退钱/打款的路径」，
自动打佣金是同一类风险：金额算错、推广员刷单、重复结算，任何一个都会直接损失现金。

## 决策

### 1. 推广员是顾客，不是后台员工

`affiliate` 表以 `customer_id` 关联客户，`unique(customer_id)`：一个客户只能有一个推广码。
推广码 4–16 位大写字母数字（`uq_affiliate_code`），可指定也可自动生成。

维护入口在后台「营销 → 分销」：选客户 → 设比例 → 拿码。

### 2. 佣金 = 订单**实付** × 比例，上限 30%

基数用 `order.total_minor`（顾客实付），**不是**商品原价小计：

- 佣金永远不超过顾客付出的钱 —— 这是资金安全的硬边界；
- 用券、秒杀、积分抵扣之后商家实收变少，佣金也应当跟着变少。

比例用万分比存储（`commission_bps`，500 = 5%），DB CHECK 限制 `1–3000`。

### 3. 触发点是「订单完成」，一单一笔

`POST /store/orders/:id/confirm-receipt` 成功后计提：

- **幂等**：`unique(order_id)` + 服务层先查，重复确认收货不会重复计提；
- **自推不计**：`affiliate.customer_id === order.customer_id` 直接返回 null
  （否则推广员给自己打折）；
- **停用不计**：停用推广员的码解析不出来，已产生的佣金不受影响。

### 4. 退款作废，但已结算的不动

退款打款成功后 `cancelCommissionByOrder` 把 pending 置 `canceled`（只改状态，不动钱）。

**已结算的保持 settled**：钱可能已经打给推广员了，自动改状态只会让账更乱，
这种情况留给商家人工处理（追回或协商）。

### 5. 「结算」= 人工确认，不是转账

后台 `POST /admin/commissions/:id/settle` 只做一件事：pending → settled + 记 `settled_at`。

商家线下（微信/支付宝/银行卡）打款之后回来点它。系统**不调用任何支付接口**
—— 这是 ADR-023 的直接延伸：能自动花钱的地方一律不自动化。

### 6. 归因只传「码」，服务端查表

店面落地页带 `?ref=CODE` → 记 localStorage（30 天）→ 下单时带 `affiliate_code`。

- 不传 `affiliate_id`：内部标识由客户端传等于让任何人把订单挂到别人名下；
- 码无效/已停用/过期 → **静默按自然流量处理**，不挡住下单
  （顾客不该因为别人发了个过期码就买不了东西）；
- 归因结果落 `order.affiliate_id`，只记归属、不影响金额。

## 后果

- promotion：迁移 `0016_affiliate.sql`（两表 + 唯一索引 + CHECK）、模型
  `affiliate / affiliateCommission`、DTO、仓储 12 个方法、服务 9 个方法
- order：迁移 `0012_affiliate.sql`（`order.affiliate_id` + 索引）、模型/DTO/仓储/建单入参
- workflows：`CartCompleteInput.affiliateId` 透传到建单步骤
- API：`GET/POST /admin/affiliates`、`POST /admin/affiliates/:id/status`、
  `GET /admin/commissions`、`POST /admin/commissions/:id/settle`（settings 权限）；
  `GET /store/affiliate/me`；结账 schema 加 `affiliate_code`
- SDK：`listAffiliates / registerAffiliate / setAffiliateStatus / listCommissions /
  settleCommission`、`getMyAffiliate`
- 后台：营销组「分销」页（推广员 / 佣金两个视图 + 添加推广员对话框）
- 店面：`AffiliateCapture` 全站捕获 `?ref=`（30 天），结账自动带上
- 测试：promotion +5（注册/码唯一/计提与幂等/自推/停用/退款作废/结算状态机/汇总）、
  api +5（注册与重复注册、停用、计提与结算、自推不计、我的推广）；
  promotion 85、api 365、order 34、storefront 46；迁移 70

## 遗留

- **多级分销（二级返佣）**：涉及层级与合规上限，先不做；单级已经能覆盖主要场景
- **佣金提现申请**：现在是商家线下打款后标记；若要做「推广员申请提现」，
  申请单可以是人工审核（不打款），但涉及状态机与对账，单独立项
- **推广数据看板**：点击、转化、客单价趋势都没有，只有佣金流水
- **归因窗口**：现在 30 天固定写在代码里，应做成店铺设置
- **部分退款**：只按「订单已退款」整体作废；部分退款按比例扣减佣金需要部分退款能力先落地
