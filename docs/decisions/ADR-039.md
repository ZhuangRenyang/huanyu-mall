# ADR-039 库存预警：只看「快卖完」的 SKU，阈值由商家定

- 日期：2026-11-12
- 状态：Accepted
- 范围：inventory 模块（按可用量筛选）、API（`admin/inventory-levels`）、admin（库存页工具条 + 标红）
- 关联：ADR-013（多仓与可用量口径）、ADR-030（工作台）

## 背景

后台库存页是一张「仓 × SKU」的大表，只有「全部仓库」筛选。
商家想知道「哪些货快卖完了、该补了」，只能自己一行行扫可用量。

淘宝的库存管理有「库存预警」：低于设定值的 SKU 单独筛出来，列表里标红。
Shopify 的库存页也有 low stock 视图。

## 决策

### 1. 按可用量筛，不按在库量

预警条件用 `available_quantity ≤ 阈值`。

在库 100、已预留 100 的 SKU，实际一件也卖不了 —— 按 `stocked` 预警会漏掉它。
可用量是后端算好的（在库 − 已预留，ADR-013），前端不重算。

### 2. 阈值由界面传，不写死在代码里

卖手机和卖家具的「低库存」不是一个数（一天卖 3 台 vs 一天卖 30 件）。
API 收 `low_stock_threshold`，界面给输入框（默认 5）。

**为什么不做「按 SKU 配置阈值」**：那是按商品设安全库存，需要商品域加字段与编辑界面，
是另一个量级的投入。先用「一个店一个阈值」覆盖 90% 的场景，不够再升级。

### 3. 不过滤时也标红

即使没勾「只看低库存」，可用量 ≤ 阈值也标红 + 「偏低 / 无货」徽标。
预警的价值在于**扫一眼就能发现**，而不是必须先勾选才知道。

## 后果

- 商家勾一下「只看低库存」就能拿到补货清单；不勾时也能从整表里看出红色行。
- 多一次带条件的查询（同一个索引），没有额外成本。

## 不做

- **不做按 SKU 的安全库存配置**：需要商品域字段 + 编辑界面，单独排期。
- **不做补货提醒（邮件/站内信）**：通知模块已能发信，但「什么时候发、发给谁」需要
  商家的运营节奏，先把「看得见」做掉。
- **不做库存周转率等指标**：需要历史快照，当前没有按天的库存流水聚合。
