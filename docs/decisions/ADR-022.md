# ADR-022 补齐商品图片与订单备注：把淘宝的两块必备区补上

- 日期：2026-11-12
- 状态：Accepted
- 范围：product 模块、order 模块、admin 商品编辑与订单详情、店面商品接口
- 关联：ADR-021（布局照淘宝）、ADR-014（简单优先）

## 背景

按「功能布局也要参考淘宝」做了一次既有功能审计，发现四处该有却没有的地方：

| 缺什么 | 现状 | 淘宝对应 |
|---|---|---|
| 商品图片 | 表 `product_image` 齐全，**界面完全没有入口** | 发布页「商品图片」：主图 + 图集 |
| 商品详情 | 字段 `description` 存在，界面没接 | 发布页「详情描述」 |
| 订单商家备注 | 表里连字段都没有 | 订单详情「商家备注」 |
| 订单操作日志 | `audit_log` 有数据，没展示 | 订单详情「操作记录」 |

前两条等于「商家上架不了能卖的商品」——没有图的商品在店面是空白块。

## 决策

### 1. 商品图片：整组替换，第一张即主图

`PUT /admin/products/:id/images { file_ids: [] }`

- 服务端先软删旧图再插新图（整组替换），前端只提交最终顺序；
  用增量增删会让「拖动排序 + 删中间一张」产生顺序错乱或残留。
- **第一张自动写回 `thumbnail_file_id`**：列表页、购物车、订单都用它，
  漏写就会出现「详情有图、列表空白」。有测试守着。
- 上限 12 张，超了 400，不落库。
- 图片 URL 由后端生成（`file.getPublicUrls` 批量一次），前端不该知道 storage key 规则。

### 2. 商品详情用纯文本，不做富文本

`description` 按空行分段。富文本编辑器会带来 XSS、粘贴样式污染、图片外链失效三个问题，
而当前阶段商家真正要的是「把材质和尺寸说清楚」。等有真实排版诉求再上。

### 3. 订单备注独立字段，只进后台

`order.merchant_note text`（迁移 `0003_merchant_note`）。

- 与「顾客留言」分开：`merchant_note` 只在 `mapAdminOrder` 出现，店面接口不带；
- 空串/纯空格等于清空（服务端 trim），不是存一串空格；
- 每次修改写审计，可追。

### 4. 操作日志不直接复用 `/admin/audit-logs`

后者要 `settings` 权限（只有 admin 有），而看订单日志的是客服/运营。
新开 `GET /admin/orders/:id/logs`，用 `orders` 权限，且**强制限定 entity_type=order + entity_id=本单**，
拿不到全表查询能力。

### 5. 商品列表加状态页签，但先本地过滤

淘宝是「出售中 / 仓库中 / 已售完」三个页签。这里做「全部 / 已上架 / 草稿」，
带数量角标。当前商品一次性加载（≤100），所以本地过滤；
后端已同步支持 `?status=` 与 `?q=`，商品上量后前端改成分页即可，接口不用再动。

## 顺带修掉的两个既有 bug

1. **店面商品详情的图片 URL 是 `/uploads/${file_id}`** —— 把 file id 当 storage key 拼，
   只要真上传过图就 404。改成 `file.getPublicUrls`。
2. **店面商品列表 `thumbnail_url` 写死 null** —— 列表永远没有图。
   改成按 `thumbnail_file_id` 批量取。

这两个都不会报错，只会「看起来没图」，所以一直没人发现。

## 后果

- 商品编辑从 3 个区块变 5 个：基本信息 → 变体·定价·库存 → 运费 → 商品图片 → 商品详情（顺序照淘宝）。
- 订单详情多两块：商家备注（金额之后）、操作日志（页尾）。
- 新增迁移 1 个；新增文件上传依赖既有 `POST /admin/files`（JSON+base64，20MB 上限）。

## 验证

- api 114 条：图片整组替换返回 URL 且首张为主图、空数组清空、超 12 张 400、
  备注写入可读回、空串清空、日志只含本单。
- 全仓 42 个测试任务、48 个类型任务、25 个构建任务、34 个迁移校验全绿。
