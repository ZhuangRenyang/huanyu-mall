# ADR-032 店面首页：搜索 → 分类 → 商品流

- 日期：2026-11-12
- 状态：Accepted
- 范围：storefront 首页（`/`）、两个首页组件
- 关联：ADR-028（商品分类，分类数据与列表筛选）、ADR-022（列表页搜索）

## 背景

店面首页改造前只有一块「当季主推」：8 个最新商品。

对顾客来说这意味着：

- **想搜东西**：得先点「查看全部」进列表页，再找那个搜索框；
- **想按类目逛**：分类建了但首页没有任何入口，等于没建；
- **没有别的路**：只有「最新上架」一种浏览方式。

淘宝首页的顺序是：**搜索框 → 分类金刚区 → 推荐商品流**。Shopify 的 Dawn 主题是
hero → collection list → featured products，同样把「找」放在「逛」之前。

## 决策

### 1. 首屏第一块是搜索，不是商品

搜索是电商首页使用频率最高的动作。把它藏在二级页面，等于每天让顾客多点一次。

搜索框提交后跳 `/products?q=<关键字>`，取数逻辑完全复用列表页（服务端按 `q` 查），
不新增接口 —— 首页只负责把关键字交出去。

### 2. 第二块是分类宫格，只列一级

- 点一级分类 → `/products?category=<id>`，列表页的二级筛选栏（ADR-028）接着展开；
- **首页不铺两层**：两层宫格会变成一堵墙，而二级本来就该在「进了一级之后」出现；
- 每个分类显示商品数（上架中的数量）：让顾客知道点进去有没有东西；
- 分类为空时整块不渲染（新店还没建分类时不出现空白区）。

### 3. 第三块保留「当季主推」

它是「逛」的兜底：不搜、不选分类的顾客从最新商品进。

### 4. 页面的 h1 视觉隐藏

首屏视觉主体是搜索框，但页面仍需要一个 h1（屏幕阅读器与 SEO）。
用 `sr-only` 的「商店首页」，不为了一个看不见的标题破坏首屏构图。

## 后果

- 顾客在首页就能完成「搜」和「按类目逛」两个最常用动作，不用先进列表页。
- 分类终于有了前台入口，商家建分类的动机成立（ADR-028 的另一半）。
- 首页多一次 `getStoreCategories()` 请求，与商品列表 `Promise.all` 并发，不增加串行等待。

## 不做

- **不做轮播 banner**：需要商家上传运营图与排期管理，是一个独立的内容管理功能；
  没有它首页依然成立，有了它就要维护「图什么时候换」。
- **不做个性化推荐**（猜你喜欢）：需要行为数据与推荐策略，单店样本量撑不起来。
- **不做首页装修/拖拽搭建**：淘宝的店铺装修是平台级能力，自建店铺用不上。
