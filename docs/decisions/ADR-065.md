# ADR-065：订单列表「申请售后」入口

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-051（退货退款）、ADR-053（退货地址）、ADR-061（地址快照）

## 背景

退款/售后功能本身已经做完了（ADR-051），但**入口藏在订单详情页的最下面**：
顾客想退一件，要先点进订单 → 翻完物流时间线 → 翻完金额明细 → 才在页面底部看到「申请退款」。

淘宝订单列表每一单都有「退款/售后」按钮，就在订单卡片上。找不到的入口等于没有 ——
顾客会直接走客服，把本可以自助的事变成人工。

## 决策

### 1. 订单卡片底部加「申请售后」，只在可退状态出现

`to_ship / to_receive / completed` 三个状态才显示。`awaiting_payment / refunded / canceled`
不显示 —— 已取消、已退款的单再挂一个售后入口，点进去是死胡同。

与退款面板（ADR-051）同一份状态判断，不另写一套口径。

### 2. 点了直接展开退款表单，不再让顾客重找一遍

列表按钮跳到 `?order=xxx&refund=1`，订单详情据此把退款表单**默认展开**
（`RefundPanel` 的 `open` 初始值 = `autoOpen && refundable`）。

只做「展开表单」，不做「自动提交」：金额、原因、售后类型仍要顾客自己填，
钱的路径一点没变。

### 3. 复用既有详情页，不开新页面

申请售后不是独立页面，是订单详情的退款区块。新开一个售后页意味着
把地址、金额、状态、退货物流都再拉一遍 —— 那是重复，不是入口。

### 4. 结构上把「整卡链接」拆开

原来整张订单卡是一个 `<a>`，里面没法再放一个可点的「申请售后」。
把卡片改成 `li > (详情链接 + 操作条)`，操作条放在链接之外 —— 避免
「链接套链接」这种 HTML 嵌套交互元素的问题。

## 后果

- 店面 `orders-view.tsx`：`OrderRow` 加「申请售后」操作条（可退状态才显示）
- 店面 `order-detail.tsx`：`RefundPanel` / `OrderDetail` 接收 `autoOpen`，默认展开表单
- 店面 `orders/page.tsx`：读 `refund=1` 透传给 `OrdersView`
- 无 API / 模块 / 迁移改动（退款能力早已就绪，纯入口与交互）
- 测试：无新增（纯展示层；退款链路已被 ADR-051/061 的 api 与模块测试覆盖）

## 遗留

- **换货入口**：淘宝的售后类型有「仅退款 / 退货退款 / 换货」，我们只做了前两个。
  换货要建新状态机（换货单 + 重新发货），不属于「入口」问题，单独立项
- **列表直接展示售后进度**：现在列表仍只显示订单状态。退款中的单能在列表上
  带一个「退款中」角标会更直观，属列表字段扩展
