# ADR-033 顾客侧物流信息：商家填的单号，顾客要看得到

- 日期：2026-11-12
- 状态：Accepted
- 范围：API（`store/orders/{id}`）、storefront（订单详情）
- 关联：ADR-013（多仓发货）、ADR-023（退款审核）

## 背景

后台发货时会填快递公司与运单号（`POST /admin/orders/:id/shipments`），
但**店面的订单详情接口不返回发货单**：

- `GET /store/orders/{id}` 只回订单本体；
- 店面 `OrderView` 里虽然有 `tracking` 字段与渲染分支，但只有 mock 种子数据填过它；
- 结果：商家填了单号，顾客在「我的订单」里什么都看不到。

「我的包裹到哪了」是下单后最高频的一次查询。淘宝的订单详情第二块就是物流信息
（快递公司 + 单号 + 复制 + 查看物流），Shopify 的顾客账户订单页同样展示 tracking。

## 决策

### 1. 详情接口返回发货单，不新建「物流接口」

`GET /store/orders/{id}` 追加 `fulfillments: [{ id, status, tracking_links }]`。

不单独做 `/store/orders/:id/tracking`：订单详情本来就要这一次请求，
再拆一个接口等于让页面串两次请求、还要处理「订单到了但物流没到」的中间态。

### 2. 取第一条有单号的发货单

拆包分批发时会有多张发货单。顾客先看到**第一个包裹**的单号，
符合直觉（先发的先到），也不需要在详情页做「包裹列表」这种过度设计。

### 3. 前端只补数据链路，不动 UI

`order-detail.tsx` 已经有「配送方式」卡片 + 运单号复制按钮，
本次只把 `fulfillments → tracking` 的映射接上（`toOrderRecord`），
UI 一行没改 —— 有渲染分支但永远没数据，是这次真正的病灶。

### 4. 归属校验保持原样

详情接口沿用 `assertOrderAccess`：有 `customer_id` 的订单必须本人，
游客单按单号查。发货单不额外放宽——物流单号同样是隐私。

## 遗留（已确认，未在本轮修）

订单详情里有两处 live 数据仍是占位文案，本轮**没有**顺手改，避免混进这个功能的 diff：

- `paymentMethod` 在 storefront 里写死「微信支付」（`recordToView`）；
- `shippingOptionName` 在 live 下为空字符串（`toOrderRecord` 没拿到运费方式名）。

这两处会让顾客看到错误或不完整的信息，应单独一轮修（需要订单详情带上支付渠道与运费方式名）。
写在这里是为了不让它被「看起来已经做完」掩盖。

## 后果

- 商家填单号 → 顾客立刻能在订单详情看到快递公司与单号，可一键复制去查。
- 后端多一次 `fulfillment.listByOrder` 查询（按订单索引），可接受。

## 不做

- **不做物流轨迹（扫码签收、路由节点）**：需要对接快递 100 / 快递鸟这类第三方，
  是独立集成，不是本功能的延伸。
- **不做「查看物流」跳转**：没有轨迹数据时，跳转只会打开一个空页面；
  给单号让顾客自己去查，比给一个假按钮诚实。
- **不做发货通知的站内信**：通知模块已有邮件通道（ADR-016），
  物流通知接进模板是另一件事。
