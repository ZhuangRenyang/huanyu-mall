# ADR-083：补上支付通道列表接口（修静默退回默认值）

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-078（全功能对齐，C 期）

## 背景

后台支付设置调用 `GET /admin/settings/payment-providers`，但这条路由**从未实现**
（只有 `/:id` 的读写）。live 模式下请求 404，前端 `catch` 后返回 `DEFAULT_PROVIDERS` ——
商家看到的「已启用 / 未启用」是默认值，不是真实配置。

这类缺陷不会报错，只会让人以为配置生效了。

## 决策

1. 仓储/服务新增 `listProviderConfigs()`：返回**全部**通道（含未启用的），
   选项解密后只回掩码（`****1234`），与单条读取同一套 `maskOptions`。
2. 路由 `GET /admin/settings/payment-providers` 注册在 `/:id` 之前。
3. 未配置的通道也要出现：只列已配置的，商家会以为系统只支持一家。

## 后果

- payment：契约 + 仓储 + 服务 `listProviderConfigs`
- API：新列表路由；后台支付页不再退回默认值
- 测试：api +1（禁用通道也在、选项只回掩码）
- 无迁移

## 遗留

- 前端目前仍保留 `catch` 兜底；接口修好后它只在网络故障时生效，保留是合理的降级
