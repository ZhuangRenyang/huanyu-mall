# ADR-019 运费与税全自动：国家是唯一口径，客户端不参与金额

- 日期：2026-11-11
- 状态：Accepted
- 范围：cart 模块、结账接口、店面结账流程
- 关联：ADR-018（按国家计税）

## 背景

用户要求：**按定位或填写的收货国家自动收运费、收税，尽量简单全自动，不能有绕过方式，不能有 bug。**

动手前核实到的四处问题（前三处是**真实的绕过口**）：

1. **运费由顾客选**：`setShippingMethod(cartId, { shipping_option_id })` 接受任意方案 id，
   只校验「方案存在」，**不校验该方案是否覆盖收货国家**。
   于是可以「地址填德国、运费选中国国内方案」，少付国际运费。
2. **税的国家来自客户端**：`GET /store/carts/:id?country=XX` 与下单请求体
   `shipping_address.country` 各算一次，两者可以不理解成同一件事；
   展示与下单用不同国家，就会出现「看到 13%、实付 0%」的空间。
3. **不填地址也能下单**：`shipping_address` 整体是可选，缺国家时走**默认税率**——
   如果商家没配默认税率，就是 0 税。这是最直接的绕过。
4. 购物车**不存国家**，所以任何一处校验都只能依赖请求参数。

## 决策

### 1. 国家落在购物车上，成为金额的唯一口径

`cart.shipping_country char(2)`（迁移 `0004_shipping_country`）。

- `PUT /store/carts/:id/address { country }` 写入，归一为大写、校验 `^[A-Z]{2}$`。
- `GET /store/carts/:id` **不再接受 `?country`**：合计只读购物车上的国家。
- 下单请求体里的 `country` **只用于核对**，不参与任何计价；与购物车不一致直接 400。

### 2. 运费由服务端自动选最便宜的可用方案

`retrieveCart` 内按 `channel + shipping_country` 列出方案，逐个走
`calculateShippingPrice`（规则价，不是方案基础价），取最低价；同价按 id 排序保证稳定。

- **读时重算**，不落库：方案里有「满额免运费」，先选后改数量会让金额过期。
- 老接口 `POST /shipping-methods` 保留但**不再改变金额**，只做两项校验：
  必须有收货国家；传的方案必须在该国家的可用清单里（防跨区套用低价）。
- 没有可用方案 → `shipping_method = null`，下单时明确拒绝（`该地区暂不支持配送`），
  **不会按 0 运费放行**。

### 3. 下单的三道闸

| 检查 | 不通过时 |
|---|---|
| 购物车有收货国家 | 400「请先填写收货国家/地区」 |
| 请求体国家（若传）与购物车一致 | 400「收货国家与购物车不一致」 |
| 该国家有可用运费方案 | 400「该地区暂不支持配送」 |

订单的 `shipping_address.country` 由**购物车**写入，客户填的只是详情（姓名/电话/地址行）。

### 4. 店面：三步结账，国家自动预填

`联系方式 → 收货地址 → 支付`（原来 4 步，**去掉「配送方式」**）。

- 首次进结账按浏览器时区猜国家（`Asia/Shanghai → CN` 等），顾客只需核对；
  **不用 IP 定位**：要外部服务、要处理隐私，时区本地就有。
- 改国家 → `PUT address` → 合计（运费+税）由服务端重算后返回，前端只展示。
- 前端不再计算运费与含税合计：`shipping/tax/total` 全部取后端字段。

### 5. 顺手修掉的一个真 bug

自定义 JSON 解析器对空 body 调 `JSON.parse("")` 抛 `SyntaxError`，
被统一错误处理器兜成 **500**。于是「带 `Content-Type: application/json` 但不带 body」
的请求全部 500（本次防绕过用例就是这样暴露的）。空 body 现在按 `null` 处理。

## 后果

**收益**：顾客不用理解运费方案与税率，填完地址就看到最终价；客户端传任何参数都改不动金额；
展示价与实收价恒等（同一份服务端合计）。

**代价与取舍**：

- **顾客不能选更快的方案**：一律自动选最便宜的。要「优先时效」得在后台给方案排序/标记，
  属于真实诉求再加，不在结账页加选项（ADR-014 简单优先）。
- 地址国家仍由顾客填写，理论上可以填一个低税国家——但金额始终按**填写的国家**计算，
  不存在「不填就少收税」；真要防地址造假是风控问题，不属于本项范围。
- 国家没有运费区域时无法下单，这是有意的：能不能卖到某国先由运费区域决定。

## 真机验证（2026-11-11）

四条链路在真机全部通过：税务 50 / 多仓 71 / 促销 48 / 通知 31。

真机抓到并修掉一个**少收钱**的缺陷：购物车税额已含运费税（2678），
订单只收商品行税（2574），差 104 = 运费 800 × 13%。
`CartTotals.shipping_tax_minor` 单独留一份并传到订单（`shippingTaxMinor`），
订单税 = 行税 + 运费税；含税价时合计不变（税已含在价内），但 `tax_minor` 要报全。

## 不做

- 不做 IP 定位/地理围栏（隐私 + 外部依赖，收益只是省一次下拉）。
- 不做「按重量/时效/承运商」让顾客选（当前单商户、方案少）。
- 不做运费税目区分（运费与商品同税率，已在 ADR-018 记录）。
