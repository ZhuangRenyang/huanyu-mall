# ADR-026 收货地址簿：中文地址口径 + 结账复用

- 日期：2026-11-12
- 状态：Accepted
- 范围：customer 模块（地址模型、默认地址）、API 店面路由、storefront（账户页地址簿、结账地址步）
- 关联：ADR-024（顾客账号真实化，地址簿是它留白的一块）、ADR-019（结账按国家算运费与税）

## 背景

ADR-024 把顾客侧接上真后端时，地址簿被明确留白：

> 地址簿前端仍是本地实现（后端接口已就绪，表单字段待改造），
> 不做「半接」—— 地址能存但下单带不出来更难查。

留白的原因有两个，这次一并解决：

1. **数据存不住**：`lib/account.ts` 里是 `sessionStorage`，换设备/关浏览器就没了。
2. **字段对不上**：`customer_address` 按 Shopify 的西方地址习惯建 ——
   `first_name` + `last_name` 都必填、`city` 必填、`postal_code` 必填。
   淘宝的收货地址是四个字段：**收件人（一个）、所在地区（省市区一整串）、详细地址、手机号**，
   邮编选填、很多人根本不知道。

逼顾客在「姓」「名」「城市」「邮编」里瞎填，得到的是假数据：后台客户详情里看到
`姓=张 名=三 城市=深圳` 还算正常，但更多人会填成 `姓=张三 名=张三`、`城市=广东省深圳市南山区`。
假数据比空数据更难用 —— 发货单和客服都得靠它。

## 决策

### 1. 字段放宽，对齐中文地址口径

迁移 `customer/migrations/0003_cn_address.sql`：

```sql
ALTER TABLE customer_address ALTER COLUMN last_name   DROP NOT NULL;
ALTER TABLE customer_address ALTER COLUMN city        DROP NOT NULL;
ALTER TABLE customer_address ALTER COLUMN postal_code DROP NOT NULL;
```

- `first_name` 存**收件人全名**，`last_name` 留空；
- 「省 / 市 / 区」整串存 `province`，`city` 留空 —— 与结账页 `region → province` 的口径一致，
  不会出现「地址簿一套字段、订单另一套字段」；
- `postal_code` 选填。

只放宽约束、不删列、不改类型：后台手工建的旧地址不受影响。DTO 里这三个字段变成可空，
后台客户详情的 `mapAddress` 本来就用 `filter(Boolean)` 拼接，展示不受影响。

### 2. 默认地址唯一，且「设为默认」是独立动作

- **第一条地址自动成为默认**：淘宝 / Shopify 都是这样，否则结账页的「默认地址」永远是空的。
- **新增或编辑时勾「设为默认」** → 先清掉同客户其它地址的默认标记。
- **独立端点** `POST /store/customer/addresses/:id/default`：
  地址簿上就是一颗「设为默认地址」按钮，语义比让前端 PATCH 一个布尔值清楚，
  也挡住了「前端传 false 把唯一的默认地址清成没有默认」。
- 先清后设在**同一个事务**里（`repo.setDefaultShipping`）：两个请求并发设默认时，
  分两步做会出现两条都是默认。

### 3. 店面接真后端

`lib/account.ts` 的 `listAddresses / saveAddress / deleteAddress / setDefaultAddress`
改成 async 走接口（mock 模式保留本地实现，演示不至于空白）。
视图模型只留 5 个字段：收件人、手机号、省市区、详细地址、国家 ——
上层的地址簿和结账页都不需要知道后端那套拆法。

### 4. 结账复用已保存地址

登录顾客走到地址步，先看到已保存地址的卡片（默认地址预选），选中即回填下方表单；
手动改任一地址字段就取消选中高亮（避免「显示选的是 A，实际提交的是 B」）。
游客不请求地址簿（不制造无意义的 401），读失败也不挡结账 —— 表单照样能填。

## 后果

- 老顾客结账少填一遍，这是地址簿唯一的价值；换设备地址还在。
- 中文地址的 `city` / `postal_code` 为空：任何按 `city` 单独取值的下游都要改成
  「province 优先、city 兜底」的拼接口径，目前只有后台客户详情用到，已确认兼容。
- 地址数量没有上限（淘宝限制 20 条）：自建商城没有平台风控压力，先不做；
  真出现刷地址的顾客再加，属于可加在服务层的规则。

## 不做

- **不做地址智能识别**（粘贴一段文字自动拆省市区）：需要第三方地址库，识别错反而更难改。
- **不做国际地址结构化**（省/州、邮编分离）：当前口径对所有国家都用「省市区 + 详细地址」，
  海外顾客填州名和邮编进 province/详细地址里也能用，不为了少数场景加一层表单分支。
- **不做删除默认地址后自动指定新默认**：淘宝也不这么做，结账页在没有默认时选第一条即可，
  少一个「地址自己变了」的意外。
