# ADR-040 商品详情面包屑：把分类接回导航

- 日期：2026-11-12
- 状态：Accepted
- 范围：API（`store/products/{handle}`）、storefront（商品详情面包屑）
- 关联：ADR-028（分类）、ADR-032（首页分类入口）、ADR-037（列表分类筛选）

## 背景

商品详情的面包屑只有两层：`全部商品 > 商品名`。

分类在 ADR-028 建了、ADR-032 上了首页、ADR-037 能筛列表，但**商品页不告诉你它属于哪个分类**，
也没有回分类页的入口。淘宝是 `首页 > 服饰 > 外套 > 商品`：分类既是导航，
也是「看完这个还想看同类」的那条路。

数据其实一直有：`ProductDetailDTO.category_ids`，只是店面详情接口没返回。

## 决策

### 1. 详情接口返回 `categories`（含 id / name / parent_id）

顺带**把父级也带上**：商品通常只挂二级分类（「外套」），不补父级就只能显示一层，
面包屑变成「全部商品 > 外套 > 商品」，少了「服饰」这层归属。

### 2. 面包屑最多两级分类

优先展示二级（更具体），没有二级就展示一级。商品挂多个分类时取第一个 ——
面包屑是导航不是分类清单，多了反而碍事。

### 3. 每一级都可点，带 `?category=`

点「服饰」跳 `/products?category=<服饰 id>`，列表页的二级筛选栏（ADR-028）接着展开。
面包屑因此不只是「当前位置」，还是站内内链（对 SEO 也有意义）。

## 后果

- 顾客能从商品页跳回所属分类，继续逛同类商品。
- 详情接口多一次 `listCategories`（分类通常几十条，一次查完在内存里索引）。

## 不做

- **不做完整路径（首页 > …）**：站点的「首页」就是 `/`，加进去只多一层点击。
- **不做多分类全列**：一个商品挂 5 个分类时，面包屑会变成一行标签墙。
- **不做 schema.org BreadcrumbList 结构化数据**：SEO 增强项，等有真实流量再补。
