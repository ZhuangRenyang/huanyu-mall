# ADR-052：后台批量发货

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-013（按仓拆发货单）、ADR-044（发货单打印）

## 背景

发货只有一条路：进订单详情 → 选仓 → 填物流公司/单号 → 发货。

大促之后「待发货」里躺着 30 单，商家要逐单点开、逐单填，一单三次点击、一次页面加载。
淘宝卖家中心的做法是：在「已卖出的宝贝」里勾选多单 → 批量发货 → 统一填快递、逐单出号。

我们缺的不是「批量按钮」，是**批量时容易出事的几个判断**：哪些单能批量、跨仓怎么办、
一单失败要不要回滚。这些判断不做，批量发货就是一个放大错误的功能。

## 决策

### 1. 只有 `paid`（待发货）的订单可勾选

退款中（`refund_pending`）的单**不出现勾选框**：
货发出去、钱退回来是净亏，而这类单在列表里和其他单长得一样。
非待发货的行留空占位（不渲染禁用框），保持列对齐同时不制造噪音。

### 2. 跨仓订单不参与批量

一张发货单不跨仓（ADR-013 §3），跨仓订单要拆成多张发货单、多个单号。
批量对话框里打开时会先拉每单的**发货计划**，`plans.length > 1` 的行直接标「跨仓」并禁止填单号，
提示「请单独进入订单详情发货」。

计划拿不到（`[]`，库存预留缺失）同样标出来，不静默跳过。

### 3. 物流公司可统一，单号必须一单一个

一个包裹一个单号。双填同一个号会让两个顾客查同一个轨迹，出问题时无法定位。
所以表里每行一个输入框，没有「统一单号」这种省事但错得离谱的选项。

### 4. 逐单执行，逐单报结果，不整批回滚

已经提交给快递的单退不回来。批量中途失败时：

- **不回滚**已成功的单（那等于让商家重复发货）；
- 失败行保留在列表里、显示服务端原话（状态已变/物流公司对不上/预留被释放，处理方式各不相同）；
- 成功的行变成「已发货」徽标，按钮变「关闭」。

### 5. 勾选随筛选条件清空

换页签、换页、换关键字都清空勾选：否则会出现「对看不见的订单发货」——
商家以为只发了一页，实际发了三页前勾的单。

### 6. 不发新接口

复用已有的 `GET /admin/orders/:id/fulfillment-plan`、`POST /admin/orders/:id/fulfillments`、
`POST /admin/fulfillments/:id/shipments`。批量是**界面层的编排**，不是新的业务动作：
每一单走的是和单发完全相同的路径与校验，这样批量不会绕过任何一条约束。

## 后果

- 后台：`pages/orders.tsx` 加勾选列 / 全选 / 批量操作条；
  新增 `components/batch-ship-dialog.tsx`（拉计划 → 填单号 → 逐单提交 → 报结果）
- 无 API / 模块 / 迁移改动（这是本 ADR 最想保住的一点）
- 无新增测试：批量不引入新的服务端分支，每一单的规则由既有 API 测试守；
  界面层无测试基建（admin 至今没有组件测试），不为这一个弹窗单独引入

## 遗留

- **电子面单 / 批量导入 Excel**：淘宝的批量发货主体是面单打印与表格导入，
  需要快递公司 API 或文件解析，属独立工作
- **批量打印发货单**：现在一单一个打印页（ADR-044）。批量打印要合并成一份 PDF，
  需要服务端渲染或前端拼页，另做
- **批量导出**：导出选中订单为 CSV（对账用），与「导出」按钮一起做更合适
