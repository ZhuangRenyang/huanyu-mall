# ADR-080：装修第二块——首页轮播图

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-077（原地重建）、ADR-079（首页模块）

## 背景

装修前两块已落地：主题外观、首页模块顺序与开关。缺的是**商家换首页大图**——
这件事以前必须改代码。CRMEB 的装修里，轮播是首页最显眼的那一块。

## 决策

### 1. 轮播单独一张表，不塞 metadata

轮播是**多行、可增删、要排序**的数据，和主题单行配置不同：
`theme_banner`（id / image_file_id / link / sort_order / is_active / deleted_at）。

图片只存 `file_id`，URL 由 file 模块按存储 key 解析 —— 与商品图同一套上传与寻址，
不另建一套图片存储。

### 2. 链接走白名单，挡住 javascript:

`normalizeLink` 只放行：空、以 `/` 开头的站内路径、`https://` 外链。
`javascript:`、`//evil.com`、`http://` 一律拒绝。

装修入口如果能让任意字符串变成 `href`，它就是第二个 XSS 入口；在服务层拦，
不依赖前端校验。

### 3. 店面只拿能直接用的数据

`/store/bootstrap` 里下发 `banners: [{ id, image_url, link }]`，
只返回启用中、且 URL 解析成功的项。店面不拼 URL、不判断 file_id。

### 4. 轮播不进「首页模块」排序

轮播固定在搜索框下方 —— 它是首屏主视觉，排到分类或商品流下面没有意义。
模块编排管的是分类 / 券条 / 商品流三块。

## 后果

- theme：迁移 `0005_banner.sql`、`theme_banner` 模型、仓储/服务/契约、`normalizeLink`
- API：`/admin/settings/banners` 增删改查（带审计）；bootstrap 下发启用中的轮播
- 后台：装修页新增「首页轮播」（上传图 + 链接 + 显示开关 + 删除）
- 店面：首页搜索下方渲染轮播，无链接则不可点
- 测试：api +1（链接白名单：http/javascript/协议相对全部拒绝）
- 顺带修复：`0003_announcement.sql` 此前一直没注册进 theme 模块迁移列表

## 遗留

- 排序：现在按创建时间；拖拽排序等后台有更多内容时再做
- 点击统计：不做（埋点属于统计期）
- 微页面与页面链接：装修剩下的两块，尚未开始
