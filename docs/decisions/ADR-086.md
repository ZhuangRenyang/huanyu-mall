# ADR-086：阶梯满减（取满足门槛的最高一档）

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-012（促销计算）、ADR-064（券范围）、ADR-085（领取后 N 天）

## 背景

券只有「一个门槛 + 一个固定金额」。「满 199 减 20、满 299 减 40」这种阶梯
要么拆成两张券（顾客得自己挑），要么做不到。

## 决策

### 1. 阶梯存 `voucher.tiers`，与单档互斥

```json
[{"min_spent_minor":19900,"discount_minor":2000},
 {"min_spent_minor":29900,"discount_minor":4000}]
```

非空即启用阶梯：**单档的 min_spent 与 discount_value 不再参与计算**。
两者同时生效会让「满 199 减 20」与「满 299 减 40」叠加，等于算错钱。

### 2. 取「已满足门槛的最高一档」

不满任何一档返回 0，调用方据此跳过这张券 —— 不能返回「券可用但减 0 元」，
否则界面上会出现一张「已选用、金额没变」的券。

抵扣不超过适用小计：配置成「满 199 减 500」也不会把订单打成负数。

### 3. 只对固定金额生效

百分比券（bps）与阶梯混用没有明确语义，忽略 `tiers`，按原百分比算。
建券表单里阶梯只出现在固定金额下。

### 4. 后台用文本行录入，解析失败的行丢弃

「满 199 减 20」一行一档。解析不了的行**跳过而不是整单报错**：
商家多打一个逗号不该导致整张券存不进去；但解析后为空则不写 tiers（回退单档）。

## 后果

- promotion：迁移 `0006_voucher_tiers.sql`、模型/DTO、仓储读写、`computeVoucherDiscount` 取档
- API：创建/更新券接受 `tiers`（最多 5 档，金额用 minor 整数）
- SDK：`tiers` 类型
- 后台：券编辑新增「阶梯满减」文本域；视图层 camelCase、请求体 snake_case 各自显式映射
- 测试：promotion +1（199/250 取第一档、300 取第二档、150 不命中）
- 迁移 59；promotion 59 通过；api 329 通过

## 遗留

- 阶梯与券范围的叠加顺序：现在先按范围算适用小计，再拿它选档 —— 与单档一致
- 阶梯的「每档不同折扣类型」（如满 299 打 9 折）不支持，只做固定金额
