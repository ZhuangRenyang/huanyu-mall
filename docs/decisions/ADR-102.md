# ADR-102：会员等级——按累计消费实时匹配，折扣与商品促销取大

- 日期：2026-11-14
- 状态：已采纳
- 关联：ADR-078（E 期会员）、ADR-012（促销计算）、ADR-099（秒杀）、ADR-101（分销）

## 背景

E 期会员的第一块是等级：消费越多折扣越大。CRMEB 有「会员等级 + 会员折扣」，
淘宝有「会员价」，Shopify 用客户标签 + 折扣码近似。

难点不在建表，而在**折扣怎么进结账**：结账链路已经很长
（秒杀 → 目录促销 → 订单满减 → 券 → 礼品卡 → 积分），会员折扣塞在哪里、
能不能叠加，必须一句话说清，否则客服解释不了「为什么这单没打折」。

## 决策

### 1. 等级不落库到客户身上，按累计消费**实时匹配**

`member_level` 只存阶梯：名称、门槛（累计消费 minor）、折扣力度（万分比）。
顾客属于哪一档，读的时候按累计消费算（取满足门槛的最高一档）。

为什么不做 `customer.level_id`：

- 落库就要维护「什么时候重算」，需要定时任务或每次下单后回写，两者都会漂移；
- 规则改了（门槛从 10 万调到 5 万），落库方案要刷一遍历史数据才生效。

实时匹配的代价是每次多查一次等级表（几十行），可忽略。

### 2. 折扣按行计算，与商品促销**取较大者**，不叠加

同一件商品不能打两次折。实现方式复用现有机制：行级循环里多一个候选
（会员折扣），与目录促销的最大折扣比较，取大的那条落进折扣明细。

- 会员 5% vs 促销 20% → 促销生效，会员折扣为 0；
- 会员 30% vs 促销 20% → 会员生效，促销为 0。

折扣明细里来源不同：促销是 `type=catalogue` + promotion_id；
会员是 `type=member` + 空 promotion_id（它不是某条促销活动）。

### 3. 秒杀价之后才打会员折扣

顺序：**秒杀价替换原价 → 会员折扣按折后金额算** → 订单满减 → 券 → 礼品卡 → 积分。

否则等于「秒杀价再打一次折」，商家不会接受。满减门槛也按会员折后金额算
（与秒杀同一口径）。

### 4. 折扣力度上限 30%

与分销佣金上限同一考虑：再高不是会员权益，是清仓。DB CHECK + 服务层双挡。

### 5. 门槛唯一

两档门槛相同，顾客算哪一档没有答案。`uq_member_level_threshold` 唯一索引 + 服务层先查。

### 6. 等级属于客户域，购物车只问「打几折」

`cart` 不依赖 `promotion` 的等级概念，也不反向依赖客户模块：

- 购物车新增可选端口 `membership.getDiscountBps(customerId)`；
- 端口实现在 cart 模块装配时用结构性类型取 `order.summarizeByCustomerIds`
  （累计消费）+ `customer.getMemberDiscountBps`（等级判定）；
- `computeDiscounts` 只接收一个 `memberDiscountBps` 数字，金额仍在促销模块算（铁律 13）。

## 后果

- customer：迁移 `0005_member_level.sql`、模型/DTO、仓储 4 个方法、服务 5 个方法
  （列表/新建/更新/匹配/折扣力度）
- cart：`CartServiceDeps.membership`（可选端口）、`MemberDiscountBps` 透传、
  折扣明细 `type=member`、计税基数与 `discount_minor` 纳入会员折扣
- promotion：`ComputeDiscountsInput.memberDiscountBps`、
  `memberDiscountMinor/memberAdjustments`、行级取大逻辑、折后小计扣减
- order / workflows：折扣类型加 `member`
- API：`GET/POST /admin/member-levels`、`PATCH /admin/member-levels/:id`（customers 权限）；
  `GET /store/member-level`（当前等级 + 累计消费 + 下一档差额）
- SDK：`listMemberLevels / createMemberLevel / updateMemberLevel`、`getMyMemberLevel`
- 后台：客户组「会员等级」页（阶梯表 + 新增/编辑对话框）
- 测试：promotion +4（按行计算、与促销取大、秒杀后再折、门槛按折后算）、
  api +4（创建与门槛唯一、排序与改折扣、我的等级匹配、未登录 401）；
  promotion 89、api 369、cart 30、customer 13、order 34、storefront 46；迁移 71

## 遗留

- **等级权益不止折扣**：免邮、专属价、生日礼都没有；先把「折扣」这一条做对
- **客户列表显示等级**：后台客户列表还没拼等级列（要 join 两个模块的统计）
- **手动调级**：现在完全自动，无法给某个客户「保级」或「直升」
- **等级变更通知**：升级/降级不发邮件
- **会员分组 / 标签**：E 期的下一块，涉及打标、按标签筛选、按标签定价，单独立项
