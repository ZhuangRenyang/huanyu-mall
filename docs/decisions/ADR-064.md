# ADR-064：优惠券适用范围（指定商品 / 指定分类）

- 日期：2026-11-13
- 状态：已采纳
- 关联：ADR-012（促销/折扣）、ADR-029（店铺券）、ADR-014（营销克制）

## 背景

`voucher.type` 从一开始就有三个值：`entire_order` / `shipping` / `specific_product`，
后台也一直能选「指定商品」——**但 `computeDiscounts` 从来没读过 `type`**。

结果是：商家勾了「指定商品」，券却按整单减。这不是「功能没做完」，
是**每核销一张就多亏一单**的钱漏洞。`shipping`（运费券）同样被静默当成整单券。

## 决策

### 1. 适用范围落成独立表 `voucher_scope`

`(voucher_id, scope_type, scope_id)`，`scope_type ∈ {product, category}`。

- 独立表才能加唯一索引、按券批量查、编辑时整表替换（先删后插）而不污染主表；
- `scope_id` 不建外键：商品/分类分属别的模块，外键会把促销模块钉死在它们的表结构上。

### 2. 满减门槛与折扣都按「适用小计」算

指定商品券的基数 = 命中范围的那些行的 `unit_price × quantity` 之和：

- `min_spent` 只数命中的行（满 200 减 30 限服饰 → 服饰要满 200）；
- 固定减免封顶到适用小计（服饰只买 50，减 80 的券不能减 80）；
- 百分比折扣天然随基数缩放。

### 3. 范围为空 = 这张券用不了，绝不降级成整单

`type='specific_product'` 但 `scopes` 为空 → 折扣为 0。这是安全方向：
商家勾了「指定商品」却忘了选，宁可这张券废掉，也不能让一张「本意是限定的券」
悄悄变成整单券。

创建与更新两处都拦：创建时 `specific_product` 必须带至少一条范围（zod `refine`）；
更新改成 `specific_product` 且原本没有范围时，服务端也拒绝。

### 4. 运费券顺带补上真语义

`type='shipping'` 现在真正只抵运费：

- 没有运费（`shippingMinor <= 0`）→ 用不了；
- 抵扣金额封顶到运费本身（想全免也最多免到运费）。

这是同一处「type 被忽略」的另一个受害者，一起修掉。

### 5. 范围按 voucherId 一次查全，禁 N+1

`computeDiscounts` 先把「存在性/状态/有效期/用量」过关的候选券攒起来，
再 `listScopesByVoucherIds(candidates)` 一次取回所有范围。一车最多 50 个码只多一条查询。

### 6. 购物车把 `product_id` 传进折扣计算

`ComputeDiscountsInput.items` 新增可选 `productId`。指定商品券按它判定命中；
老调用方不传就只能按分类命中（字段可选，不破坏既有调用）。

### 7. 后台范围选择器

新建/编辑券时，`type=指定商品` 下方出现「适用范围」：分类勾选 chips + 商品搜索勾选，
底部显示「已选 N 个分类、M 个商品」。保存时一并提交，列表/详情都回带 `scopes`。

## 后果

- promotion：迁移 `0004_voucher_scope.sql`、`voucherScope` 表、
  `listScopesByVoucherIds` / `listScopesByVoucherId` / `replaceScopes`（仓储）、
  `listVoucherScopes` / `listVoucherScopesByVoucherIds`（服务）、
  `eligibleVoucherBase` 计算基数
- cart：`computeDiscounts` 调用带 `productId`
- API：`createVoucherBody`/`updateVoucherBody` 收 `scopes`；创建/更新校验范围非空；
  列表/详情回带 `scopes`
- SDK：`AdminVoucher.scopes?`、`CreateVoucherRequest/UpdateVoucherRequest.scopes?`
- 后台：券表单范围选择器、列表摘要
- 店面：券条标注「限指定商品 / 仅抵运费」（诚实提示，避免顾客领了券结算才发现用不了）
- 测试：promotion +6（命中商品/命中分类/门槛按适用小计/无适用商品/空范围/运费券封顶）、
  api +5（无范围 400、带范围 201 回读、整单券、更新改指定商品 400、列表带范围）

## 遗留

- **券范围明细下发给店面**：目前顾客只知道「限指定商品」，不知道具体哪些。
  真要在商品页标「可用券」需要把范围带进 `listPublicVouchers`，会加大公开接口体积
- **排除范围（指定商品 + 排除某些）**：淘宝支持「部分商品可用 + 排除」，
  现在只有「包含」语义。要做得加 `exclude` 标志，另议
- **优惠券与目录促销叠加顺序**：两者仍是独立计算后相加，未做「券不计入满减促销」这类
  叠加策略，属 ADR-012 的已知边界
